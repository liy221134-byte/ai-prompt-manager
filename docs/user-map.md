# 用户地图（v2.12.0 现版本）

## 用途

照着这张图找入口：**我想做什么 → 点哪里**。产品没有隐藏菜单，所有能力都在下面这些地方。
配合[用户故事与线上自测清单](user-stories.md)逐条验；配合
[v2.13.0 设计](superpowers/specs/2026-09-24-v2.13.0-linking-and-guidance-design.md)看下一轮要补什么。

## 一、顶部：两个视图

```
┌──────────────────────────────────────────────────────────────────┐
│ [公共资产] [项目]        [项目选择器 ▾] [项目设置] [+ 新建项目]   │  ← 顶部
│                                            N 项资产   [退出登录] │
└──────────────────────────────────────────────────────────────────┘
     ↑ 一级切换，刷新后停在原来那个     ↑ 只有「项目」视图才有这些
```

- **公共资产**＝账号级方法库（原来的「默认项目」）。提示词、规则、文档、模板、规则包都在这。
- **项目**＝某个项目自己的资产。规则、文档、模板、图谱节点、验收记录、发布记录。
- 技术档案不在标签里，它在**项目设置**里（一个项目只有一份）。

## 二、速查：我想做 X，点哪里

| 我想…… | 去哪点 |
| --- | --- |
| 采集一条提示词 | 公共资产 → 提示词/全部 → **智能采集**（粘贴原文 → AI 识别 → 确认保存） |
| 手写一条提示词 | 公共资产 → 提示词/全部 → **新增提示词** |
| 把两条以上提示词合成一条 | 公共资产 → 提示词/全部 → **AI 合并**（选 2–5 条） |
| 让 AI 优化一条提示词 | 打开提示词详情 → **AI 优化** |
| 填变量、复制拿去用 | 打开提示词详情 → 填「填写变量」→ **一键复制** |
| 找一条旧提示词 | 顶部搜索框；或在**筛选**里按状态/标签/规则包筛 |
| 装一整套规则到项目 | 公共资产 → 更多 → **导入规则包** → 选项目安装 |
| 把自己攒的规则收成一个包 | 公共资产 → 更多 → **打包成规则包** |
| 看某个包长什么样 / 导出去 | 公共资产 → 规则包标签 → 点包 → 详情（导出 / 安装 / 成员清单） |
| 把规则整理成 AGENTS.md | 项目 → **规则编译**（选模板 → 复制/下载/存成文档资产） |
| 把一批 Markdown/文本/ZIP 导进库 | 公共资产 → 更多 → **导入文档包**（AI 出草稿，确认后才建） |
| 把自己的模板导进来 | 公共资产 → 更多 → **导入模板**（一次可选多个 .md） |
| 新项目要用公共库里的规则/文档 | 项目 → 更多 → **从公共资产库挑资产** |
| 从建表语句建图谱节点 | 项目 → 更多 → **导入工程** → 数据库 Schema |
| 扫本机代码目录建模块/接口节点 | 项目 → 更多 → **导入工程** → 分析代码目录（**只能本机模式**） |
| 看项目图谱、影响分析 | 项目 → **项目图谱** |
| 看还缺哪些工程文档、哪些需求没验收 | 项目 → **工程基线** |
| 新建验收记录 | 项目 → 工程基线 → **验收覆盖** → 新建验收记录 |
| 新建发布记录 / 看门禁 | 项目 → 工程基线 → **最近一次发布** → 新建发布记录 |
| 填技术档案 | 项目 → **项目设置** → 技术档案（可「从 package.json 推断」） |
| 导出/导入整库备份 | 公共资产或项目 → 更多 → **数据管理** |
| 找回删掉的东西 | 公共资产或项目 → 更多 → **垃圾箱**（默认留 30 天） |
| 改项目名、目标、阶段、质量等级、归档 | **项目设置** |
| 让 AI 直接查库、写库 | 本机开 `npm run mcp`，在支持 MCP 的客户端里用（**只能本机**） |

> 只想确认 MCP 通不通：跑 `npm run mcp:check`——它自己起服务、列项目、数图谱节点、
> 对一个节点做影响分析，不用接客户端。

## 三、每个视图里有什么

### 公共资产视图

- 类型标签：全部 / 提示词 / 规则 / 文档 / 模板 / 规则包
- 搜索框 + **筛选**（状态、标签、关系目标、规则包，带角标和一键清空）
- 主按钮：**智能采集**、**AI 合并**、**新增提示词**（都在提示词或全部标签下）+ **更多**
- 更多：导入文档包、导入规则包、导入模板、规则编译、打包成规则包、垃圾箱、数据管理

### 项目视图

- 类型标签：全部 / 规则 / 文档 / 模板 / 图谱节点 / 验收记录 / 发布记录
- 主按钮：**项目图谱**、**工程基线**、**规则编译**（全部或规则标签）+ 按标签出现的
  **新增规则 / 新增文档 / 新建模板** + **更多**
- 更多：导入工程、从公共资产库挑资产、新增规则、新增文档、新建模板、垃圾箱、数据管理
- 一个项目都没有时：给「新建项目」和「从公共资产库挑资产」

### 项目设置

项目名称、项目目标、当前阶段、**质量等级**（个人工具／低风险生产／涉及用户数据／高敏感——
它决定工程基线要哪些文档、发布前要做哪些检查）+ **技术档案** + 归档／重新激活。

## 四、四类项目资产的定位（在哪建、干什么用）

| 资产 | 干什么用 | 建在哪 |
| --- | --- | --- |
| 规则 | 约束 AI 怎么做事的条文，能编译成 `AGENTS.md` | 项目 → 更多/标签下新增，或从公共库挑、从规则包装 |
| 文档 | 项目过程产出（PRD、ADR、架构说明、验收清单…） | 同上，或导入文档包 |
| 模板 | 产物的结构模板，规则编译时套用 | 公共资产导入模板，或项目里新建 |
| 图谱节点 | 需求／模块／数据／接口／测试的编号节点 | 项目图谱里新增，或从 SQL／代码目录导入 |
| 验收记录 | 一条需求的验收条件→步骤→结果→证据→提交版本 | 工程基线的「验收覆盖」 |
| 发布记录 | 一次上线的门禁清单和结果 | 工程基线的「最近一次发布」 |
| 技术档案 | 这个项目用什么技术（一个项目一份） | 项目设置 |

**关系怎么用**：节点、规则、文档、技术档案之间用「引用／依赖／替代／实现」连起来，
项目图谱的「这个节点指向谁／谁指向它／间接影响」读的就是这批关系。
提示词上不显示关系——它是一次性取用的东西。

## 五、本地模式和线上有什么不一样

| | 本地模式（`npm run dev:local`） | 线上（Vercel）／云端模式（`npm run dev`） |
| --- | --- | --- |
| 数据放在哪 | `.data/prompts.sqlite`（本机文件） | Supabase 云端库 |
| 登录 | 不需要 | 邮箱密码登录 |
| 分析代码目录 | ✅ 可用 | ❌ 读不到你电脑的目录，那一栏禁用 |
| MCP（`npm run mcp`） | ✅ 可用 | ❌ 只在本机 |
| 其他功能 | 一样 | 一样 |

两边是**两套数据，不会自动同步**。搬数据：源那边「数据管理 → 导出备份文件」，
目标那边「数据管理 → 选择备份文件」导入（只新增、不覆盖）。云端拉到本机也可以让我代跑
`npm run sync:from-cloud`（先加 `--dry-run` 看会拉什么）。

## 六、本地测那两个独有功能

```powershell
# 1）本机模式的服务（现在就在跑）
npm run dev:local

# 2）另开一个终端：MCP 服务（只读就加 MCP_READ_ONLY=1）
npm run mcp
```

- 「分析代码目录」：项目 → 更多 → 导入工程 → 填一个本机目录路径（例如 `E:\codeX项目\src`），
  先出草稿、勾选后再写库。
- MCP：在支持 MCP 的客户端里连上这个服务，它按工具清单查库；写入的资产来源会标成「AI」，
  每次写入都留一个版本。
