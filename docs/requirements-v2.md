# 需求收敛：文档／模板边界、Spec 层与交互流程（待确认）

## 这份文档回答什么

1. 公共资产里的「文档」和「模板」两个页签，是不是在维护同一批东西？
2. 结合豆包那次「PRD 与 Spec 的区别」（2026-09-24），交互流程要怎么改？
3. 最终确定的需求清单，按版本切分。

## 一、文档与模板：现在是「同类东西散在两处」

### 核对结果（本机库，2026-09-24）

公共资产（默认项目）里的 15 份「文档」：

| 种类 | 数量 | 例子 | 性质 |
| --- | --- | --- | --- |
| 项目画像 | 3 | 个人工具／中型云端产品／大型平台 | 参考型 |
| 编译验证记录 | 6 | 个人工具编译验证 | **实例型** |
| 案例 | 3 | 多会话并行会重复实现同一任务 | 参考型 |
| **documentType =「模板」** | **2** | 技术档案模板、验收证据链 | **本该是模板** |

模板页签里的 4 个：AGENTS、README、START_PROMPT、DOCUMENT_SYSTEM（新项目骨架文件）。

### 结论

- **不完全是同一批内容，但边界确实乱了**：真正重复的是那 2 条 `documentType=模板` 的文档——
  它们和模板页签里的东西是同一层（填空骨架），却挂在文档页签下。
- 根因是历史演进：`v2.2.0` 导入种子包时，附属内容统一落成「文档 + documentType」；
  `v2.4.0` 才开放独立的「模板」类型，于是同一件事有了两个落点。
- 另外 9 份实例型内容（编译验证记录、案例）按豆包那次确立的原则，也不该占公共中心的位置。

### 建议（不合并类型，合并心智）

不建议把「模板」并进「文档」：模板要参与规则编译（机器按类型筛），元数据也不同。
要改的是**内容边界和界面说法**：

1. 公共资产的文档页签改叫**「参考文档」**，只放方法级参考（画像、案例、方法说明）；
   界面上写明「项目自己的文档不要放这里」。
2. 那 2 条 `documentType=模板` 的资产**转成模板类型**（一次性数据修正）。
3. 加两个动作，让骨架和实例能来回走：
   - **文档 → 另存为模板**（把写好的实例抽成骨架，进公共模板层）
   - **模板 → 用这个模板新建文档**（把骨架变成项目里的一份实例）
4. 项目视图的文档页签按**链路阶段**分组显示（见下），一眼看出缺哪一环。

## 二、从豆包对话吸收的四条结论

1. **PRD 与 Spec 不是一回事**：PRD 讲为什么做／做什么／成功标准（你拍板）；
   Spec 讲这次具体怎么改：动哪些文件、数据结构怎么变、接口契约、边界情况（AI 起草、你确认）。
2. **你的链路里 Spec 是缺口**：现在是「PRD（做什么）→ 直接让 AI 写代码」，
   中间只有 `AGENTS.md` 里那句口头说明顶着。Plan 偏弱，验收很强。
3. **Spec 是你唯一能在代码产生前拦住 AI 的闸门**：你不读代码，尤其用 Supabase 时，
   「数据结构怎么变、对老数据什么影响」不写进 Spec 先确认，迁移跑完就晚了。
4. **模板进中心，实例进项目**：资产中心只维护空白骨架（例如 `TPL-SPEC-001`）；
   每个项目自己产生的 spec 实例放项目里。**别让实例涌进中心，否则中心变成网盘。**

据此需要在产品里补两层：

- **模板层补一件**：实现规格模板（Spec），分小功能／大版本两档。
- **项目里补一个阶段**：Spec 实例（文档类型新增「实现规格」），并且和 PRD、Plan、验收串成链。

## 三、优化后的交互流程

核心改动只有一句：**公共资产只放"骨架和方法"，项目里放"这次做的事"。**

```
公共资产（方法库）                          项目（过程资产）
├─ 提示词    复制去用的模板                  ├─ 规则    这个项目生效的规则（来自中心或自建）
├─ 规则      法则级约束                      ├─ 文档    按链路阶段分组 ↓
├─ 模板      填空骨架（含 Spec 骨架）        │   ① 需求：PRD／范围
├─ 参考文档  画像、案例、方法说明            │   ② 规格：Spec（本次怎么改）
└─ 规则包    成套搬运                        │   ③ 计划：分几步、每步怎么验
                                             │   ④ 交付：架构、数据流、接口说明
                                             ├─ 图谱节点   代码／数据骨架，挂文档用
                                             ├─ 验收记录   条件→步骤→结果→证据
                                             └─ 发布记录   上线门禁

两个动作把两边连起来：
  模板 ──用这个模板新建文档──▶ 项目里的实例
  项目文档 ──另存为模板──▶ 公共模板层（把经验固化成骨架）
```

界面上的三处具体调整：

1. **公共资产**：文档页签改名「参考文档」（写明只放方法级参考）；模板页签保留，
   里面能选「用这个模板新建文档」。
2. **项目视图**：文档页签按链路四段分组（需求／规格／计划／交付），
   每段后面写「已有 N 份」；某段为空时给「用模板新建」，点一下直接带上该段的模板。
3. **工程基线**：增加一组「链路完整性」检查——这个项目有没有 PRD、有没有 Spec、
   有没有验收、有没有发布记录，缺哪一环点一下就能建（带模板）。
