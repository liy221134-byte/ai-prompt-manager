## 一、路线评估：三个判断，两个要改，一个要补

### 先说清依据来源（有一处对不上，必须先纠正）

  UP 主是**像素范**（B 站，30.2 万粉），nodeId `faw3JP6ZPLacDT0w9VyAhT`，全文已读完

**注意一个关键事实**：这份报告里确实有「把主题拆成**五个学习等级**」的方法，
但它只给了**提示词**，**没有给出五层具体是什么**——原话是让 AI 回答「每一层该掌握什么、

   - **能力递进型**（最常见）：看过 → 听懂 → 写下来 → **表达出来** → 融会贯通

如果你手上真有「水球泡」那份，把链接给我，我重新对一遍。**在这之前，下面的判断按上面前提成立。**

### 判断 1（**要改**）：现在的 S1—S6 不是「学习阶梯」，是「内容分区」

这是本规划最重要的一条。

看 `rk-mid-integration.yaml` 的 6 个 stage：项目管理框架 / 五大过程组实操 / 信息技术基础 /
组织保障与监理 / 法规与职业道德 / 应试专项。它们按**教材章节**切（`scope_chapters` 逐一对得上
第 9 章、10—14 章、1—8 章…），`weight` 是**占分权重**。

**这不是能力阶梯。** 证据在 `entry_criteria` 里：S2 的进入条件是「S1 达标」，S4 是「S2 达标」——
这是**内容模块的前置依赖**，不是「同一能力从第 3 层升到第 4 层」。

后果很具体：**M1 做出来的「按阶梯出题」，本质等于现在的「按分类刷题」换了个分类名。**
现在的 `/practice` 已经能按分类筛，M1 再做一个按 stage 筛，用户感知不到差别，这一版的钱白花。

**改法：把一维改成二维。**

| 维度 | 是什么 | 现状 | 改后 |
| --- | --- | --- | --- |
| A · 内容模块 | 学哪块知识（教材 18 章归并成 6 块） | 现在的 S1—S6 | 保留，但**改名为 `module`**，不再叫 stage |
| B · 能力层级 | 对这块知识能到什么程度（L1—L5） | **完全没有** | 新增，诊断和出题都按它调节 |

能力五层，我按考试场景定（不是照搬通用模型，是改成能判分的）：

| 层 | 名字 | 判定标准（能判、不模糊） | 对应题型 |
| --- | --- | --- | --- |
| **L1** | 认得 | 给选项能挑对，但说不出为什么 | 单选 · easy |
| **L2** | 说得出 | 不看资料，用自己的话讲清它是什么、几个要素 | 判断 / 简答 |
| **L3** | 算得出 | 套公式、走流程，能一次做对 | 计算 / 流程默写 |
| **L4** | 判得准 | 给一个**没见过**的场景，判断它属于哪个过程组、该走哪条流程 | 场景单选 / 案例分析 |
| **L5** | 迁得动 | 错题能归因到哪个概念错；能拿自己的项目对着讲一遍 | 实操 / 案例改写 |

考试的真实门槛（我的判断，需你用真题校）：**L3 覆盖高频考点 + L4 及格线**。
L5 不是及格必需，是防「换了问法就不会」。

诊断要输出的就是 **6 个模块 × 5 层的矩阵**，而不是「你得了 62 分」。

> **这条不确认，M1 就别开工。** 它是整个 v4 的地基——比数据库字段重要得多。

### 判断 2（**要改**）：order 排的顺序，踩了报告明确批评的坑

报告原话：「学习劲头在刚开始的 20% 时间里拥有 80%，你需要用它来解决学习内容中**最重要的部分**，
而不是最入门的部分」，而且要点名批评了「从红宝书第一个词 abandon 学起」。

现在 yaml 的排法是 S1(100h) → S2(70h) → **S3(130h)** → S4(20h) → S5(40h) → S6(20h)。

问题：**缺口最大、耗时最长的 S3 信息技术基础（130 小时、零基础、expected_gap=5）被排在第 3 位。**
按 380 小时的总量算，学到 S3 时已经是第 200 小时之后了，那股劲早就没了。
这正是报告说的错配——**最有劲的时候在啃最轻的东西**。

另外 `weight` 我判断**很可能填反了**：
第 9 章只是「项目管理概论」，第 10—14 章才是五大过程组的逐章展开（十大知识领域就在这里面展开），
选择题 75 分的主战场在 10—14 章。现在给 S1（第9章）=0.30、S2（10-14章）=0.20，与教材结构不匹配。

**改法**（等真题校准后定稿，先给方向）：
1. 顺序改成**按「缺口 × 分值」双高优先**：S1 只做「建地图」用最短时间过掉（不占 100 小时），
   紧接着上 S3 前四章（跟工作直接相关、能立刻用上的：信息化发展 / 云大物移智区 / 信息技术服务 / 信息系统架构），
   再上 S2（计算题 + 案例题，最需要练、也最容易有成就感）。
2. S4（监理/组织保障，合计占分最低）**放最后扫**——这就是报告说的「信号筛选」。
3. `planned_hours` 全部等第一次诊断结果出来再定，现在这组数字是「基于已知画像预判」，没有一手依据。

### 判断 3（**要补**）：你说的是「全旅程保障」，现在这条线只管「学习 + 练习」

你这次的原话是「根据学习目标**全旅程**的保障学习」。现在 M0—M4 覆盖的是：数据地基 → 计划导入
→ 诊断 → 自适应 → 知识图谱。**全是「学」这一段。**

考试这件事的真实旅程比这长，而且有一段是**单点致命**的：

| 节点 | 时间 | 现在有没有覆盖 | 风险 |
| --- | --- | --- | --- |
| **报名** | **2027-03 下旬**，山东窗口约 10-20 天，**无补报** | **没有** | **错过＝等一年。这是整个计划唯一不可挽回的失败点** |
| 缴费 | 报名同期，68 元/科 | 没有 | 报名不缴费等于没报 |
| 准考证打印 | 考前约 1 周 | 没有 | — |
| 机考模拟 | 4 月起 | 部分（S6 应试专项） | — |
| 成绩查询 / 复盘 | 考后约 1 个月 | 没有 | 影响是否二战 |

**我的建议：不要为这个做通知系统**（那是过度设计）。M1 主题页上加一行「关键节点倒计时」就够，
数据源直接用主题包里已有的 `deadline` / `registration_expected` 字段。真正兜底的还是你手机日历——
报名那件事我会在 2027-03-01 单独提醒你一次，不依赖产品。

## 二、v4 迭代需求（修正版）

### 里程碑重排

原计划 M0→M4 保留，但插入 **M0.5（诊断校准）**，并把「能力层级」做进 M1。

| 版本 | 范围 | 你能感知到什么 | 相对原计划 |
| --- | --- | --- | --- |
| **M0** | 数据地基：schema + 补字段 + 4 表 + 导入器 | 无界面变化 | 不变 |
| **M0.5** | **首次离线诊断 + 校准**：40 题诊断卷 → 出「模块×层级」矩阵 → 回填 `expected_gap` / `planned_hours` / 重排顺序 | **一份 PDF/网页诊断结果 + 一份改过的主题包** | **新增** |
| **M1** | 计划导入 + **按（模块×层级）出题** + 关键节点倒计时 | 能选主题、看阶梯、按层刷题 | 加「层级」维度 |
| **M2** | 诊断闭环（举证 + AI 归因 + 人确认 + 复测） | 能做入学测、看矩阵、看进步 | 不改 |
| **M3** | 自适应出题（连续拷问）+ 一页素材表 | 系统追着你问；学完出一页纸 | 不改 |
| **M4** | 手绘知识图谱检查 | 拍照上传，AI 指遗漏 | 不改 |

**为什么 M0.5 要插在 M0 和 M1 之间**
原计划的顺序是「先跑（M1）再诊（M2）」，理由是诊断的 AI 归因要有作答数据。
**产品功能的顺序没错，但学习动作的顺序反了**——报告的六环里，「先测再学」是第一环。
解法是把两者拆开：产品侧的诊断功能留在 M2，**学习侧的第一次诊断现在就用一份卷子离线做掉**。
这样 M1 出题优先级、`planned_hours`、stage 顺序才有真实依据，而不是继续凭画像预判。
**成本很低：一份卷子 + 一次分析，不需要任何产品功能。**

### 各版明确不做（防止范围失控）

- M0：不动界面、不打标现有 135 题（移 M0.5 之后，见 M0 设计第一节）
- M1：不做通知/提醒推送、不做多主题并存（只中项一个）、不做移动端适配
- 全线：不做多用户、不做分享、不做社区题库、不做 AI 自动生成整卷（M3 之外）

## 五、第一次测试：入学诊断卷（M0.5 · D1）

### 设计

| 项 | 定 |
| --- | --- |
| 题量 | **40 题**（29 KP 抽样覆盖，高频 KP 加题） |
| 时长 | **90 分钟**，一次做完，中途不查资料 |
| 题型 | 32 单选 + 4 判断 + 4 简答/计算 |
| 层级分布 | L1 12 题 / L2 10 题 / L3 8 题 / L4 8 题 / L5 2 题 |
| 判分 | 对的记层级达成；**错的记「卡在哪一层」**——L1 错＝没学过，L2 错＝只会认，L3 错＝不会用，L4 错＝换问法就废 |
| 输出 | 6 模块 × 5 层矩阵 + 一句话结论（比如「S3 停在 L1，S2 停在 L3」） |
| 严肃性 | **按真考对待**：不查资料、不猜、不会就空着。空着也是有信息的——空着＝L0 |

### 12 道样题（正式版 40 题的结构与难度以这 12 道为准）

---

**Q1 · S1 / KP-0101 · L1 · 认得**
项目区别于运营的两个本质特征是？

A. 有预算、有团队
B. 临时性、独特性
C. 有目标、有风险
D. 需审批、需验收

答案 B。选错＝连最基础的概念都没建立，S1 要从零讲。

**Q2 · S1 / KP-0102 · L2 · 说得出**
不看资料，用一句话写出「五大过程组」分别是哪五个，并说明它们之间是时间顺序还是逻辑关系。

答案：启动、规划、执行、监控、收尾；**逻辑分组**，在实际项目中高度交叠、循环往复，不是瀑布式时序。
（写出五个名字算 1 分，答对「不是时间顺序」再得 1 分。只背得出名字＝停在 L2 上半段。）

**Q3 · S1 / KP-0104 · L4 · 判得准**
某公司设立一个 PMO，只提供模板、培训和顾问咨询，**不要求项目必须遵守**，项目经理可自主决定是否采纳。
这属于哪种 PMO？

A. 支持型　B. 控制型　C. 指令型　D. 混合型

答案 A。（控制型＝要求遵守但程度中等；指令型＝直接管理项目。三者区别只看「强制程度」这一个轴。）

**Q4 · S2 / KP-0206 · L3 · 算得出**
某项目 BAC=1000 万元，当前 EV=400 万元，PV=500 万元，AC=450 万元。求 SV、CV、SPI、CPI，并说明进度与成本状态。

答案：SV=400−500=−100（落后）；CV=400−450=−50（超支）；SPI=0.8；CPI≈0.889。
**给分点**：四个值各 1 分，状态判断 1 分。只写数字不写公式＝扣一半，这就是案例题的失分模式。

**Q5 · S2 / KP-0207 · L4 · 判得准**
项目执行中，客户口头要求增加一个报表功能，开发组长认为工作量不大，当天就改完上线了。
从变更管理角度，这个处理**最严重的问题**是？

A. 没有更新项目进度计划
B. 跳过了变更影响分析与 CCB 审批，且未更新基准
C. 客户没有提交书面申请
D. 没有通知测试人员回归

**Q7 · S3 / KP-0302 · L1 · 认得**

A. IaaS　B. PaaS　C. SaaS　D. 私有云

**Q8 · S3 / KP-0305 · L2 · 说得出**
软件测试按阶段分为哪几类？按顺序写出来，并说明「系统测试」和「验收测试」的核心区别。

答案：单元测试 → 集成测试 → 系统测试 → 验收测试。
区别：系统测试由**开发方**验证系统是否满足需求规格；验收测试由**用户方**验证是否满足业务需要。
（区别说反＝L2 未达标，这两者混淆是选择题高频陷阱。）

**Q9 · S3 / KP-0308 · L4 · 判得准**
某市级政务数据共享平台，涉及 200 万自然人信息，一旦被破坏会对社会秩序和公共利益造成严重损害。
按等保要求，它**最低**应达到几级？

A. 一级　B. 二级　C. 三级　D. 四级

答案 C。定级看的是「受侵害的客体 + 侵害程度」两个维度：损害社会秩序和公共利益（严重）⇒ 三级。
答「四级」＝把「严重损害公共利益」和「特别严重损害社会秩序」混了；答「二级」＝只按数据量猜。

**Q10 · S4 / KP-0402 · L1 · 认得**
信息系统监理的「四控两管一协调」中，「四控」是？

A. 质量、进度、投资、安全
B. 范围、进度、成本、质量
C. 质量、进度、合同、信息
D. 投资、质量、风险、变更

答案 A。B 是**项目管理的四要素**，不是监理的——这是本模块最高频的混淆点。

**Q11 · S5 / KP-0501 · L2 · 说得出**
按《招标投标法》，写出「招标公告 / 投标文件 / 中标通知书」三者各自的法律性质，并说明哪个标志着合同成立。

答案：招标公告＝**要约邀请**；投标文件＝**要约**；中标通知书＝**承诺**，合同成立。

**Q12 · S6 / KP-0604 · L4 · 判得准**
某项目「进度严重滞后，团队连续加班三个月，但交付量没有增加」。请写出 3 条可能原因，
每条都必须落到具体的项目管理过程上（不能写「管理不到位」这种话）。

判分标准（这也是案例题的评分逻辑）：
- 「加班三个月产出不增」⇒ 若答「进度计划未做资源平衡 / 未识别关键路径 / 非关键任务占用了关键资源」= L4
