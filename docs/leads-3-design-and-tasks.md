## 二、做什么 / 不做什么

### 做（M0）

1. **核对并定稿 S7 剩余技能的处置**（见第三节）。台账写"15 个"，但按行列举是 16 个（2+3+2+1+1+7），**M0 第一步先逐条核对，不强行凑数**。
2. **处置落地**：
   - 进**模板层**的 3 个（`job-stories` / `user-stories` / `wwas`）：**v2.25.0 资产口径收口时已在 `templates/methods/` 落了 `user-story.md` / `job-story.md` / `wwa.md`**（见 `docs/pending-items.md` 与 `tests/asset-single-source.test.mjs`）——M0 只需核对这三份模板与台账处置是否一致、补资产 id 引用，**不新建**。
   - 进**参考文档层**的 2 个（`prioritization-frameworks` / `ui-ux-pro-max`）：新建 2 条参考文档资产（会腐化的清单类），**需你逐次点头**。
   - 单独立一片的 7 个团队管理方法（OKR／路线图／排期／复盘／干系人／会议纪要／发布说明）：新建一个独立资产片，或降级为"先只记账、待立项"。**若实建需你点头**。
3. **采集台账补四个字段**：每条来源补「来源链接、核实日期、处置结论（已采／不采／暂缓）、落到哪条资产」。现有台账（第六节）已有「来源 / 类型 / 状态 / 提炼出的资产 ID / 采集日期 / 备注」，需补齐**来源链接**与**处置结论**两列，并把"采集日期"统一为"核实日期"。

### 不做什么

- 不采腾讯生态（M2，等 token）。
- 不做爬虫式批量抓取、不做未经确认的自动入库。
- 不把外部技能直接编译进 `AGENTS.md`，一律先 `candidate`。
- 不新建"进模板层"那 3 个（v2.25.0 已存在，避免重复资产）。

## 五、验收标准（M0）

1. S7 剩余技能每个都有明确处置结论，无"待定"（含 15 vs 16 的核对结论）。
2. 台账每条来源都能看到四字段：来源链接 + 核实日期 + 处置结论 + 落到哪条资产。
3. 进参考文档层的 2 条、团队管理片（若实建）都写了 `source_references`、默认 `candidate` / `hypothesis`。
4. 不重复建已存在的 3 个模板层资产（核对通过即算完成）。
5. 改动都经你逐次点头后落地，无未经确认的资产库写入。
