# 第 2 周手动验收测试单

## 测试目标

验证提示词管理、变量替换、预览、复制、本地保存、搜索、编辑和删除功能是否符合第 2 周验收标准。

## 测试准备

1. 确认项目已经启动。
2. 使用浏览器打开 `http://localhost:3000`。
3. 准备一个可以粘贴文本的地方，例如记事本，用来检查复制结果。
4. 测试过程中不要清除浏览器网站数据，否则本地提示词会被删除。

## 可直接粘贴的测试提示词

### T01 无变量

```markdown
# 角色
你是一名资深产品经理。

# 任务
请输出一份产品需求评审检查清单，并按照风险从高到低排序。
```

预期：没有变量输入框，正文直接可以复制。

### T02 单个中文变量

```markdown
请为 {{项目名称}} 编写一份产品需求评审检查清单。
```

预期：只显示“项目名称”一个输入框。

### T03 重复变量

```markdown
请评估 {{项目名称}}。

在结论中再次提到 {{项目名称}}，并给出最重要的三个风险。
```

预期：只显示一个“项目名称”输入框，正文中两处同步替换。

### T04 带空格的中文变量

```markdown
请为 {{ 项目名称 }} 生成项目目标说明。
```

预期：变量识别为“项目名称”，不会新建一个带空格的变量。

### T05 多个变量

```markdown
# 背景
{{业务背景}}

# 目标
{{项目目标}}

# 输出要求
请按照 {{输出格式}} 输出一份完整方案，并指出三个待确认问题。
```

预期：显示三个输入框，未填完之前复制按钮不可用。

### T06 中英文变量和复杂格式

```markdown
# 角色
你是一名 {{Role}}。

# 任务
请为 {{项目名称}} 设计一份检查清单。

# 输出
使用 Markdown 表格输出：
| 风险 | 影响 | 建议 |
| --- | --- | --- |
| 待填写 | 待填写 | 待填写 |
```

预期：正确识别“Role”和“项目名称”，Markdown 表格可以正常显示。
