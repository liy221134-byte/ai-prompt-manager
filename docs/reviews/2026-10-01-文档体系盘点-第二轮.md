## 3. 修正后的缺口定位（这是本轮的核心产出）

**CodeX 已经有的（链路已通 3/4）：**

| 链路阶段 | CodeX 现状 | 形态 |
| --- | --- | --- |
| ① 需求（PRD） | 有**提示词**、有**文档类型**、有**链路检查项** | ⚠️ **缺模板骨架** |
| ② 规格（Spec） | `templates/engineering/implementation-spec.md`（`TPL-SPEC-001`） | ✅ 模板骨架已有 |
| ③ 计划（任务顺序） | `implementation-spec.md` 大版本档含"任务顺序"；设计门文档含任务清单 | ✅ 已有 |
| ④ 交付（架构/数据流/接口） | `engineering/` 10 份模板 | ✅ 已有 |

**真正缺的两项（精确到文件）：**

1. **`templates/**/prd.md`**——PRD 的**填空模板骨架**。现状是只有"提示词"能生成 PRD，
   但没有一份"空白骨架"能让 `implementation-spec.md` 第 29 行引用的「哪份 PRD」落到实物。
   → 这正是"那次整理没有对应模板"的答案：**当时 Spec 落成了模板，PRD 漏在提示词这一层。**
2. **`templates/**/contract.md`**——zod **数字契约模板**。现状 zod 只有规则
   （`RULE-SCHEMA-CHECK-001`：**必须做**），缺一份"怎么写"的骨架（**怎么做**）。
   → 规则与模板互补，不冲突。

**不需要新增的：** SDD 本体（`implementation-spec.md` 已覆盖 SDD 6 要素中的大部分：
预期结果≈需求追溯、范围边界≈不做什么、约束条件≈边界与错误、已定决策≈方案、
任务拆分≈任务顺序、验证标准≈验收映射）。

## 4. 主流调研两轮对比（本轮更细）

| 体系 | 上一轮结论 | 本轮补充/修正 |
| --- | --- | --- |
| PRD | 8 段（Summary/Contacts/Background/Objective/Segments/Value/Solution/Release），Amazon 逆向工作法，适配度高 | **主流共识更强调短与取舍**：2–4 页、5 核心段（Problem/Solution/Scope/Technical Approach/Success Metrics）、**非目标（Non-goals）比目标更重要**；且**PRD 不含技术设计**（那属 Spec/工程文档）。→ **与 CodeX 已有的"轻量 PRD 两页以内"提示词完全一致** |
| ADR | Nygard 轻量五段，已用 7 份 | 补充：主流扩展 = `Alternatives Considered` + `Deciders`；增强版 `MADR`；与 arc42 §9 对齐 |
| Diataxis | 四象限，偏文档站，不适配 | 补充：核心是 Compass（action/cognition × acquisition/application），边界混淆是文档问题主因 |
| arc42 + C4 | 12 章 + 分层图，偏重 | 补充：12 章**全可选**，唯 §1.2 质量目标必填；分 LEAN/ESSENTIAL/THOROUGH 三档；§9 就是 ADR |
| SDD vs RFC | AI 执行包形态，适配度高 | **定位升级**：SDD 已是 2025–2026 主流方法论，工具生态齐全（Spec Kit/Kiro/Claude Code/Cursor/OpenSpec/BMAD/Tessl）；**6 要素 + 3–4 阶段（Specify→Plan→Tasks→Implement）+ EARS 记法**；反模式 = "spec theater"（生成 spec 却不走人工门）；判据："一段话交给新人都说不清，就该写 spec" |

## 5. 修正后的建议 + 拍板项

**建议组合（不变）**：`PRD + Spec + ADR + 契约模板`；**不引入** arc42 / Diataxis。

**建议新增（修正后只剩两项模板）：**

1. 补 `templates/**/prd.md`——**轻量 PRD 模板骨架**（对齐 CodeX 已有提示词与主流共识）：
   要解决的问题与给谁用 / 做什么 / **明确不做什么（非目标）** / 成功标准 / 上线前必须满足的条件，**两页以内**。
   不照抄 8 段长版，免得和现有轻量提示词打架。
2. 补 `templates/**/contract.md`——**zod 数字契约模板**：字段/类型/必填/取值范围 +
   `schema.parse()` 入口校验 + 失败返回结构化错误 + 不过不写库，与规则 `RULE-SCHEMA-CHECK-001` 配套。
