> 调研对象：WB 侧体系（`E:/WB项目集` + `E:/AI资产市场` + `~/.workbuddy`）与我们这侧（`E:/codeX项目`）。
> 方法：读一手文件、用脚本统计台账、联网核一手源。

## 0. 一句话结论

**两侧各缺一半，而且缺的正好是对方的强项。**

| | 规则会不会腐坏 | 规则跑没跑，有没有机械约束 |
| --- | --- | --- |
| 我们这侧 | **没有机制**（只有一张 2 行的命中表） | **有**（模板断言测试、门禁命令、导入链路实跑） |
| WB 侧 | **有机制**（868 行 append-only 台账、可数退役阈值、豁免分类） | **没有**（它自己的审计原话：「不能——只有散文规则，没有任何机械约束」） |

所以「要不要优化」的答案不是「学 WB」或「让 WB 学我们」，而是：
**把我们已有的机械约束接上一条规则台账，再把技能规模和规则注入量压下来。**
下面按维度给证据，最后给四档建议。

## 2. WB 侧体系现状

### 2.1 四层格局（它自己的 README 定义）

| 层 | 位置 | 管什么 |
| --- | --- | --- |
| 技能层 | `E:/AI资产市场` | 技能正本，给 Codex / Claude Code / Cursor / WorkBuddy 四家挂载 |

它的原则是「四层互不复制正文，只放指针」。这条执行得很实的：`~/.workbuddy/DEV-SYSTEM.md`
只剩 **1.2 KB 的指针文件**，正文在母仓（L2「引用优先于复制」）。

### 2.2 母仓的三套体系资产

| 资产 | 装什么 | 正本关系 |
| --- | --- | --- |
| `开发体系/` | `DEV-SYSTEM.md`（跨项目方法）＋ 2 份提示词包 | 从 `~/.workbuddy` **迁入**，是唯一正本 |
| `文档体系/` | `DOCUMENT_SYSTEM.md` ＋ 12 份工程模板 | 2026-10-01 从我们这侧 `templates/` **复制**，复制即脱钩 |
| `项目新建体系/` | `START_PROMPT.md` ＋ 起步模板（`AGENTS.md` / `README.md`） | 同上 |

### 2.3 `DEV-SYSTEM.md` 的骨架（比我们多三样东西）

它的结构：五条铁律 L1–L5 → 四道门（需求 / 设计 / **沉淀**）→ 沉淀三层 → 可信度三档 →
冲突裁决表 → 提交与版本纪律。

**它从我们这里继承的部分**：三道门、防过度设计梯子（7 阶，且注明「两边不一致时以源为准」）、
交付门六要素、「证据只记一处」、中文注释与文案、多会话隔离。

**它比我们多的三样**：

1. **沉淀门是强制的**：一次会话工具调用超量／修了棘手错误／摸索出可复用流程，**同一回合内**就沉淀成技能或记忆，不等提醒（落盘仍要人点头）。
2. **可信度三档**：`hypothesis` / `provisional` / `verified`，升级必须指向真实文件或验收记录。它自认**目前没有一条够得上 `verified`**。
3. **规则防腐三件套**（这是它最硬的部分）：
   - 命中台账 `rule-hits.md`，append-only，43 条规则逐条累计；
   - 退役阈值：连续 5 次「不适用」→ 退役候选；20 个会话未命中 → 退役候选；同一条 3 次「违背」→ **强制复盘，等人介入**；
   - **低频高危豁免 A/B 两类**：A 类（删数据、推远端、写生产库）只免「未命中」不免「违背」；B 类「命中即退场」——它举的例子很关键：**引入开源方案这类规则，命中一次就不再触发，「未命中」恰恰是生效证据，用未命中判它退役等于惩罚最有效的规则**。
   - 附带两张表：**工具与依赖期限表**（新增 MCP／技能／依赖须挂 2 周观察期，"验收口径要写成能数出来的事"）、**技能使用台账**。

### 2.4 台账实测（我跑脚本统计，不是读它的成稿）

| 指标 | 值 |
| --- | --- |
| 体量 | 54,885 字节 / 868 行 |
| 覆盖会话 | 11 个（2026-09-29 ～ 10-01） |
| 判定分布 | 守住 **256**、不适用 **71**、违背 **20**（其中含它**自曝自己造出来的问题**） |

## 6. 外部现成方案（都核过一手源）

| 方案 | 是什么 | 对我们哪个缺口 | 一手事实 | 我的判断 |
| --- | --- | --- | --- | --- |
| **AGENTS.md 标准** | 事实标准：Codex、Cursor、Copilot、Gemini CLI、Aider、Amp、Windsurf、Jules 等都读它；支持嵌套，**目录树里最近的那份优先**（OpenAI 主仓有 88 份） | 多工具共用一份规则 | agents.md 原文：「Agents automatically read the nearest file in the directory tree, so the closest one takes precedence」 | **已经用对了**。可以顺手用"嵌套"解决 O2——把方法层放子目录 AGENTS.md，根只留硬边界 |
| **Agent Skills 规范** | `SKILL.md` + YAML frontmatter；**规范只允许 6 个字段**：`allowed-tools` / `compatibility` / `description` / `license` / `metadata` / `name` | O3 技能规模与格式统一 | Claude Code 文档：超出规范的字段会让打包/上传**硬报错**（示例报错原文列出了这 6 个 allowed properties） | **必查**：我们的技能若要多平台分发，多余字段会直接失败。值得跑一次 frontmatter 体检 |
| **技能列表预算** | 列表占上下文 **1%**；溢出时按「最少调用」顺序丢 description | O3 | 同上，官方原文，并给了 `skillListingBudgetFraction` 调高与 `name-only` 降级的开关 | **必须处理**。131 个技能 × 每轮都在付，这是纯成本 |
| **ruler** | 把规则集中写在一处，**生成**各家的规则文件（`AGENTS.md` / `CLAUDE.md` / `.clinerules` / `CRUSH.md` …）＋ MCP 配置，并在 `.gitignore` 里维护托管块 | 多工具同步（我们目前手工四套） | 官方支持表列了 18 个 agent；`ruler.toml` 配在 `.ruler/` | **先不急**。我们已有 `verify-mounts.sh` 做校验；引入它是新增外部依赖，走同意门。收益要等"挂载目标继续变多"才明显 |
