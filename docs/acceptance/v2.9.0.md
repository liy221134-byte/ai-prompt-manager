# v2.9.0 验收清单（验收证据链）

## 怎么用

- 版本：`v2.9.0`，主题是「证明这项需求真的做完了，而不是只写了一张验收清单」。
- 状态：**功能与界面补验已完成，等你签字**。
- 设计见 [验收证据链设计](../superpowers/specs/2026-09-23-v2.9.0-acceptance-evidence-design.md)。
- 能对上就在方框里打勾；每条都写依据，证据只记一处。

## 验收记录

- 2026-09-23 由 Codex 开发并代跑，界面补验跑在**本机库副本**上
  （原始本地库没有被改动）。
- 实测数据：默认项目 + 66 个图谱节点（工程导入那一版留下的），
  另外用 MCP 建了两条需求节点（REQ-001、REQ-002）和一条 AI 提交的验收记录。
- 界面动作：工程基线看验收覆盖 → 给 REQ-002 新建验收记录 → 打开 AI 提交的那条记录
  把结论从「待确认」改成「通过」→ 回工程基线看覆盖变化 → 打开需求节点看验收统计。

- [x] 能新建验收记录：选需求节点、填验收条件／步骤／结果、证据、提交版本。
      依据：从工程基线的缺口点「新建验收记录」，编辑器里标题、对应需求节点、结论都预填好；
      填完正文保存成功，列表「验收记录 2」。
- [x] 不能挂空需求：不选需求节点保存会被拦下。
      依据：`tests/asset-editor.test.mjs`「验收记录草稿：需求节点必填，空的证据行会被丢掉」；
      `tests/mcp-write.test.mjs` 覆盖了「没给需求编号就报错」「编号写错就报错」两条。
- [x] 结论默认「待确认」，可以由人改成通过／未通过／例外。
      依据：新建时结论是「待确认」；实测把 AI 提交那条的结论改成「通过」并保存成功，
      详情里显示「结论：通过」。
- [x] 证据是「说明 + 链接或路径」的清单，空的证据行会被丢掉。
      依据：`tests/asset-metadata.test.mjs` 校验证据结构；草稿构建时空白行被过滤（有测试）。
- [x] 类型筛选能筛出验收记录。
      依据：工具栏计数出现「验收记录 2」，`tests/project-workspace.test.mjs` 断言了筛选选项。

## 二、需求节点的验收视图

- [x] 需求节点详情能看到有几条验收、几条通过。
      依据：REQ-001 详情显示「验收记录：1 条，通过 1 条」；
      还没验收的需求显示「验收记录：还没有，去「工程基线」里的验收覆盖建一条」。
- [x] 工程基线里有「验收覆盖」，列出还没通过验收的需求。
      依据：建记录前显示「需求 2 个，其中 2 个还没有通过验收」；
      REQ-001 改成通过之后变成「其中 1 个还没有通过验收」，且 REQ-002（未覆盖）排在前面。
- [x] 待确认不算覆盖。
      依据：REQ-002 有一条「待确认」的记录时，仍然列在「还没有通过验收」里；
      `tests/acceptance-evidence.test.mjs` 里也断言了「例外」不算通过。
- [x] 缺口能一键进新建记录，已经挂上的能打开需求。
      依据：未覆盖的需求有「新建验收记录」，有记录的需求多一个「打开需求」。

## 三、AI 能提交、不能拍板

- [x] MCP 能新建验收记录，但结论只能是「待确认」。
      依据：真机用 MCP 新建后返回「已新建验收记录「REQ-001 验收记录（AI 提交）」……
      结论是「待确认」，要让它在覆盖统计里算通过，得由人在界面上确认。」
      数据库里这条记录的结论就是 `pending`。
- [x] MCP 工具里没有能改结论的字段。
      依据：`tests/mcp-write.test.mjs`「MCP 改验收记录：改内容可以，结论改不了」——
      更新请求里根本不存在结论字段，改完结论仍是原值。
- [x] MCP 能按需求编号挂记录，编号写错时给中文提示。
      依据：同一用例覆盖「没给需求编号」「编号找不到」两条错误路径。

## 五、设计偏差

详细见[设计文档第六节](../superpowers/specs/2026-09-23-v2.9.0-acceptance-evidence-design.md)，
关键一条：**需求节点的关联存在元数据字段 `nodeId` 里，没有写成关系**——
语义固定、好校验，代价是需求节点的「谁指向它」清单里不会出现验收记录。

## 六、已知边界（不在本版）

1. 不接 GitHub／CI：提交号手填，不自动拉提交历史、不自动跑测试。
2. 不做证据附件上传：只支持说明 + 链接或文件路径。
3. 不做验收清单模板；8 份工程文档模板在 v2.8.0 已经有。
4. 不做发布门禁记录（这次发布有没有做检查）：排在 v2.10.0。
5. 加固与验收仍等整个 2.0 产品做完后统一做。

## 七、这一版省掉了什么

- 没有做「验收条件自动生成」：条件由人写，AI 可以起草但要走普通资产写入，不另开一条路。
- 没有做跨项目的验收统计看板：只在单个项目的工程基线里算。
- 没有给需求节点加反向索引字段：覆盖统计每次现算，量小够用。
