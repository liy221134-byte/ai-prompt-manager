## 一、这一版要解决的问题

M1 到 M3 解决的是「学什么、做哪几道、这块是什么意思」，但一直没有回答
**「我现在到底到哪一层」**。矩阵只显示覆盖（这层几道题、做了几道、对了几道），
PRD 里点名的诊断结论一直空着；`learning_diagnostics` 表建了三天，一行没写过。

M4 就是把这句话补上：抽一张卷，判出每块卡在哪一层，并给出「卡在哪、缺什么、今天做什么」。

## 三、关键决定：为什么每层只抽一道题，结论还是给区间

`2026-10-27-v4-m1-module-level-practice-design-and-tasks.md` 里记过一条教训：
**首次诊断用单题定生死，判出来的结论不可信**。这道题现在被自己撞上了——
每格一题正好就是「单题定生死」。

加题不是解决办法：每格两题就是 48 道，人会中途放弃，而放弃的卷子连初判都给不出来。
采取的办法是**把结论的精度降到和证据相称**：

| 不说 | 说 |
| --- | --- |
| 你具备 L3 能力 | 连续答对到第 3 层，第 4 层答错 |
| 你在 L2 | 最薄的一块是「信息技术基础」，第 1 层就没过 |
| 你这块不会 | 这块第 5 层没有可判分的题，**未测** |

配套两条：
- 结果页显示「答了 24/24 题 · 1 题以前做过 · 6 个格子没题」——样本量摊开在明面上
- 抽题优先没做过的；抽到做过的会标出来，并提示「结论可能偏高」

想更准的路也留着：去矩阵里把该层剩下的题做完，那层的证据就厚了。诊断不必包办这件事。

## 四、验出来的真错

### 4.1 `kind` 用了自己编的词，被 CHECK 约束拦下（已修）

写库时用了 `kind: "initial"`。库里 `learning_diagnostics_kind_check` 只允许
`baseline / module_gate / retest` 三个值，插入直接失败。

教训不是「记不住这三个词」，而是**建表时就定好的词汇表，我没查**：
查列、查索引、查 RLS 策略都做了，唯独没查 `pg_constraint`。

### 4.2 错误信息被吞成一句「保存失败」（已修）

第一次失败时界面只显示「保存失败：保存失败。」。原因是：

```ts
caught instanceof Error ? caught.message : "保存失败。"
```

Supabase 抛的 `PostgrestError` **不是 Error 实例**（只有 message / details / hint / code），
所以真实原因被兜底文案顶掉，只能回库里翻约束才知道错在哪。

修法：抽 `readErrorMessage()`，按 message → details → hint → 字符串 的顺序取。
这次是「保存」踩到，下次任何 Supabase 写入都会受益。

### 4.3 两处文案承诺了没做的事（已改）

- 结果页底部原写「保存后今日计划会按这次判出的层级排题」
- 空态原写「这也是今日计划按层级排题的依据」

**今日计划没有接入诊断结论**：它仍按练习覆盖与剩余天数算题。这两句是假承诺。
已改成只承诺做到的事（结论能存下来、下次打开还能看到），把「诊断驱动排题」
留给下一步，并记在下面的缺口里。

## 五、已知缺口

1. **诊断结论还没有接入今日计划与矩阵**。现在它是一份「看得见、能用来自查」的结论，
   但不改变系统排给你的题。这是 M4 之后最该做的一件事：用 `reached` 决定每天从哪一层起练，
   否则诊断与执行还是两条线。
   → **已由 M4.5 补上**（2026-10-28，见 `acceptance/v4-m4-5.md`）。矩阵侧仍未接，
   那属于 M5 自适应出题的范围。
2. **L5 测不到**。中项 34 道实操题全部集中在 L5，没有客观题，机器判不了对错。
   要补 L5 的客观题，或者以后给实操题做人工评分标准——两条都是内容工作，不是代码工作。
3. **每层一题是初判，不是定论**。已在界面上如实标明（样本量、重复题数量），
   但没有做「做完该层剩余题后自动升级结论」的机制。
4. **诊断卷固定 24 道**，不随题库增长调整。题库补了 L5 客观题之后，卷子会变成 30 道，
   这需要重新看「40 分钟」这个量还撑不撑得住。
5. 归因只送错题、不送整卷。若某个模块全对但明显低于其他模块（比如全对在 L3，别人全对到 L4），
   模型看不到这个差距——它只做「错题归因」，不做「横向比较」。
6. **编号口径有一处并存，没在本轮统一**：`docs/learning/v4-plan.md` 第七节（另一轮补记）
   把诊断闭环列为「编号待重排」，同时登记了一个待确认的 **M2.6 周节奏**；
   本验收单与 `roadmap.md` 按既有编号记为 **M4**。
   `v4-plan.md` 那段自己声明了「重排编号属于独立一轮工作，本轮不动」，所以这里只记录差异，
   不改它。真到重排时，`acceptance/` 下六份清单的文件名要一起动。
