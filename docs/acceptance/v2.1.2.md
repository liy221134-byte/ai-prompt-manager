## 二、设计偏差（已确认，延后处理）

1. 设计里写的是「导入依旧是先预览后确认」，实现做成了**选完文件直接按计划落库，然后用提示条报
   条数**（新增项目／资产／跳过）。
   2026-09-22 产品负责人确认：**预览的改造成本较高，这一版先这样，预览放到后续版本再规划**。
   风险边界保持不变：这条路径只新增不覆盖，本地已有同 id 的资产一律跳过。

- [x] 关系目标归档后，详情里显示「目标已归档」。

- [x] 把 v2 备份导入一个空库时能真正建出项目和资产。
      依据：实测两轮。第一轮把源库（1 个项目、1 条规则）的备份导入全新库，提示

## 三之一、验证过程中新发现的边界

1. ~~**提示词的关系只在编辑器里看得到**~~ **已在本版修掉**：提示词详情现在有关系展示和
   「目标已归档」标注，和规则、文档、技术档案一致。
2. **筛选值失效会筛空**：把某条资产设为筛选目标后再把它删除/归档，筛选下拉里那个目标没了，
   但筛选状态还留着，列表会变成空且看不出原因。属于边界情形，建议下一版在选项消失时自动复位。

## 三之二、本轮补验时发现并修掉的问题

1. **提示词能把自己设成关系目标**：关系目标下拉复用了资产编辑器的「排除自己」判断，
   编辑提示词时没有排除正在编辑的这条，会建出「A 指向 A」的关系。
   修法：候选列表抽成共享函数 `listRelationTargetOptions`，把两套编辑器的「正在编辑项」
   一起排除；新增 3 条测试覆盖排除自己、垃圾箱和其他项目。
2. **提示词改动后资产快照没刷新**：保存、删除、恢复、合并、优化、导入这些路径只更新提示词
   列表，资产列表没跟着更新。表现是新建提示词后它立刻不能当关系目标、资产详情里的
   「被谁引用」还显示旧标题。修法：这些路径统一走 `applyPromptLibrary`，写完提示词顺手
   刷新资产快照。
3. **垃圾箱里的目标提示词不显示「目标已归档」**：提示词详情只认「当前提示词 + 已打开的垃圾箱」
   两份数据，垃圾箱没打开时目标状态是空的。修法：关系目标改由资产快照垫底、提示词快照覆盖。
4. **备份弹层的说明和实际内容对不上**：文案还写着「只包含提示词，规则和文档不在备份范围内」，
   而 v2 备份已经把项目、规则、文档、技术档案和关系一起导出了。修法：改成 v2 的实际范围，
   并写明「导入只新增、不覆盖，同名项目合并到已有项目」。
