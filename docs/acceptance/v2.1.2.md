# v2.1.2 验收清单（技术档案、资产关系与备份升级）

## 怎么用

- 版本：`v2.1.2`，主题是「技术档案 + 资产关系 + 备份格式升级」。
- 状态：**未完成，还不能签字**。功能主体已实现并有测试，但备份的导出与导入界面尚未接线，
  另有四条界面路径需要补验，见第二、三节。

## 一、已经能勾的项

- [x] 项目里可以创建一份技术档案，保存后列表里能看到，改动产生新版本。
      依据：技术档案进可编辑类型；浏览器实测「新建技术档案 → 填技术栈 → 保存」通过。
- [x] 一个项目最多一份技术档案。
      依据：`findProjectTechProfile` 只认一份，测试覆盖「已有就编辑、没有就新建」。
- [x] 资产详情里可以新增、修改、删除四类关系（引用、依赖、替代、实现），关系是单向的。
      依据：规则/文档/技术档案编辑器与提示词编辑器都加了关系区；浏览器实测建关系并保存、
      详情显示「引用：<目标标题>」。
- [x] 关系目标被归档后，详情里显示「目标已归档」而不是报错。
      依据：详情抽屉按目标状态标注（代码层实现）。
- [x] 组合筛选与搜索升级：类型、状态、标签、关系目标可组合；搜索范围含技术栈名称与关系说明。
      依据：`filterProjectAssets` 新增标签与关系目标条件，搜索文本加入技术栈名称和关系说明，
      工具栏新增「标签」「关系目标」两个下拉；类型检查与构建通过。
- [x] 备份格式升级到 v2：包含项目、提示词、规则、文档、技术档案和关系；
      旧 v1 备份继续可导入；同名项目按名称合并到已有项目。
      依据：新增 `createAssetBackup` / `parseBackup` / `planProjectMerge`，5 项测试覆盖
      格式、垃圾箱不入备份、v1/v2 解析分流、结构错误提示和同名合并映射。
- [x] 来源包二进制不进备份，备份文件里写明需要另行保留原始文件。
      依据：备份只保存资产记录，`note` 中明确写出这一条。
- [x] `npm run check` 全部通过。
      依据：lint 0 问题、类型检查通过、测试全过、生产构建成功。

## 二、还没做完、暂时不能勾的项

- [ ] 备份的导出改用 v2，导入端能预览并落库。
      现状：v2 格式、解析、同名项目合并映射都已实现并有测试，但**导出与导入界面还没接线**，
      现在导出的仍然是 v1（只含提示词）。
      注意：在导入端接线之前不会切换导出格式——否则会出现「导出的文件自己读不回来」。

## 三、需要补验的界面路径

1. 提示词编辑器里建关系 → 保存 → 刷新后仍在。
2. 技术档案里勾选「偏离默认选型」不挂 ADR 时，保存被拦下并显示中文提示。
3. 关系目标归档后，详情里显示「目标已归档」。
4. 标签与关系目标两个筛选下拉的组合结果符合预期。

## 四、这一版新增的自动化证据

- `asset-tech-profile.test.mjs`：技术档案元数据校验与兜底、ADR 强关联、ADR 候选筛选、
  一个项目一份、关系写进草稿再存回元数据、提示词关系往返。
- `asset-backup-v2.test.mjs`：v2 备份结构、垃圾箱不入备份、v1/v2 解析分流、
  结构错误中文提示、同名项目合并映射。

## 五、已知边界

1. 关系类型保持宽松：四类关系对任意资产组合都开放，不做类型匹配限制。
2. 提示词、规则、文档、技术档案之间的联动与相互转换不在此版，
   已记入 `docs/v2-plan.md` 的「后续再评估」。
3. 加固项（迁移演练、端到端边界测试）统一留到资产管理 MVP 收尾时做，不在本版。
