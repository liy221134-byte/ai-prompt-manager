关联设计：`docs/leads-3-m2-design-and-tasks.md` 第十四节
关联需求：`docs/leads-3-m2-2-requirements-draft.md`（2026-09-30 确认：全自动 / 不加 dry-run / 话术分两支）

- **状态**：**已签核（2026-09-30）**。第 8 条「真实来源端到端」由产品负责人实测通过——
  本地智能体按话术 A 支产出 .md 后自己跑了 `npm run collect:land`，**直接写入本机库**，
  台账多出采集记录、公共库多出草稿态候选。已知限制见文末（命令只写本机库，云端靠 `sync --push`）。

## 验收标准

1. **落库命令存在且能跑**：`npm run collect:land -- <目录> --source "…" [--kind document] [--ecosystem "…"]`
   能执行完，打印批次号、新增条数、采集记录 ID。
2. **产出件格式契约生效**：目录里每个 .md 落成一条候选规则；标题取第一个 `# ` 行，
   没有井号标题时退回文件名；`---` frontmatter 不进正文；空文件跳过。
3. **落库规则与 UI 入口一致**：落下的规则是 `draft` + `hypothesis` + `sourceExcerpt`（正文前 200 字），
   项目固定公共资产库；同时**自动生成一条采集记录**（处置=已采，落点指向这批新资产）。
4. **原始产出件留档**：每个 .md 留一条 `source_package` 资产，规则资产的 `sourceAssetId` 指向它。
5. **幂等**：同样的产出件再跑一遍 → 逐条提示「跳过（库里已有同名规则）」，输出 **0 新增**，
   台账不变化。
6. **缺参数被拦**：不给路径 / 不给 `--source` / 目录里没有 .md 时，命令报错并打印用法，不写库。
7. **话术分两支**：生成的话术里 A 支（本地智能体：产出后跑 `npm run collect:land …`，
   带来源名、选了生态就带 `--ecosystem`）与 B 支（云端智能体：交回 .md/.zip，
   到「采集台账 → 给压缩包」导入）都在；不填生态时命令里不冒出 `--ecosystem`。
8. **真实来源端到端**（由产品负责人验）：复制话术给本地智能体 → 它产出 .md 并自己跑落库命令 →
   刷新 `/external-sources`，台账多一行采集记录、公共库多出候选规则（草稿态）。
9. **工具类形态（MCP 服务／本地插件）**：`--kind document` 时产出件落成 `document` 而不是 `rule`——
   带 `role: source` + `authority: false` + `sourceLocation`（来源名），状态 `draft`；
   **不进规则编译候选集**（公共库里 active 的规则不含这批）。用产品的合规函数扫它：**0 违规**。
10. **形态参数被校验**：`--kind` 传了 `rule` / `document` 之外的值 → 报错打印用法、不写库。
11. **话术先判形态**：生成的话术里有「先判断这个来源的结论形态」，规则类与工具类两套产出要求，
    且工具类那支的命令带 `--kind document`。

## 已知限制

- **命令只写本机库**。写完要同步云端：`npm run sync -- --push`（只有 `E:/codeX项目` 能跑同步）。
- **同一来源补采会生成第二条采集记录**：与「给压缩包」入口同口径，没有来源级去重；
  台账里看得见（同来源两行），不做隐藏。
- **去重按「公共库里是否已有同类型同名资产」判定**，规则与文档分开判（同名不算重复），
  且不比较正文——改了正文重跑不会更新已有资产。
- **不自动转正**：落下来是 `draft`（外部采集模式下规则与文档都是草稿），
  确认过再到产品里转 `active`（合规硬约束不变）。
- **工具类文档落的是「参考资料」档**（`documentType` 默认值），不新增文档类型——
  要细分「安装建议／使用手册」属于改数据模型，本版不做。
