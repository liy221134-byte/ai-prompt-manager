# v2.10.0 验收清单（发布门禁与故障演练）

## 怎么用

- 版本：`v2.10.0`，主题是「每次上线留下人能验证的证据，出事时知道怎么退回去」。
- 状态：**已于 2026-09-24 由产品负责人签字**。
- 设计见 [发布门禁与故障演练设计](../superpowers/specs/2026-09-23-v2.10.0-release-gate-design.md)。
- 能对上就在方框里打勾；每条都写依据，证据只记一处。

## 验收记录

- 2026-09-24 产品负责人确认签字。
- 2026-09-23 由 Codex 开发并代跑，界面补验跑在**本机库副本**上（原始本地库没有被改动）。
- 实测数据：默认项目（质量等级「涉及用户数据」）+ 80 条资产。
- 界面动作：工程基线看「最近一次发布」→ 新建发布记录（门禁自动带出 6 项）→
  填版本号、回滚目标、勾第 1 项并写证据 → 保存 → 回来看到门禁 1／6 → 打开记录看详情。

## 六、设计偏差

详细见[设计文档第六节](../superpowers/specs/2026-09-23-v2.10.0-release-gate-design.md)，关键一条：
**发布记录的标题按版本号自动生成**（例如「v2.10.0 发布记录」），编辑器里不再单独填标题。

## 七、已知边界（不在本版）

1. 不接 CI：门禁项人工勾选并写证据，不自动跑检查、不读流水线。
2. 不做演练记录的结构化类型：先给模板和红线，真用得上再加。
3. 不做发布审批流、多环境编排和自动回滚。
4. 加固与验收仍等整个 2.0 产品做完后统一做（这一版是 2.0 功能线的最后一版）。

## 八、这一版省掉了什么

- 没有做门禁项的独立编号目录：检查项文字本身当标识，够用再说。
- 没有做「上次发布和这次发布的差异对比」：只显示最近一次。
- 没有把演练记录做成资产类型：模板 + 红线先跑一轮。
