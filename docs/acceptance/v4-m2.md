## 一、这一版要解决的问题

M1 只服务一个主题：代码里「取第一条主题」，阶梯名字硬编码在组件里。真实需求不是这样——
手里同时有七八个目标（中项、架构师、Python、SQL、AI coding 体系、品牌体系、向上管理），
不同命题要不同的阶梯。学 Python 用「说得出」判不出来：能背出装饰器定义不等于会写。

所以这一版改两处模型：

1. **目标与主题分离**：主题是公共内容（一份主题包一行，所有人看同一份），
   目标是个人安排（每周投入几小时、哪次考）。合成一张表，第二个人一改就改了第一个人的。
2. **阶梯定义随主题走**：五层的「结构」通用（必须五层、判据必须可观察），
   「名字与判据」由主题自带。同一个矩阵组件，换一套表头就能量 Python。

少一步就直接报错——这正好是它该做的事。

## 四、验出来的两个真错

### 4.1 目标主键多用户会撞（已修）

`learning_goals.id` 是 text 主键且无默认值，前端最初写成 `goal-${topicId}`。
单人用没问题；第二个人把同一主题设为主攻时撞主键，而报错指向主键冲突、
不是「已启用过」，排查时极易被带偏。

修法：`src/lib/learning/goal-id.ts` 生成 `goal-${userId}-${topicId}`。
同一人同一主题恒等（upsert 天然幂等），不同人互不干扰。4 项单测锁死。

### 4.2 中项 84 道单选题全部判错（已修）

答对却显示「回答错误」。根因是库里 `answer` 存在两套口径：
早期主题存选项全文（127 道），中项存字母 A/B/C/D（84 道），
判分逻辑拿「选项全文 === 字母」比，永远不等。

修法：`src/lib/practice/answer.ts` 判分前把答案统一展开成选项全文，
两批数据共用一套判分，不改库不重导。9 项单测锁死。
详见 `docs/acceptance/v4-m1.md` 第四节之二。

**这条最值得记**：它不是这一版引入的，是 M0 导题库时就埋下的，
但直到「真在浏览器里点一次」才暴露——单测和导入日志都报成功。
同类错误（字段加进去了、口径对不上）只有真跑一遍才发现。

## 五、真库验证时踩的一个坑

矩阵页一直停在「加载中…」，页面还报「1 Issue」。CDP 抓网络请求才看到根因：
请求是 `learning_topics?id=eq.undefined` → 400，客户端拿到的 `topicId` 是 undefined。

原因是 dev server 是上一个会话启动的，新增的动态路由段 `[topicId]` 没被它加载。
重启 dev server 后正常。

**结论**：新增路由目录（尤其动态段）后要重启 dev server，热更新不一定认。
以后遇到「新页面取不到路由参数」，先重启再排查代码。

## 七、这一版刻意不做

- **不做今日计划**：主攻唯一已经确定，但「今天该动哪块、做几道」还没算。
  这是下一版（M2.5）最该做的，因为现在这页能告诉你缺在哪，仍不告诉你今天干什么。
  → **已由 M2.5 补上**，见 `docs/acceptance/v4-m25.md`。
- **不做 AI 回填通路**：给大纲让 AI 拆模块、知识点、层级，预览确认后写库。
  工程量大，且 118 道题还没刷完，缺的不是造题速度。
- **不做目标编辑表单**：现在只能「设为主攻」，改考试日期、每周小时还得改库。
  `weekly_hours` / `target_date` 字段已预留，界面留到做今日计划时一起上——
  没有今日计划，这些字段填了也不产生任何可见效果。
  → **已由 M2.5 补上**（设置对话框），见 `docs/acceptance/v4-m25.md`。
- 不做诊断（M3）、不做自适应出题（M4）。
