# v2.21.0 验收清单（关联录入入口补齐）

## 版本目标

把「关联已有的东西」这两个入口补齐，都用库里已有的资产关系模型，不动表结构：

1. 图谱里从一个节点直接挂一份文档。
2. 新建验收记录时直接勾选它覆盖哪些需求（勾一条、勾多条都行）。

## 做什么 / 不做什么

**做**：

1. 图谱里选中一个节点时，能直接选一份项目文档挂上去（不再只能「一份文档挂多个节点」）。
2. 说清「这个节点指向谁」列的就是资产关系，图谱的「谁指向它」「间接影响」顺着这批关系算。
3. 节点编辑器的「资产关系」区补一句说明，指出挂文档该往哪加。
4. 文档型验收记录的编辑器里加「覆盖哪些需求」多选框，直接勾需求节点；
   勾选口径和工程基线的覆盖统计共用一份。

**不做**：

1. 不改资产关系的数据结构，不新增表、字段或迁移。
2. 不改「批量挂文档」的行为，只把两边的判定收到一个函数里。
3. 不重做覆盖统计，也不给验收记录加「只能选一条」的限制——产品负责人定的是「两种都认」。
4. 不动待排期第 1 条——它早在 v2.13.0 就做完了，见下。

## 未完成事项与风险

1. **待排期第 1 条其实早就做完了**：工程基线的缺口行在 v2.13.0 就有「或用已有」下拉，
   文档满足了显示「打开」，不需要新建。本次核对后没有改代码。
2. **待排期第 3 条已做完**：产品负责人 2026-09-27 定「两种都认」，所以做成了多选框——
   一份清单可以覆盖一条，也可以覆盖多条，和覆盖统计的口径一致。
3. 每个节点只能看到自己当前类型的树；挂文档的范围是「当前项目的活跃文档」，跨项目不行。
4. 验收记录的「覆盖哪些需求」勾选改的是关系本身：如果这条记录同时用「关系」区指向了别的文档，
   那些关系不受影响；但取消勾选会摘掉指向那条需求的**全部**关系（覆盖统计本来就是这么认的）。
