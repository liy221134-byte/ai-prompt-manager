# v2.1.1 验收清单（文档包导入与元数据编辑）

## 怎么用

- 版本：`v2.1.1`，主题是「上传文档包 → AI 识别草稿 → 确认创建 → 补齐元数据」。
- 状态：**未完成，不能签字**。后端与逻辑已完成，界面还没做，见最后两节。
- 判定方式：能对上就在方框里打勾；只在自动化里验证过的项目会写明依据。

## 一、已经可以通过的项

- [x] 上传 Markdown、纯文本和 ZIP 都能成功，原始文件被完整保留且可下载查看。
      依据：上传校验与存储测试、上传接口测试（含按相对路径取回原文）。
- [x] 上传阶段不创建项目、不写入资产，只把原文暂存到来源目录。
      依据：接口测试「上传后不写资产，只暂存原文」。
- [x] AI 提取的规则创建后是草稿状态，不会自动进入活跃列表。
      依据：确认创建的测试断言规则状态为 `draft`。
- [x] AI 摘要不覆盖原文：来源包资产的正文为空，原文只以文件形式保留，资产里只记相对路径。
      依据：确认创建的测试断言来源包 `content` 为空且记录 `storedPath`。
- [x] 资产第 1 版的来源指向对应的来源包，元数据修改会产生新版本而不是覆盖。
      依据：确认创建的版本来源测试、元数据版本测试。
- [x] 未登录不能上传文件，也不能读取别人的来源包。
      依据：云端桶策略在真实 Postgres 上核对（私有桶、四条策略都按 `auth.uid()` 隔离）。
- [x] 一次导入最多 200 条资产，超出会要求分批。
      依据：草稿上限测试与确认接口校验。
- [x] 规则与文档的完整元数据在数据层可用：核心字段必填，扩展字段可空，
      旧元数据缺字段按空值处理，认不出来的值按空值兜底。
      依据：元数据测试（旧数据兼容、类型兜底、非法值判定）。

## 二、还没做完、暂时不能勾的项

      **预览界面还没做**，所以界面上看不到。

- [ ] 文档可以在界面上区分来源、工作稿、权威版和编译结果。
