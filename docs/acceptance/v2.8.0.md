# v2.8.0 验收清单（项目质量等级与工程基线）

## 怎么用

- 版本：`v2.8.0`，主题是「按项目风险等级，把该有的工程文档和该守的规则摆到明面上」。
- 状态：**功能与界面补验已完成，等你签字**。
- 设计见 [生产工程治理设计](../superpowers/specs/2026-09-23-v2.8.0-quality-level-design.md)。
- 能对上就在方框里打勾；每条都写依据，证据只记一处。

## 验收记录

- 2026-09-23 由 Codex 开发并代跑，界面补验跑在**本机旧库副本**上
  （2.8.0 之前建的库，项目表没有 `risk_level` 列），原始本地库没有被改动。
- 实测数据：默认项目 + 75 条资产（含 66 个图谱节点）。
- 界面动作：打开项目设置看等级 → 打开工程基线看要求与缺口 → 点「新建文档」建了
  一份「架构与请求链路」→ 回来看到缺口减少 → 切到「涉及用户数据」→ 要求从 2 份变成 6 份。

## 一、质量等级字段

- [x] 项目设置里能选等级，新建项目时也能选。
      依据：项目设置里「质量等级」下拉显示「个人工具」，四档都能选；新建项目表单同样有这个下拉。
- [x] 老库自动升级，老项目读成「个人工具」。
      依据：拿 2.8.0 之前的库副本起服务，`PRAGMA table_info(projects)` 从
      `id,name,description,status,stage,created_at,updated_at,archived_at` 变成多一列
      `risk_level`，原来的默认项目读出来是 `personal`，界面正常打开。
- [x] 改等级能存住。
      依据：切到「涉及用户数据」后直接查库，`projects.risk_level = 'user_data'`，
      `updated_at` 也跟着更新。
- [x] 老备份能导入。
      依据：备份解析现在按「缺字段补个人工具」处理，`tests/asset-backup-v2.test.mjs`、
      `tests/asset-backup-compatibility.test.mjs` 全过。

## 二、工程基线

- [x] 按等级列出「必须有的工程文档」，并算出已有／缺失。
      依据：个人工具要求 2 份（架构与请求链路、环境变量清单），打开面板显示
      「已有 0／2，还缺 2」，每条都有一条「新建文档」按钮。
- [x] 缺失项能一键进新建文档，标题和文档类型已填好。
      依据：点「新建文档」后编辑器里标题是「架构与请求链路」、文档类型是「架构说明」、正文空着；
      保存后列表计数变成「文档 1」，数据库里那条资产的 `documentType` 是 `架构说明`。
- [x] 已经有的文档会让缺口消失，能点开。
      依据：保存后回到工程基线，显示「还缺 1」，第一条变成「已有：架构与请求链路」并带「打开」按钮。
- [x] 等级越高要求越多。
      依据：切到「涉及用户数据」后要求变成 6 份、「还缺 5」；测试里断言高敏感等级包含全部 8 份。
- [x] 要求里的每份文档都对应仓库里的模板文件。
      依据：`tests/quality-level.test.mjs` 拿 `templates/engineering/` 的真实文件比对
      文件名和一级标题，对不上就失败。
- [x] 建议关注的规则方向和发布前检查按等级给出。
      依据：面板上三段分别列出文档、规则方向、发布前检查；个人工具 2 条检查，
      涉及用户数据 6 条检查。

## 三、边界

- [x] 只做对照和跳转，不自动创建任何东西。
      依据：文档要用户点「新建文档」再保存；规则方向只提示，不自动装规则包。
- [x] 判定口径写在界面上，不用猜。
      依据：面板底部写明「同一个项目里活跃、没进垃圾箱的文档资产，文档类型对得上或标题一样」；
      测试覆盖草稿、归档、垃圾箱、别的项目和非文档资产都不算已有。
- [x] 等级不认识时不炸。
      依据：`readQualityProfile` 和 `readProjectRiskLevel` 对未知值都回落到「个人工具」，
      有单元测试。

## 五、线上要做的一步（交付前必须执行）

这一版给项目表加了一列。代码一推到 `main`，Vercel 会自动部署；**迁移要在代码生效前执行**：

```sql
-- supabase/migrations/20260923150000_add_project_risk_level.sql
alter table public.projects
  add column if not exists risk_level text not null default 'personal';
```

执行方式二选一：在 Supabase 控制台里跑这段 SQL，或者用数据库密码走
`supabase db push --db-url`。跑完再让代码上线（或者上线后立刻跑，中间这段时间
线上「项目设置」保存会报错，其他功能不受影响）。

## 六、设计偏差

详细见[设计文档第六节](../superpowers/specs/2026-09-23-v2.8.0-quality-level-design.md)，关键两条：

1. 要求清单做成工具栏抽屉（和项目图谱、导入工程一致），不是工作区里的常驻面板。
2. 「等级改动写进版本记录」没有实现：项目没有版本表，改成更新时间 + 界面即时生效；
   要真正的项目版本记录是另一个改动。

## 七、已知边界（不在本版）

1. 不记录「这次发布检查做没做」：发布门禁与故障演练记录排在 v2.10.0。
2. 不做验收证据链：需求编号 → 验收条件 → 测试步骤 → 证据 → 提交版本，排在 v2.9.0。
3. 不自动创建文档、不自动装规则包：只给清单和入口。
4. 不做第三方安全扫描和成本采集。
5. 加固与验收仍等整个 2.0 产品做完后统一做。

## 八、这一版省掉了什么

- 没有引入文档生成：模板正文让用户自己复制，少一套「模板变量渲染」的机制。
- 没有给项目加版本表：等级改动只更新更新时间，够用再说。
- 没有做等级到规则包的自动安装：只提示方向，装不装由用户定。
