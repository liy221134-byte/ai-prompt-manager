## 一、这一版要解决的问题

到 M2.5 为止，系统能准确说「今天做哪几道题」，但答不了「这个知识点到底在讲什么」。

算一下就知道这不是小缺口：中项 380 小时配 118 道题，一天 3 道，40 天刷完，
剩下 160 天没有东西可学。**缺的是内容，不是功能。**

所以这一版补的是内容：每个知识点一份讲义，固定四段——一句话定义 + 要素 / 例题 / 怎么考。

## 三、讲义放在哪：改过一次决定

原方案是在 `knowledge_points` 上加 `summary` / `note_md` 两列，写一份迁移，导入器把讲义写库。
**这个方案当晚被推翻**，迁移文件 `20261028170000_add_knowledge_notes.sql` 已删除（从未执行过，删掉无副作用）。

| | 存数据库（原方案） | 编译成常量（现方案） |
| --- | --- | --- |
| 真源 | 库里一份 + 主题包一份，**两份要对齐** | 主题包一份 |
| 改讲义后 | 要重导一次库；漏了就是页面显示旧内容，且看不出异常 | 改 yaml → `npm run gen:topic-notes` → 提交 |
| 运行时开销 | 本来就要查知识点，讲义顺带取，无额外请求 | 零请求，随 bundle 走（5 篇约 20 KB） |
| 迁移依赖 | 要一次 DDL | 无 |
| 谁来写 | 导入器 | 生成器（`scripts/build-topic-notes.mjs`） |

判据是「它是什么」：讲义是随主题包分发的**静态内容**，有读无写，不参与判分也不参与统计。
给只读内容建副本，等于给自己多养一份必须同步的真源。

**代价说清楚**：多了一个生成步骤。所以加了两道守卫——
`npm run check:topic-notes`（挂进 `check:fast`）与 `tests/topic-notes.test.mjs` 的同步用例，
改了 yaml 忘了重新生成会直接失败，不是靠人记得。

## 四、验出来的真错

### 4.1 练习页的讲义入口点了没反应（已修）

`learning-topic.tsx` 在练习模式下**提前 return**，只渲染 `PracticeQuiz`；
讲义抽屉挂在下面那段主 `return` 里。结果是：点「看「…」的讲义」→ 状态设上了 → 但抽屉节点不在渲染树上 → 界面毫无变化。

浏览器实测才发现的（读 DOM 确认没有 `z-50` 层）。修法是把抽屉提到两个 `return` 之前定义，两边共用同一个 `noteDrawer`。
单测覆盖不到这种错——它是「组件树分支少挂一个节点」，只有真点一下才知道。

### 4.2 第一版讲义文档没写清「存哪」（已补）

`topic-pack-schema.md` 原来只说 `note` 怎么写，没说写完去哪。补了第三节末尾那张对照表与实现路径。

## 五、已知缺口

- **29 个知识点只有 5 份讲义**（S1 全部）。其余 24 个是「讲义待补」的灰字状态，按模块逐个补。
  讲义校验卡的是「三段齐全 + 一句话不超 60 字」，不是字数下限——长度交给写的人判断。
- **讲义全量编进前端 bundle**。5 篇 20 KB 没问题；29 篇约 60 KB，仍在可接受范围。
  真到影响首屏（比如十几个主题）时再改成按主题动态 import，现在做是过度设计。
- 讲义里的表格靠 `MarkdownContent` 渲染，已验证表格、列表、行内加粗都正常，
  但**没验过超长表格在窄屏的横向溢出**。
