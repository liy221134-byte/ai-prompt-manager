# v2.24.0 验收清单（项目规模参与编译筛选）

## 版本目标

让「适用项目规模」这个字段真正生效：只给中大型项目的规则，不会被个人工具项目收进产物。
设计见 `docs/superpowers/specs/2026-09-27-v2.24.0-project-scale-filter-design.md`。

## 做什么 / 不做什么

**做**：技术档案加结构化的「项目规模」字段；规则编译按它筛（有交集就收）；
没填就不筛；编译抽屉里说明当前按不按规模筛。

**不做**：不给 `projects` 表加字段、不拿质量等级推算规模、不强制填规模。
详见设计文档第一节。

## 验收标准

1. [x] 档案填 `personal`，一条只标 `large` 的规则进「已排除」，理由写明两边规模。
       依据：`tests/rule-compile.test.mjs`「项目规模参与筛选：有交集就收，一项都对不上才排除」。
2. [x] 档案填 `personal` 和 `medium`，一条标 `medium` 的规则照收（有交集就收）。
       依据：同文件「项目规模为空时不筛；规则标了多项规模时有一项对上就收」。
3. [x] 规则没标规模时，任何项目规模下都收。
       依据：同文件第一条测试里的 `rule-any` 在 included 里。
4. [x] 项目没填规模、或没有技术档案时不筛。
       依据：同文件「项目规模为空时不筛…」里不传规模的断言。
5. [x] 技术档案元数据校验：规模里出现非法值要被拒；缺字段时补成空数组。
       依据：`tests/asset-tech-profile.test.mjs`「技术档案里的项目规模：合法值通过校验，非法值被拒」
       与「技术档案没填项目规模时补成空数组，非法值在归一化时被丢掉」。
6. [x] 技术档案编辑器里能多选四档规模，存回去能读出来。
       **存回去**由 `tests/asset-tech-profile.test.mjs`「项目规模能写进草稿再存回元数据；
       没填就不写这个字段」覆盖；**界面**由 2026-09-27 本机实测确认——「新建技术档案」的
       编辑器里能看到四个勾选框（个人工具／中型云端产品／大型平台／受监管项目），
       下面是技术栈清单。截图 `.data/acceptance-2026-09-27/24-02-tech-profile-scale.png`。
7. [x] 编译抽屉里能看到当前按哪些规模筛；没填时显示「不按规模筛」。
       依据：同日实测，抽屉顶部同时显示「这个项目还没有技术档案，或者档案里没有能对上
       技术上下文的技术栈——本次不按技术栈筛。」和「这个项目还没填项目规模——本次不按规模筛。」
       截图 `24-01-compile-scale-notice.png`。
8. [ ] **用 0.7.0 那 6 条做真实验证——没做。**
       它要求先把 0.7.0 的规则包导入本机库（一次写库），再给本项目建一份技术档案并填「个人工具」，
       然后看那 6 条是否进「已排除」。这两步都会改本机库，我没有擅自做。
       **下次导入规则包时顺手验**。
9. [x] 完整检查通过。依据：2026-09-27 `npm run check`——类型检查、547 条测试、代码检查、
       生产构建全过（本版新增 5 条测试）。

## 设计偏差

1. **规则的规模实际存在 `pack.projectScale` 里，不在规则元数据顶层。**
   设计写的是「规则标了规模时」，我原以为它读的是规则自己的字段；查库发现
   `RuleAssetMetadata` 根本没有 `projectScale`——46 条规则的顶层都是空的，
   而 `metadata.pack.projectScale` **逐条不同**（`rule-mth-scope-001` 是 personal／medium／large，
   `rule-playbook-release-001` 是 medium／large／regulated）。也就是说：**这个值确实是这条规则
   自己的规模**，只是被放在 pack 链接里。
   我的处理：新增一个 `readRuleProjectScale`，从 pack 链接里读，并把这条语义写进代码注释；
   没进过包的手工规则没有这个值，按「没标规模」处理。
   **代价**：字段位置语义含糊（叫 `pack.projectScale`，读起来像「整包的规模」）；
   手工建的规则没法声明规模。要挪到顶层的话，得动导入映射并回填现有规则，
   **这条请你定要不要单独做一版**。

## 未完成事项与风险

1. 第 8 条没验，见上。
2. 规模只有「技术档案」一个来源；档案没填就等于不筛。也就是说**不填不会拦任何东西**——
   想靠它挡住大型项目规则，前提是每个项目都老老实实填了规模。
3. 技术档案一个项目一份（已有规则），所以规模也是项目级的一个值，做不到「同一个项目里
   不同模块用不同规模」。
