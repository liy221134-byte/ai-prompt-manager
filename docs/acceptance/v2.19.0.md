## 验收标准

- [x] 同步计划能算出「推到云端／拉到本机／待裁决／两边一样」四类；限定方向时另一向不动。
      依据：`tests/asset-sync.test.mjs`。
- [x] 两边内容一样时不动、也不算冲突。依据：同文件「两边都有且内容一样」。
- [x] 时间一样但内容不同 → 进待裁决，两边都不动。依据：同文件「时间一样但内容不同」。
- [x] 只增不删：同步清单里没有删除动作，删除状态本身照常同步。
- [x] 命令可用：`npm run sync -- --dry-run` 打印本机/云端条数与四类计数；
      `--export-push-file` 导出备份文件（本轮导出 4 个项目、248 条资产）。

## 需要你操作的

- [ ] 打开线上站点 → 数据管理 → **导入备份** → 选 `sync-push-2026-09-24.json` → 确认导入。
- [ ] 导入后核对：云端条数 = 本机 248 条里云端原来没有的那些 + 原有 80 条。
- [ ] 以后换到能直连 Supabase 的网络（例如手机热点）时，跑一次 `npm run sync -- --dry-run` 看两边差异。

## 未完成事项与风险

- 不做共同祖先比对：只按时间判新，两边同分钟都改过时可能判错（内容仍在版本记录里）。
- 待裁决只在命令行列出，没有界面。
- 云端侧的同步入口（让云端主动来读）没做；本机出口被拦时只能靠备份导入。
- 自动定期（每天自动跑）没做：本版只给命令，定时交给 Codex 定时任务或云端定时入口。
