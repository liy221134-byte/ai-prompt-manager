# v2.22.0 验收清单（技术上下文参与编译筛选）

## 版本目标

让规则的「技术上下文」从只显示不生效，变成真的参与编译筛选：标了具体技术的规则，
只有和项目技术栈对得上才收进产物。设计见
`docs/superpowers/specs/2026-09-27-v2.22.0-tech-context-filter-design.md`。

## 做什么 / 不做什么

**做**：规则的技术上下文参与筛选；技术栈只认项目里那份活跃技术档案；
没档案就不筛；有交集就收；界面上写明当前按不按技术栈筛。

**不做**：不改表结构、不新增第二个技术栈来源、不在产物正文里标技术上下文、
不自动保存草稿。详见设计文档第一节。

## 验收标准

逐条对照设计文档第三节的 9 条。

1. [x] 项目技术栈有 `Next.js` 时，标 `nextjs` 的规则进「参与编译」。
       依据：`tests/rule-compile.test.mjs`「技术上下文参与筛选：有交集就收，一项都对不上才排除」。
2. [x] 项目只有 `Next.js`、规则标 `supabase` 时进「已排除」，理由点名两边。
       依据：同一条测试断言理由为
       「技术上下文对不上：这条规则是 supabase，这个项目的技术栈是 nextjs」。
3. [x] 规则只标 `generic`、或没标技术上下文时，任何技术栈下都进「参与编译」。
       依据：同一条测试里的 `rule-generic` 与 `rule-none` 都在 included 里。
4. [x] 项目技术上下文为空时（没有档案，或档案里认不出技术），不筛。
       依据：同文件「项目技术上下文为空时不筛：所有活跃规则照旧进候选」。
5. [x] 名字能对上：`Next.js`／`next.js`／`next` 都算 `nextjs`，`PostgreSQL`／`pg` 都算 `postgres`；
       认不出的名字被忽略、不报错。
       依据：`tests/asset-tech-profile.test.mjs`「技术栈名字能读出技术上下文：归一化加别名，
       认不出来的忽略」与「没有技术档案、或档案里全是认不出的名字时，技术上下文是空的」。
6. [x] 规则同时标 `[nextjs, supabase]`、项目只有 `nextjs` 时照收（有交集就收）。
       依据：`tests/rule-compile.test.mjs` 里的 `rule-both` 在 included 里。
7. [x] 冲突检测行为不变：技术上下文有交集仍算冲突候选。
       依据：`tests/rule-compile.test.mjs`「冲突候选只列维度重叠的规则，并写明重叠在哪」本次未改动、仍通过。
8. [x] 编译抽屉里能看到当前按不按技术栈筛。
       依据：2026-09-27 本机实测（科创平台 2.0，无技术档案）显示
       「这个项目还没有技术档案，或者档案里没有能对上技术上下文的技术栈——本次不按技术栈筛」，
       同时「参与编译 12 条、已排除 0 条」，没有误筛。截图
       `.data/acceptance-2026-09-27/22-01-compile-notice.png`。
       **「按技术栈筛」那一半没有在界面上实测**：库里 0 份技术档案、也没有标了具体技术的项目规则，
       造这个场景要新建一份技术档案和一条规则。功能本身由第 1、2、6 条测试覆盖。
9. [x] 完整检查通过。依据：2026-09-27 `npm run check`——类型检查、534 条测试、
       代码检查、生产构建全过（本版新增 4 条测试）。

## 设计偏差

1. **「不筛」的条件比设计文档宽了一条。** 设计文档写的是「没有技术档案就不筛」；
   实现里改成「项目的技术上下文集合为空就不筛」，这同时覆盖了「档案里全是认不出的技术栈名」
   这种情况（例如档案里只写了 React、Tailwind）。
   原因：如果只在「没有档案」时不筛，那么一份写满陌生技术名的档案会让所有标了具体技术的规则
   被一次全排除，而且界面上看不出为什么。**这条要你定改设计还是改实现。**

## 未完成事项与风险

1. 技术上下文字段本身是自由文本（`metadata.techContext` 是字符串数组，界面是手填），
   所以「认识的取值」这份清单写在代码里（`src/lib/tech-profile.ts` 的 `knownTechContexts`），
   和 `seed-packs/engineering-foundations/schema.md` 靠人工保持一致——两边都可能漂移。
2. 技术栈名字靠归一化加一张别名表匹配。写了别的名字（例如「Postgres 16」能对上，
   但「关系型数据库」对不上）就不参与匹配，界面上不会报错，也不会提示「这个名字没认出来」。
3. 筛选结果只影响编译候选；已经编译保存过的产物不会自动重算。
