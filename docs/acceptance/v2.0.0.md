# v2.0.0 整体验收清单（项目与统一资产底座）

## 版本与结论

- 目标版本：`v2.0.0`。
- 分支：`feat/v2.0.0-asset-foundation`。
- 代码与本地验证：通过。
- 人工验收：项目工作区、规则和文档已在浏览器逐条确认。
- 云端验证：未执行，Supabase 迁移还没有应用。
- 结论：本地可交付；云端验收要等迁移应用后补做。

## 本期范围

### 包含

- 项目工作区：新建、重命名、归档、重新激活、切换，刷新后记住上次使用的项目。
- 统一资产模型：提示词、规则、文档共用一套资产主模型和不可变版本。
- 资产列表：按项目、类型和状态筛选，支持搜索。
- 规则和文档：新增、编辑、查看、归档、重新激活、查看历史版本、恢复历史版本。
- 旧提示词数据和旧版提示词备份继续可用。

### 不包含

- 文档包导入和 AI 识别项目草稿（`2.0.1`）。
- 规则和文档的完整元数据编辑（`2.0.1`）。
- 技术档案、资产关系、完整备份格式升级（`2.0.2`）。
- 迁移演练、回滚验证和边界测试（`2.0.3`）。

## 自动化验证

`npm run check` 退出码 0：lint 无错误、类型检查通过、190 项测试全部通过、生产构建成功。

本版本新增的测试重点：

- 项目和资产领域模型：项目生命周期、资产类型、资产版本结构。
- 本地迁移：默认项目创建、提示词和恢复快照迁移、重复打开不重复迁移、迁移失败不破坏旧数据。
- 云端结构：项目、资产、版本表和 RLS 策略。
- 数据源契约：本地与云端同一套方法。
- 项目工作区：项目创建、重命名、归档、重新激活、最近使用项目记忆。
- 规则和文档：草稿校验、字段构造、版本记录、恢复到历史版本。
- 备份兼容：旧备份导入默认项目、重复导入不重复、合并与优化恢复关系、垃圾箱恢复、备份只包含提示词。

## 人工验收步骤

1. 打开首页，确认默认项目下原有 3 条提示词数量和内容不变。
2. 新建项目，确认新项目计数全为 0；切回默认项目，确认提示词恢复。
3. 打开项目设置，重命名并改阶段，确认界面和列表同步更新。
4. 归档默认项目，确认 3 条提示词仍在；重新激活，确认项目回到进行中列表。
5. 切到「规则」标签，新增一条规则，确认保存后自动打开详情并产生第 1 版。
6. 编辑规则改正文，确认产生第 2 版；恢复第 1 版，确认产生第 3 版且第 1、2 版都还在。
7. 归档规则，确认从活跃列表消失；切到状态「已归档」能找到，重新激活后回到活跃列表。
8. 切到「文档」标签，新增一条文档，确认文档类型和状态写入正确。
9. 打开任意提示词详情，点「回到优化前」并确认，确认标题和正文回到优化前。
10. 打开「数据管理」，确认备份范围提示明确说明只包含提示词。

## 已知边界与风险

1. **备份只覆盖提示词。** 规则和文档不在备份文件里，界面上已经明确提示。完整备份升级排在 `2.0.2`。
2. **提示词写入路径还没有切到统一资产。** 提示词仍写入旧的提示词表，统一资产表在启动时同步；因此「导入的提示词进入默认项目」要在下一次启动后才能在资产数据里看到，界面上的提示词列表不受影响。
3. **状态变化也会产生一条版本记录。** 归档和重新激活走的还是保存通道，所以版本列表里会多出「归档资产」「重新激活资产」两条记录。
4. **列表一次读取全部项目的资产再在前端过滤。** 个人规模没问题，资产量很大时需要改成按项目请求。
5. **新账号或云端首次使用会自动补建默认项目。** 保证提示词始终有归属。
6. **云端未验证。** 迁移没有应用前，云端模式跑不起来。
