# v2.29.0 验收清单（种子包状态口径与规则包重装）

## 版本目标

修两个真实断点：① 打包器把成员状态强制成 `active`，源文件标的 `candidate` 从来没生效，
导致「未经人工确认不许升 active」这条 SOP 被系统性绕过；② 重装规则包时包条目的版本号
永远停在首次导入的值。设计见
`docs/superpowers/specs/2026-09-30-v2.29.0-seed-pack-status-and-reimport-design.md`。

## 做什么 / 不做什么

**做**：打包器按源文件 `status` 出包（`candidate` → 库里的 `pending`）；重装时更新包条目
的版本号、说明和元数据；导入结果报「新增／跳过／其中旧版本」三个数字；导入对话框说清
「装到哪个项目」是复制正本还是只装引用，并从公共资产入口默认选中默认项目；把
「默认项目 = 公共资产库」写进 `AGENTS.md`。

**不做**：不覆盖已有成员的正文和状态；不改包文件格式与去重键；不做「一键升级库里成员」；
不动库里已有的 29 条 active 欠账（另见文末）。详见设计文档第一节。

## 验收标准

1. [x] 重跑打包器后，包内成员状态与源文件对得上：工程包 0.13.0 是 **58 条 `pending` +
       11 条 `active`**（原来 54+15 条全 `active`）。
       依据：`tests/seed-pack-import.test.mjs`「成员状态跟着源文件走：candidate 进库是
       待确认，不再被强制成 active」；那 11 条 active 里 1 条是源文件本来就写 `active` 的
       `PLAYBOOK-DEBUG-001`，另 10 条是没有 `status` 字段的画像与验证记录。
2. [ ] 导入后新成员的库内状态是 `pending`，且合规违规数**不因新导入而增加**。
       依据：只读沙盘推演确认新增成员状态是 `pending`（见第 6 条）；**真正导入本机库
       之后**再跑 `npm run check:leads3-compliance` 复核，属待办。
3. [x] 库里已有 0.12.0 的包时导入 0.13.0 的包文件 → 包条目版本号变成 `0.13.0`。
       依据：`tests/rule-pack-install.test.mjs`「重装规则包：包条目按包文件更新，编号、
       项目和创建时间不动」。
4. [x] 同一次导入，已有成员一条不改（正文、状态都不动）。
       依据：同一条测试断言 `assetsToCreate` 只含新成员；实现里 `packAssetUpdate` 只碰包
       条目本身，没有任何成员写入路径。**库里实际那条**的 `updatedAt` 未被改动，需在真正
       导入后抽查一次，属待办。
5. [x] 新增成员数正确：工程包 **8** 条（含补登的 `MTH-REQ-FORMAT-001`）、训练包 **6** 条。
       依据：只读沙盘推演（用本机库真实数据）。
6. [x] 导入结果能报出三个数字：新增、跳过、其中旧版本条数。
       依据：只读沙盘推演——工程包「新增 8 / 跳过 61 / 其中旧版本 61」，训练包
       「新增 6 / 跳过 9 / 其中旧版本 9」；版本号读不出来时一律不算旧版本，见
       `tests/rule-pack-install.test.mjs`「版本号读不出来时不算「旧版本」，宁可少报」。
7. [ ] 包条目更新后 `asset_versions` 里多一条记录，且能恢复到旧版本。
       依据：走的是既有的 `updateAsset` + 版本机制（`versionReason: "save"`），
       代码层面已接上；**需要在界面上点一次恢复**才算验完，属待办。
8. [ ] 从公共资产入口打开对话框，默认选中「默认项目」；切到普通项目时说明文字写明
       「只装引用，正文留在公共资产库」。
       依据：代码已按设计改（`defaultProjectId` 由调用方按视图传入、说明文字随选择变化），
       **界面未实测**——见文末「未验完的一项」。
9. [x] `AGENTS.md` 里能搜到「默认项目 = 公共资产库」这条对应关系。
       依据：`AGENTS.md` 产品规则第 7 条。
10. [x] 回归：`npm run check` 全过（类型检查 + 587 项测试 + 代码检查 + 生产构建）。

## 未验完的一项

第 8 条（导入对话框）是这次唯一没做完的验收。原因是本机环境卡住，不是代码没改：

- 目录里已经有一个开发服务在跑（PID 11972，10:08 启动，占着 `localhost:3000`），
  Next.js 不允许同目录再起一个 `next dev`，所以 `npm run dev:local` 起不来。
- 那个服务是**云端模式**（`/api/health/db` 返回 401，说明走了 Supabase 那条分支），
  进它的界面需要登录态，而我没有已保存的会话——按项目规则不许拿产品负责人的账号去登录。

要验完这一条，二选一：① 产品负责人自己用 `npm run dev:local` 起服务，打开
「公共资产 → 更多 → 导入规则包」看一眼默认项目和说明文字；② 同意我停掉 3000 上那个
服务，由我起本机模式自己验。
