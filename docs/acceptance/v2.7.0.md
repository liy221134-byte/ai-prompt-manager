# v2.7.0 验收清单（MCP 动态查询）

## 怎么用

- 版本：`v2.7.0`，主题是「让 AI 在干活时直接查我的库，也能把结果写回来」。
- 状态：**已于 2026-09-23 由产品负责人签字**。
- 设计见 [MCP 动态查询设计](../superpowers/specs/2026-09-23-v2.7.0-mcp-dynamic-query-design.md)；

## 二、写入

- [x] 新建的资产能在界面上看到，来源标成「AI」。
      依据：MCP 新建规则 `rule-de838ce5-…` 后，用应用自己的接口 `GET /api/assets` 读回来：
      标题「MCP验证：本地服务可写」、来源 `ai`、作用层级 `global`、正文完整。
- [x] 修改会产生新版本，旧版本保留。
      依据：同一条规则 `GET /api/assets/<id>/versions` 返回 3 条版本——
      创建资产／保存资产／归档资产。
- [x] 归档后不再出现在默认列表和查询结果里。
      依据：`set_asset_status` 归档后再查，规则查询结果里不再出现；内容和历史版本都还在。
- [x] 工具清单里没有删除类工具。
      依据：写工具只有 `create_asset`／`update_asset`／`set_asset_status`，
      没有删除、没有垃圾箱、没有清空垃圾箱。
- [x] 图谱节点编号重复会被拦下，不写坏数据。
      依据：`tests/mcp-write.test.mjs` 和 `tests/mcp-server.test.mjs`——同编号（大小写不同也算重复）

## 三、边界与安全

- [x] 只读开关生效。
      依据：`MCP_READ_ONLY=1` 时工具清单只剩六个查询工具（内存传输和真实 stdio 两处用例都断言过）。
- [x] 库文件按仓库定位，不看客户端在哪个目录启动。
      依据：在 `%TEMP%` 目录里直接跑脚本，stderr 打印的是
      `E:\codeX项目\.data\prompts.sqlite`。
- [x] 找不到项目或资产时给中文提示，不抛异常、不写坏数据。
      依据：`tests/mcp-server.test.mjs`「找不到的项目和资产都返回中文提示，不抛异常」。
- [x] 不开端口、不引外部服务。
      依据：只用标准输入输出；新增依赖只有 `@modelcontextprotocol/sdk` 和 `zod`，
      都在开发依赖里，生产构建产物不变（`npm run build` 通过）。

## 五、设计偏差

详细见[设计文档第六节](../superpowers/specs/2026-09-23-v2.7.0-mcp-dynamic-query-design.md)，
关键两条：

1. 按「AI 也能写」的决定，工具从六个变成九个；写工具只做界面上已有的可恢复操作。
2. **写入没有「先预览、我确认」这一道**：MCP 的写入由 AI 发起，没法在界面拦确认，
   改成靠「每次修改都有不可变版本 + 没有任何删除入口」兜底。
   如果你要的是「AI 只能落草稿、你确认后才生效」，说一声我改。

## 六、已知边界（不在本版）

1. 只有本机能用：不做远程 MCP、不开端口、不做鉴权和多用户。
2. 关系（引用／依赖／替代／实现）仍然只能在界面上建；MCP 只能读关系。
3. 技术档案不开放写入（一个项目一份、结构特殊）。
4. 项目设置、规则编译、备份导出、垃圾箱仍然只在界面上做。
5. 云端 Supabase 库不参与：只读本机 SQLite。
6. 加固与验收等整个 2.0 产品做完后统一做。

## 七、这一版省掉了什么

- 没做 MCP 的 resources 和 prompts 能力，只做 tools：AI 真正需要的是工具调用。
- 没做写入确认弹窗（做不了），改用版本历史加「没有删除入口」兜底。
- 没做批量工具（批量建节点、批量改标签、批量归档）：需要时再说。
