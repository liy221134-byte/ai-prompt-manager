# v2.11.0 验收清单（统一加固与验收）

## 怎么用

- 版本：`v2.11.0`，主题是「不新增功能，把 2.0 这一条线的迁移、备份恢复、回滚和安全边界统一验一遍」。
- 对应关系：本版就是 [2.0 资产管理底座计划](../v2-plan.md) 里的「加固与验收」
  （计划里写作 `2.0.3`），早期清单编号是 `v2.1.3`；
  那一版只覆盖到 MVP，功能线做完后按现在的版本顺序统一做，落地为 `v2.11.0`。
  早期记录保留在 [v2.1.3 验收清单](v2.1.3.md)，本文只记这一轮统一加固的结果。
- 能对上就在方框里打勾；每条都写依据，证据只记一处。

## 验收记录

- 2026-09-24 由 Codex 开发并代跑。演练都在**真实数据的副本**上做，原始本地库没有被改动
  （演练后核对：原始库仍是 7 条资产、7 条版本、没有新增）。
- 演练数据：本机库副本 1 个项目 + 82 条资产（7 类）+ 2 条关系；云端生产库 41 条资产 + 1 个项目。
- 动作：回滚演练（用 v2.9.0 的代码读 v2.10.0 的库）→ 备份往返演练 → 云端只读复核 →
  按发现修代码和文档 → 清理临时产物。

## 三、回滚

- [x] 跨版本回滚的风险实测并留证。
      依据：用 v2.9.0 的代码读含「发布记录」的库，**启动即失败**：
      「资产数据无法识别：release_record-…」；同一份库用当前代码读正常（82 条）。
      这条写进了 `docs/operations/release-rollback.md` 的「回滚前置检查」，
      并列出各版本引入的资产类型和处置顺序。
- [x] 报错不再是「看不懂的一句话」。
      依据：本地和云端两条读路径的报错都改成带类型和处置建议
      （先导出备份，再决定升级回新版本还是删掉这条记录）；
      `tests/asset-database.test.mjs` 里有一条用例专门守这个场景。
- [x] 同版本内回滚没有这个问题。
      依据：v2.11.0 不引入新资产类型，回到 v2.10.0 时类型集合一致。
- [x] 回滚后的验收清单更新到 2.0 的实际范围。
      依据：`docs/operations/release-rollback.md` 的验收项从「看得到全部提示词」
      改成「项目与资产列表、各类资产详情、备份导入、规则编译、项目图谱、MCP 各跑通一次」。

## 四、安全与边界

- [x] 匿名访问云端库被拒绝。
      依据：2026-09-24 用 anon key 直接读 `assets` 和 `projects`，都返回 401
      （`permission denied for table`）；行级安全与授权范围没有松动。
- [x] 云端配置缺失时安全关闭，不降级到本机库。
      依据：`tests/runtime-config.test.mjs`；线上强制 `supabase` 模式，配置不合法直接拒绝启动。
- [x] 未登录访问受保护页面会跳登录。
      依据：`tests/auth-routing.test.mjs`。
- [x] 限额与边界都有测试兜着。
      依据：来源包单包 20 MB、单次导入最多 200 条、ZIP 条目数与体积上限
      （`source-package-upload.test.mjs`、`zip-reader.test.mjs`）；
      代码目录扫描上限 3000 个文件/单文件 400 KB/12 层（`code-directory-scan.test.mjs`）；
      图谱节点编号同项目同类型唯一（`graph-node.test.mjs`）。
- [x] AI 不能替人拍板。
      依据：验收记录的结论在 MCP 写入字段里不存在，新建一律「待确认」；
      发布记录不在 MCP 可写类型里，真机调用被参数校验拒绝（v2.10.0 验收记录）。

## 七、已知边界

1. 备份不含历史版本和来源包原文，已写进备份说明；要留历史版本得另外留库文件。
2. 跨「引入新资产类型」的版本回滚，必须先导出备份并清理新类型资产；
   没有改成静默跳过——少显示数据比报错更危险。
3. 没有引入浏览器端自动化测试框架：边界靠定向实测 + 单元测试覆盖。
4. 线上域名自测（需要产品负责人的 Vercel 账号）单独挂待办，不并入本版。

## 八、这一版省掉了什么

- 没有为「回滚」写脚本：手动步骤只有四步，写成脚本反而要维护。
- 没有做全量性能压测：数据还是个人工具量级。
- 没有把演练做成产品里的自动化流程：演练记录模板已经有了，真做演练时照着填。
