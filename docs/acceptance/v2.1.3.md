# v2.1.3 验收清单（MVP 加固与验收）

## 怎么用

- 版本：`v2.1.3`，主题是「不新增功能，把资产管理 MVP 的迁移、备份恢复和边界行为验一遍」。
- 这一版对应 [2.0 资产管理底座计划](../v2-plan.md) 里的「加固与验收」
  （计划里写的是 `2.0.3`，按 `2.1.x` 的编号顺序落地为 `2.1.3`）。
- 状态：**挂起**。2026-09-23 产品负责人决定：先把后续功能版本做完，再统一走加固与验收；
  本文已经跑完的部分（迁移演练、备份恢复核对、边界修复）先留档，等统一加固时接着往下走。
- 能对上就在方框里打勾；每条都写依据，证据只记一处。

## 一、迁移演练

- [x] 真实本地库的副本能从旧结构升到统一资产结构，提示词逐条一致。
      依据：2026-09-23 演练。基线取自 `.data/prompts.sqlite`（升级前结构、7 条提示词），
      在 `%TEMP%\upgrade-drill\copy.sqlite` 上跑升级；比对资产标识、标题、分类、标签、
      正文哈希（sha256 前 16 位）、适用场景、创建与更新时间、垃圾箱状态，**7 条全部一致，
      没有多条也没有少条**。原始库全程没有被升级，仍是升级前结构、7 条提示词。
- [x] 升级只加新表，旧 `prompts` 表保留为只读快照，升级后的写入不进旧表。
      依据：演练库里 `prompts` 表仍是 7 行；改一次提示词标题后，旧表内容不变，
      改动只写进 `assets`，并产生第 2 条版本记录。
- [x] 迁移失败时旧提示词数据仍然完整可读。
      依据：`asset-backup-compatibility.test.mjs`。
- [x] 云端生产库结构与数据复核。
      依据：2026-09-22 只读核对线上库——资产 9 条（全是活跃提示词）、1 个默认项目、
      0 条关系、没有垃圾箱和归档残留，与 2.1.0 验收后的状态一致。
- [x] 云端每日定时任务真的在跑，清理函数可执行。
      依据：2026-09-23 只读核对 `health_checks` 表，`heartbeat` 记录的最后一次心跳是
      `2026-09-22 03:39 UTC`（对应 `0 3 * * *` 的每日任务）；当时云端没有过期版本记录、
      也没有垃圾箱资产，再用 service role 直接调用 `purge_expired_prompt_versions`
      返回 204 成功。这条结了 v1 留下的「云端清理远程执行待验证」。
- [x] 推送到 `main` 会触发 Vercel 生产部署。
      依据：2026-09-23 复核线上域名，部署标识从 `dpl_BHpG3reHnjBwzJF43NPHKqGVFofE`
      变成 `dpl_88vSUZPrAv7mSus7obnZLETGvR7r`，说明 2.1.2 之后的提交已经部署上线。
- [x] 回滚路径有效：回滚前必须先导出一份备份，切回旧代码后旧代码读的是迁移前快照。
      依据：2.1.0 已做过切换与回滚实测（见 [v2.1.0 验收清单](v2.1.0.md) 与
      [v2.1.0 交接](operations/v2.1.0-handoff.md)）；本版复核了快照表确实保留。

## 二、备份与恢复演练

- [x] v2 备份导入空库能建出项目和资产，带关系的数据也一起进来。
      依据：见 [v2.1.2 验收清单](v2.1.2.md) 第三节的两轮实测。
- [x] 导入后的资产有可读的版本记录。
      依据：2026-09-23 核对演练库 `%TEMP%\empty212d\fresh.sqlite`——导入的 5 条资产
      各有 1 条版本记录，编号从 1 开始。
- [x] 导入只新增不覆盖，同标识的资产跳过，同名项目按名称合并。
      依据：见 v2.1.2 清单；`asset-backup-v2.test.mjs` 覆盖同名合并映射。
- [x] 备份文件里写明来源包二进制不在备份内，需要另行保留原文件。
      依据：备份的 `note` 字段；界面提示同步改了措辞（v2.1.2 的修复项）。

## 三、边界行为

- [x] 关系目标被删除或归档后，详情显示「目标已归档」而不是报错。
      依据：见 [v2.1.2 验收清单](v2.1.2.md) 第三节。
- [x] 提示词不能把自己设成关系目标。
      依据：`asset-relation-targets.test.mjs`（候选列表排除正在编辑的那条）+ 浏览器实测。
- [x] 筛选目标消失后筛选自动复位，列表不会莫名变空。
      依据：本版修复 `resetMissingFilter` 并加了 2 条测试；浏览器实测——按标签
      「重启测试」筛出 1 条，把这条移入垃圾箱后，标签筛选自动回到「全部标签」，
      列表显示剩余 6 条（修复前这里会变成空列表且看不出原因）。
- [x] 资产跨项目不串数据：切换项目后列表、筛选和关系目标各自独立。
      依据：`project-workspace.test.mjs`；v2.1.2 的界面补验里也走过跨项目导入。

## 五、已知边界（不在本版处理）

1. 备份导入没有预览步骤（产品负责人已确认延后）。
2. 资产之间的联动与相互转换（规则沉淀成文档、文档拆出规则等）需要单独设计。
3. 规则编译、协作路径、图谱和 MCP 动态查询等，按计划在资产管理 MVP 稳定后再评估。

## 六、这一版省掉了什么

- 没有新增功能，也没有加自动化浏览器测试框架：边界靠定向实测 + 单元测试覆盖。
- 没有做全量性能压测（数据量还是个人工具量级），只在需要时按实际瓶颈补。
