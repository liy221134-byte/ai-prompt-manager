## 回滚验证记录

回滚路径：先用 2.1.0 导出一份提示词备份，再切回 2.0.0 代码并导入该备份。

实测过程（2026-09-21 夜）：用 2.1.0 造出 6 条活跃提示词（含 3 条示例、1 条合并结果、1 条普通提示词）和 2 条垃圾箱内容（合并来源 + 手工删除），导出备份，然后**用 main 上的 2.0.0 代码打开同一个数据库**。

| 步骤 | 结果 |
| --- | --- |
| 2.1.0 下的活跃提示词 | 6 条 |
| 2.1.0 下的垃圾箱 | 2 条（合并来源、手工删除） |
| 导出的备份包含 | 6 条活跃提示词 |
| 切回 2.0.0 代码后看到 | **0 条** |
| 导入备份后 | 新增 6 条，标题和正文与切换前一致 |

结论：回滚路径可用，但**必须先导出备份**。

切回旧代码后看到 0 条，是因为 2.1.0 把提示词写在统一资产里，旧代码只读旧的提示词表，那张表在切换后就不再写入了。这不是缺陷，是切换的必然结果；它意味着回滚不能只切代码，必须带一份备份。这条要当作回滚操作的强制步骤。

已知边界：备份只包含活跃提示词，垃圾箱里的内容不在备份文件里（这是 2.0.0 就有的行为）。所以回滚会丢掉「回滚前正处于垃圾箱」的内容。

重复实测的方法：用 2.1.0 建库并导出备份，再用任意一份 2.0.0 代码（例如 `main` 检出目录）打开同一个数据库文件并导入该备份。
