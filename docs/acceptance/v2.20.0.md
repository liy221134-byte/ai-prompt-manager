## 一、逐条挑规则

- [x] 打开一个已经被当前项目引用的规则包，成员清单下面出现「要用这个包的哪些规则」，
      每条规则一个勾选框，默认全选，右上角显示「选中 N / 共 M 条」。
      依据：`src/components/rule-pack-detail-drawer.tsx`；待第三节手工确认。
- [x] 取消勾选并保存后，项目规则列表里看不到这几条。
      依据：`tests/rule-reference.test.mjs`「引用记录里的排除清单：被排除的规则不进项目列表」。
- [x] 重新打开这个包，取消掉的那几条仍是未勾选状态，能再勾回来。
      依据：勾选状态从引用记录的排除清单反推（`detailPackReferences`）。
- [x] 一个项目的排除不影响别的项目：同一个包装进两个项目，一个排除了某条，另一个照常看得到。
      依据：`tests/rule-reference.test.mjs`「排除清单只作用于本项目的引用记录，别的项目不受影响」。
- [x] 没有勾选变化时「保存」按钮是灰的，改过之后才可点。

- [x] 装到「公共资产库」时不出现挑规则这一节（那里是复制正本，没有引用）。

      依据：副本是项目里的独立资产，公共库那份没有被写入。
- [x] 没有包来源的项目自己的规则，看不到「另存为项目规则」按钮。

## 设计偏差

1. **脱钩的纯逻辑放在 `src/lib/rule-reference.ts`**，设计里写的是 `src/lib/asset-draft.ts`。
   理由：脱钩标记的读取优先级和排序逻辑都在 `rule-reference.ts`，放一起不用来回跳；
   `asset-draft.ts` 管的是编辑器草稿，不带这种读取语义。
2. **任务 3（规则编译）没有改代码**：设计里说要在 `src/lib/rule-compile.ts` 上做改动，
   实施时读代码发现候选集按调用方传进来的引用标识计算，排除清单在
   `listProjectRulesForUse` 这一层已经生效，编译这一层不用再改一遍。
3. **脱钩副本不继承资产关系**：原关系指向公共库那份的资产标识，搬进项目是断的，
   所以副本的 `relations` 清空，需要时自己重建。设计里没写这一条。

## 四、顺带修的老 bug（写库自测发现的）

**现象**：在项目里「从公共资产库挑资产」选两条规则，提示说「带进 0 条，跳过 2 条（之前挑过）」，
项目里一条规则也没有。工程基线里「把这 12 条装进项目」同样只进了 4 条模板，8 条规则全不见。

**复现与定位**（2026-09-25，线上真实数据）：云端库里确实写了 2 条规则副本（进了公共库）
和 1 条引用记录（进了项目），但那条引用记录的 `status` 是 `pending`；
而 `listProjectReferencedPacks` 只认 `deletedAt` 为空且状态为活跃的记录，
于是项目被当成「没引用任何包」，规则自然一条都不显示，提示还把原因说成「之前挑过」。

**根因**：`buildPackReferenceAsset` 直接抄了包自己的状态。挑资产时现攒的那个包状态是
`pending`（包本身还没定稿），引用记录就跟着变成 `pending`。

**最小修复**：引用记录固定记成活跃——它表达的是「这个项目在用这个包」，
该跟项目走，不该跟包的成熟度走。顺带把那条误导提示改成
「另有 N 条没有复制（规则按引用生效，或者之前已经挑过）」。

**回归**：`tests/rule-pack-install.test.mjs` 两条——
「引用记录必须是活跃的：包本身还待确认时，也不能把项目里的引用藏起来」、
「挑进项目的规则真的能在项目里看到（端到端走一遍引用）」。

**还没修的一处**（留给下一次，需要先定做法）：挑资产时现攒的包用的是**固定标识**
`rule-pack-public-library`，所以第二次挑、以及工程基线装推荐时，那些规则既没进公共库正本、
也不在引用范围内，照样看不见。三种做法（每次挑一个独立包标识 / 引用记录里直接记引用了哪几条 /
不复制直接引用）要先拍一个，不在本版顺手改。

**2026-09-25 当天已定并做完**：产品负责人拍板走第二种——引用记录里直接记引用了哪几条。
见 [挑资产引用模型设计](../superpowers/specs/2026-09-25-v2.20.0-picked-rule-reference-design.md)。

- 挑规则进项目＝记引用：正文留在公共库，公共库不再新增同名副本。
- 读取时把点名的那些算进来，按资产标识去重；脱钩副本按来源资产标识让位。
- 脱钩放宽：从公共库直接挑进来的规则（不属于任何包）也能另存为项目规则。
- 新增 6 项测试：点名引用进列表、重复只出现一次、脱钩让位、引用记录构造、脏数据容错，
  以及「项目自己的规则不用脱钩 / 不在包里的公共规则也能脱钩」。
