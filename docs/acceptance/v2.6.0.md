## 三、边界与安全

- [x] 云端模式下「代码目录」这一栏不可用，并写明原因。
      依据：面板按 `dataMode` 判断，云端传 `supabase` 时显示「云端模式读不到你的本机目录，
      这一栏要跑在本机时才能用」并禁用。**这一条只做了代码路径确认，没有在云端域名上实机
      点过**（线上域名自测仍挂在待办里）。
- [x] 路径不对时给中文提示，不写任何资产。
      依据：单元测试「路径不对时给中文提示，不写任何数据」「给的是文件而不是目录时明确报错」；
      接口在路径为空时按 400 返回「请先填写要扫描的目录。」。
- [x] 扫描有上限，不会把磁盘扫穿。
      依据：文件数上限 3000（超了直接报错让收窄目录）、单文件超过 400 KB 只进清单不读内容、
      目录层数上限 12、符号链接不跟；超大文件那条有单元测试。
- [x] 导入不覆盖已有内容。
      依据：同编号默认跳过，只创建新节点；来源标成「导入」，
      备注写明来自哪个文件或目录（TBL-projects 备注「从 粘贴的 SQL 导入的建表语句」）。

## 五、设计偏差

详细见[设计文档第六节](../superpowers/specs/2026-09-23-v2.6.0-engineering-import-design.md)，
关键三条：

1. 外键关系改成「先记编号、落库时再判」，为了接住「第二份迁移引用第一份迁移的表」这个真实场景。
2. 列级 `references` 也当外键解析；复合外键合并成一条关系。
3. 接口节点只认有导出 HTTP 方法的 route 文件。

## 六、已知边界（不在本版）

1. 不接 MCP、不做动态查询：Agent 连接的第三件事单独一版，先出设计再动代码。
2. 只认 `CREATE TABLE`，不解析 `ALTER TABLE`、视图、函数和触发器。
3. 代码目录分析只在本机模式可用，云端模式不做。
4. 不分析 `import`／`require` 调用关系，只按目录和路由文件归类。
5. 不做增量差异界面：导入是「看不存在的就补上」，不做三方合并。
6. 导入不覆盖你已经改过的正文，要更新就自己去编辑器改。
7. 加固与验收等整个 2.0 产品做完后统一做。

## 七、这一版省掉了什么

- 没有引 SQL 解析库：自己写确定性解析器，只认建表语句，够用且不新增依赖。
- 没有连数据库读真实 Schema：只解析你给的 SQL 文本，不改你的库、也不读线上库。
- 没有做扫描粒度选择（按文件／按目录、只扫某个子目录）：先只给「一层目录一个模块节点」，
  目录太杂时靠收窄路径解决。
