# v2.23.0 验收清单（本机 MCP 自动接入，只支持 Codex）

- 状态：**已于 2026-09-30 由产品负责人签收**。

## 版本目标

让「让 AI 用上这个库」不用再手写配置：本机模式下点一下就能把 Codex 接上，
并且能验证、能撤回来。设计见
`docs/superpowers/specs/2026-09-27-v2.23.0-local-mcp-setup-design.md`。

## 做什么 / 不做什么

**做**：一个面板（看状态 / 接入 / 撤销 / 验证）；只支持 Codex；改前备份成固定的
`config.toml.bak`；只碰 `[mcp_servers.ai-prompt-manager]` 这一段；云端模式没有入口。

**不做**：不支持别的 AI 工具、不自动发现工具、不引 TOML 依赖、不改本产品的表结构。
详见设计文档第一节。

## 验收标准

1. [x] 文件里没有这一段时，计划是「新增」，生成的内容指向本仓库、不带密钥。
       依据：`tests/codex-config.test.mjs`「写进去的那一段…」与「没接入过…」。
2. [x] 已有这一段且内容一致时，计划是「不动」，写入结果与原文一模一样。
       依据：同文件「同一段内容再写一次：原样返回，不做任何改动」。
3. [x] 已有这一段但内容不同时，计划是「覆盖」，并把当前那段带出来。
       依据：同文件「内容不一致：状态是 different…」。
4. [x] 撤销时有备份就恢复备份、无备份就只删这一段；备份文件名固定是 `config.toml.bak`。
       依据：同文件路径用例 + `resolveCodexBackupPath`。
5. [x] 表在开头、中间、末尾三种位置都能定位并处理。
       依据：同文件「表在开头、中间、末尾三种位置都能删掉，别的行一行不动」。
6. [x] 处理前后，这一段之外的每一行逐字节不变。
       依据：同文件多处断言原文开头与另一张表原样保留；另有本机实测（第 7 条）。
7. [x] 本机模式下点「接入」：多出这一段、旁边生成备份、别的段没变。
       依据：2026-09-27 实测（把 `CODEX_HOME` 指向 `.data/codex-home-test/`，**没有碰真实的
       `~/.codex/config.toml`**）。测试夹具里预置了 `model`、`approval_policy` 和另一张表
       `[mcp_servers.other-tool]`；接入后这些原样保留，末尾多出接入段，并生成
       `config.toml.bak`。截图 `.data/acceptance-2026-09-27/23-02-mcp-before.png`、`23-03-mcp-after-apply.png`。
8. [x] 点「验证」：真起一次 MCP 服务、连上、列出工具并报耗时。
       依据：同日实测，面板显示「连上了，用了 1853 毫秒，看到 6 个工具」并列出
       `list_projects、search_prompts、get_asset、list_rules、list_graph_nodes、analyze_impact`。
       **6 个而不是 11 个**：自检脚本跑只读模式（`MCP_READ_ONLY=1`），只注册查询工具——
       设计文档里我写的「当前 11 个」写错了，已订正。截图 `23-04-mcp-verify.png`。
9. [x] 点「撤销」：文件回到改前的内容。
       依据：同日实测点「用备份还原」后，`config.toml` 逐字节回到预置内容，面板状态回到
       「还没有接入过」。截图 `23-05-mcp-after-revert.png`。
10. [x] 云端模式下这个入口不出现；接口也拒绝。
       依据：入口按 `dataMode === "local"` 条件插入，云端模式（`dataMode="supabase"`）不渲染。
       接口侧实测：以云模式（`npm run dev`）启动后请求 `/api/mcp-setup`，匿名访问被中间的
       登录检查拦在 **401**；登录之后会走到路由里的 `rejectLocalApiInCloudMode`，那是
       `/api/code-scan`、`/api/source-packages` 等 4 处接口共用的同一个守门函数。
       **登录态那一半没有实测**——需要云端的应用账号密码，我没有，也不该拿。
11. [x] 完整检查通过。依据：2026-09-27 `npm run check`——类型检查、542 条测试、代码检查、
       生产构建全过（本版新增 6 条测试）。

## 设计偏差

1. **验证的实现方式和设计描述不同。** 设计写的是「真的起一次 MCP stdio 连接，列出工具」；
   实现改成了**跑项目自己的自检脚本** `scripts/check-mcp.mjs`。原因：MCP 的
   `@modelcontextprotocol/sdk` 在 `package.json` 里是 **devDependency**，不该被应用路由 import；
   而那个自检脚本本来就在做同一件事（起服务、连上去、列工具、再读一遍项目和规则），
   复用它既不加依赖，也比自己写一半握手更可信。行为不变：仍然真连、仍然是只读、仍然有超时。
2. **设计文档验收标准第 8 条写错了工具数。** 我写「当前 11 个」，实际只读模式注册 6 个。
   已订正设计文档。

## 未完成事项与风险

1. 只支持 Codex。Claude Code、Cursor 的配置文件格式和路径都不一样，等真要用再单独立项。
2. 备份只留最近一次（你选的方案 A）。连续改两次之后，只能回到第二次之前，回不到更早。
3. 「验证」跑的是只读自检，证明不了写入类工具（`import_documents`、`create_asset` 等）也能用。
4. 云端模式下登录用户那条拒绝路径没有实测，见验收标准第 10 条的说明。
5. 顺带发现一处与本次无关的 lint 警告：`scripts/import-seed-content.mjs` 里 `readdirSync`
   被引入但没用到。我没动它——不在本次范围里。
