## 三之二、2026-10-28 修复的导入器缺陷

**问题**：导入器 `upsert` 的字段映射里**没有 `type`**，34 道实操题被 `practice_questions.type`
列的默认值 `'单选'` 悄悄写成单选。云端实测 `{"单选":118}`，而 YAML 是 84 + 34。

**为什么一直没发现**：此前每次导入只核对 `module_id` / `level` / `knowledge_point`，
没有核对 `type`；YAML 校验器查的是源文件本身，也看不到写库映射。**导入日志仍然报成功。**

**影响**：实操题会以单选题形态进页面，选项为空 → 无法作答；34 道 L5 实操题等于作废，
而 L5 正是「写不出来」这个病的对症层。

**修法**：
1. 字段映射抽成纯函数 `toQuestionRow(q, topicId)`，`type` 显式写出并给「单选」兜底
2. 新增 3 项单测锁死：题型不被默认值吞掉、缺题型兜底为单选、真实主题包 118 道题
   逐题比对「题型 / 知识点 / 层级 / 模块」四项映射后与源一致
3. 重新导入，云端复核 `{"单选":84,"实操":34}`，实操题选项全空、单选题选项全 ≥2

## 三之三、渲染验证的通道（2026-10-28 更新）

上一版这里写的是「内置浏览器截图恒超 10 MiB、DOM 返回空，只能靠产品负责人截图」。
2026-10-28 实测，通道已可用，且分工明确：

| 通道 | 能否验证 | 带登录态 |
| --- | --- | --- |
| Chrome 扩展（受控新标签页） | 能截图、能按 DOM 节点点击 | **带**（日常浏览器登录态） |
| chrome-devtools（CDP） | 能看 console、network、执行 JS | 同一实例则可 |
| 内置浏览器 | 能截图 | 不带 |

结论：**需要登录态的界面验证走 Chrome 扩展**，本会话的入口、目标列表、矩阵、答题
四处渲染都是这么验的（截图 + DOM 双确认，避免只截到「加载中」的中间态）。
CDP 用来抓 console 与 network —— 矩阵页那次卡「加载中」就是靠它抓到
`learning_topics?id=eq.undefined` 的 400 才定位到「新动态路由未被旧 dev server 加载」。

## 四之二、答题回写验出的一处真错：字母答案被当成全文比对

第一次答题时选对了却显示「回答错误」。原因是库里 `answer` 存在**两套口径**：

| 题库 | `answer` 存什么 | 题数 |
| --- | --- | --- |
| 早期主题（AI 提示词那批） | 选项全文 | 127 道单选 |
| 中项主题包 | 字母 `A/B/C/D` | 84 道单选 |

判分逻辑写的是 `selectedSingle === current.answer`，而 `selectedSingle` 是选项全文，
跟字母永远不相等 ⇒ **中项 84 道单选题无论选什么都判错**。

修法：新增 `src/lib/practice/answer.ts`，判分前把答案统一展开成选项全文
（单个 A—E 字母按位置取选项，其余原样返回），两批存量数据共用一套判分，不改库、不重导。
9 项单测锁死：字母展开、全文原样、实操题文本不被误当字母、越界字母不猜、
多选逐项展开、非 JSON 不抛错、同一题两种写法判分结果必须一致。

顺带补了一个缺口：原来只有多选题答错才显示「正确答案」，单选答错只能靠选项底色猜，现在两种都写出来。
