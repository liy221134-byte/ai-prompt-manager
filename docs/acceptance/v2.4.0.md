# v2.4.0 验收清单（模板中心）

## 怎么用

- 版本：`v2.4.0`，主题是「把模板变成资产，让编译产物能套自己的结构」。
- 状态：**功能与界面补验已完成，等你签字**。
- 设计见 [模板中心设计](../superpowers/specs/2026-09-23-v2.4.0-template-center-design.md)。
- 能对上就在方框里打勾；每条都写依据，证据只记一处。

## 验收记录

- 2026-09-23 由 Codex 开发并代跑，全程在**本地库副本**上执行，原始本地库没有被改动。
- 实测数据：`templates/new-project/` 的 4 个模板文件 + 种子资产包（12 条规则）。
- 界面动作：导入模板库 → 看模板详情（变量清单）→ 导入规则包 → 打开规则编译 →
  分别选 AGENTS 和 README 模板看产物变化 → 把产物保存成文档资产。
- 局限：浏览器自动化环境里文件下载被取消，「下载」按钮没有真点，草稿内容有单元测试覆盖。

## 一、模板资产

- [x] 类型筛选里有「模板」；模板能新建、编辑、查看，产物文件名和备注能存能读回。
      依据：导入后筛出「模板 4」；详情显示「产物文件名：DOCUMENT_SYSTEM.md」；
      编辑器里有「产物文件名」「备注」两个字段。
- [x] 模板详情能看到正文里解析出来的变量清单。
      依据：README 模板详情显示「模板变量（12 个）」并列出变量名；
      DOCUMENT_SYSTEM 模板没有变量，显示 0 个。
- [x] 「导入模板」一次选多个 Markdown，每个文件建一条模板资产，产物文件名默认取原文件名。
      依据：一次选 4 个文件后列表出现 4 条模板，标题是文件去扩展名（AGENTS／README／
      START_PROMPT／DOCUMENT_SYSTEM），产物文件名带扩展名。
- [x] 新项目模板库导入产品可验证：来源标成导入、正文与文件一致。
      依据：4 条模板的 `source.sourceType = import`、`originalFilename` 是原文件名；
      内容与仓库文件逐字一致（映射逻辑有单元测试）。

## 二、套模板编译

- [x] 编译面板能选模板，产物正文以模板为骨架。
      依据：选 README 模板后产物以 `# {{项目名称}}` 那份模板开头，
      标签名跟着变成 `README.md（12）`。
- [x] 能自动填的变量直接填上：项目名称、项目说明、技术栈。
      依据：产物里出现 `# 默认项目` 和 `> 现有提示词迁移后的默认归属项目。`；
      变量名写法不同（例如「一句话说明这个项目解决什么问题」）也会按关键词识别。
- [x] `{{规则集}}` 位置插入规则段落；模板里没写时追加到产物末尾并注明。
      依据：AGENTS 模板没有这个占位符，面板提示「规则段落已追加到产物末尾」，
      产物末尾出现「## 规则（由编译追加）」；带占位符的情况由单元测试覆盖。
- [x] 剩余没被填的变量原样保留，面板列出「还要你填的变量」。
      依据：README 模板下列出「谁使用这个产品、用户现在遇到什么问题…」等 9 项。
- [x] `START_PROMPT.md` 保持内置结构（不被主产物模板替换）。
      依据：选 README 模板时右侧仍是 `START_PROMPT.md（1）`。

## 三、产出去向

- [x] 套模板生成的产物能保存成文档资产，文件名取模板的产物文件名。
      依据：保存后出现标题 `README.md` 的文档资产，`metadata.role = compiled`、
      `documentType = README.md`，有版本记录。
- [x] 产物仍能复制、下载；不修改模板本身、不写外部文件。
      依据：面板上两个按钮都在；编译过程只读模板，未改动模板资产内容。

## 四、工程检查

- [x] `npm run check` 全过。
      依据：类型检查、344 项测试、lint 零问题、生产构建成功。

## 五、设计偏差

1. 变量名匹配改成按关键词识别（名字里含「名称」→ 项目名，含「一句话」或
   「解决什么问题」→ 项目目标，含「技术栈／技术选型」→ 技术栈），
   而不是死记几个变量名——仓库里的模板写法就不统一。
2. 选中的模板只套在主产物上，`START_PROMPT.md` 保持内置结构：
   开工提示的结构固定，混用两套模板反而不好判断产物是什么。
3. 产物头部统一加一行生成信息（工具版本 + 生成时间），模板正文其它部分原样保留。

## 六、已知边界（不在本版）

1. 模板不做变量类型校验，也不做「必填变量」拦截：留空就保留占位符，由人决定。
2. 不做模板市场与共享；一次装一整套模板靠多选文件。
3. 模板不参与「规则编译」以外的生成流程（例如还没有文档生成器）。
4. 加固与验收等整个 2.0 产品做完后统一做。

## 七、这一版省掉了什么

- 没有为模板单独做一套抽屉组件：模板沿用现有资产详情和编辑器，只是多了两个字段。
- 没有做模板版本升级提示：模板和别的资产一样靠版本记录回溯。
- 没有做「模板 → 提示词」的复用（模板变量规则和提示词一致，但没做互转）。
