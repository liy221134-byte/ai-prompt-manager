## 二、冲突候选与人工裁决

- [x] 冲突候选只列高置信的「可能打架」：一条「必须」和一条「禁止」，

      依据：界面显示 1 对（接口契约与数据所有权规则 × 小改动不写测试），
      重叠维度写出「作用层级：未填层级、作用范围：项目、技术上下文有交集、
      同一层级上一条「必须」一条「禁止」」；单元测试同样覆盖。
- [x] 排除之后草稿里不再出现这条规则；关掉面板再打开，裁决还在。
      依据：排除后「参与编译 12 条、已排除 1 条、冲突候选 0 对」，
      AGENTS.md 预览里搜不到该规则；重新打开面板仍是「已排除 1 条」，

- [x] 可以恢复参与。
      依据：点「恢复参与」后回到「参与编译 13 条、已排除 0 条」，

## 六、顺带修掉的真 bug

1. **编辑器保存会抹掉改不到的元数据**：可信度、编译去向、所属包和编译裁决不在编辑器的字段里，
   保存时按草稿重建元数据就会把它们丢掉——编辑一次导入的规则，「来自哪个包」就没了。
   已改成保存时把这些字段原样带回来，补了 2 条测试。

## 七、设计偏差

1. 冲突候选的口径收紧了：从「三个维度重叠」改成「方向相反 + 至少一个维度相关」。
   原因是种子包这种同质规则集里，同层级同范围会两两成对、刷出几十条噪声；
   收紧后列表短、每条都值得看。已回写进设计文档。
2. 编译裁决不在资产编辑器里编辑，只在编译面板里裁决；编辑器保存时会保留已有裁决。
3. `README.md` 不在本版产出：标了 `readme` 编译去向的规则并入 `AGENTS.md`，
   等模板中心那版再分开。

## 八、已知边界（不在本版）

1. 冲突判定只看结构信号，不做语义比对、不自动裁决。
2. 每次保存编译产物都会新建一条文档资产，不做「更新已有产物」；需要保留历史版本的话这样更安全。
3. 模板中心（自定义产物结构）、上下文图谱和 MCP 都不在本版。
4. 加固与验收（迁移演练、端到端边界测试、临时文件清理）等整个 2.0 产品做完后统一做。

## 九、这一版省掉了什么

- 没有做「按可信度自动裁剪」：候选集怎么算看得见、可改，不替你做决定。
- 没有做产物结构自定义（模板中心），先用内置结构。
- 没有做冲突裁决的历史记录，只保留每条规则上最近一次裁决。
