## 一、功能

- [x] 公共资产的「文档」页签显示为「参考文档」，并写明只放方法级参考。
      依据：本机实测。
- [x] 项目文档按 需求／规格与计划／交付／验收与发布 四段分组，空段写明这一格放什么。
      依据：`tests/document-flow.test.mjs`；本机实测。
- [x] 工程基线顶部有链路完整性检查（PRD／Spec／验收／发布记录），缺哪环给哪环入口。
      依据：`tests/document-flow.test.mjs`「链路完整性」；本机实测。
- [x] 工程基线缺某类文档时，可把已有文档标记成该类型（不重复建）。
      依据：本机实测（标记后缺口立即变成「已有」）。
- [x] 项目图谱可批量把一份文档挂到多个节点上，已挂过的跳过。
      依据：本机实测（7 份文档 → 9 个节点，重复挂会提示"已经挂过"）。
- [x] 节点影响分析三层都有内容：指向谁、谁指向它、间接影响（通过谁串起来）。
      依据：本机 MCP `analyze_impact`（`MOD-src/lib/server`：2 / 1 / 1）。
- [x] 导入工程新增「项目文档」：原样导入 Markdown，不走 AI，同名默认不导入。
      依据：`tests/document-import.test.mjs`；本机实测导入 7 份。
- [x] 技术档案可复制提示词（含项目名、项目说明、已有技术栈）。
      依据：`tests/tech-profile-prompt.test.mjs`。
- [x] `implementation-spec.md` 进模板门禁（10 份工程模板）。
      依据：`tests/engineering-templates.test.mjs`。
- [x] 本机 MCP 自检命令可用：`npm run mcp:check`（可加 `-- --node <编号>` 看某个节点）。
      依据：本机实测输出。
- [x] 文档与模板归位：文档里 `documentType=模板` 归零，模板资产 9 条（含新导入的 Spec 模板 10 条）。
      依据：本机与云端各核对一次；记录见 `docs/operations/database-migrations.md`。

## 设计偏差

1. `v2.12.0` 与 `v2.13.0` 合并为一次上线（v2.12.0 未单独发布）。
2. 文档/模板归位实际影响 **5 条**资产（原评估 2 条，其余是同一批内容装到别的项目时的副本）。
3. 「打包成规则包」入口放在公共资产视图的「更多」里（设计里写的是项目视图）。

- 移动端未专门适配；本地专属能力仍只有两项（分析代码目录、MCP）。

- 云端私有桶里可能残留取消导入时已上传的原文（未实现放弃时的清理），下一轮补。
