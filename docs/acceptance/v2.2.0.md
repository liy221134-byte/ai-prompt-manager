- [x] 一个项目能安装多个包（结构上支持），安装后能按包筛选，只显示这个包带来的资产。

## 五、开发过程中修掉的真 bug（都不属于本版新功能）

1. **技术档案的编辑入口拿不到资产**：`isEditableAssetData` 只认规则和文档，
   2.1.2 把技术档案加进可编辑类型时没同步，第二次点「技术档案」会打开空编辑器、
   保存报错。已改成按可编辑类型列表判断，补了测试。
2. **种子包附属文档缺包内编号**：画像和验证记录没有 front-matter 编号，
   包内编号落成空字符串，安装时会被判成「没有包链接」而跳过（实测少 7 份验证记录）。
   已用解析出来的稳定编号兜底。
3. **安装计数把同一个编号算多次**：成员装在两个项目后，再装第三个项目时会把
   同一个包内编号数成两条。已按包内编号去重，并优先取包所在项目那份。
4. **按包筛选时停在「提示词」标签会看到空列表**：提示词不属于任何包，
   现在选包会自动切到「全部」标签（和切项目时的处理一致）。

## 六、设计偏差

1. 包的状态直接用资产自带的 `status`，没有单独存 `packStatus` 字段（避免两处数据打架）。
2. 成员清单不单独存一份，包详情按成员的包链接反查（个人工具的数据量够用）。
3. 导入的成员统一落成「活跃」：安装包是用户主动采纳，验证程度由「可信度」标注，
   种子包里的 `status: candidate` 原文保留在成员正文里。
4. 种子包的 `layer`（项目／模块／功能／文件／数据）和产品的「作用层级」
   （全局／模块／任务／代码）取值不同，只映射同义的 `module`，其余留空、原文保留。

## 七、已知边界（不在本版）

1. 规则冲突检测与人工裁决、编译产出 `AGENTS.md`（下一版与规则编译一起设计）。
2. 规则包的市场、共享、多人协作不在计划内。
3. 备份导入仍然没有预览步骤（沿用 2.1.2 的决定）。

## 八、这一版省掉了什么

- 没有给规则包做手工编辑器：包由导入和打包生成，包内资产各自在正常编辑器里改。
- 没有为种子包单独写一套导入入口：种子包先生成规则包文件，走和别的包一样的导入路径。
- 没有做包之间的依赖与升级提醒（包版本只记录，不比较）。
