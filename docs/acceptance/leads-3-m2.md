## 验收标准

1. **台账读库**：`/external-sources` 的行数 = 库内「采集记录」文档资产条数（迁移后应为 README 原有 23 条）。
2. **新建落库**：点「新建采集」填完保存，视图立刻出现该行；刷新后仍在（不是前端假数据）。
3. **字段一致**：点任意一行，抽屉字段与库内记录逐字段一致；落点若为库内资产，抽屉里能打开该资产详情。
4. **档位措辞**：六档「是否编译」正确标注，且候选档措辞已是「已进编译候选（待确认发布）」。
5. **走完全程**：一条真实外部技能的候选资产经人工确认升 `active` 后，出现在规则编译抽屉候选集里，
   台账对应行的档位变为「已进编译候选」。**每一步都有人工确认点**（无自动升档）。
6. **合规新判据**：`npm run check:leads3-compliance` 在新判据（`active` 须有确认记录）下扫全库 0 违规；
   人为构造一条「`active` 且无确认记录」的规则能被抓出来。
7. **迁移幂等**：迁移脚本连跑两次，第二次 0 新增；`--dry-run` 不写库。
8. **生态筛选**：按生态筛出的行数与登记录数一致；「全部」档不丢行。
9. **边界**：记录缺字段时视图显示「—」不崩；采集记录为 0 条时显示空态提示而非报错。
10. **真在浏览器看到渲染**：本地模式与云端模式各看一遍，不是只跑测试。
11. **全量检查**：`npm run check:fast` 全过（基线见下）；`npm run lint` 0 error
    （它是线上构建的门，见下面「lint 这一关」）。

## 已知限制

- **云端模式未在浏览器验证（第 10 条部分未验）**：M2.0 的写入范围按设计稿第七节第 5 条只含本机库，
  云端数据尚未推送，因此云端模式的浏览器实测留到 `npm run sync` 推送时一并做。本地模式已充分验证（截图见下）。
  这一条记入 `docs/pending-items.md`。
- **落点指向的资产若不在库内，显示原文不跳转**：与 M1 同口径——落点写的是种子包规则 ID 或模板路径时，
  按判定规则显示「未导入库」或「已进模板/规则层」且不跳转，属数据现状非缺陷。
- **「是否编译」仍是按库内资产状态的推导**：不解析 `AGENTS.md` 正文做精确比对（精确比对留到后续版本）。
  六档含空档（`empty`），空档显示「—（未提炼资产）」。
- **第四约束只对规则资产判**：文档没有「发布」语义（采集记录一登记即为 `active`），采集记录的确认状态
  改在视图「人工确认」一行显示，不进违规判定。原因见设计稿第十二节第 2 条。
- **构建环境**：`npm run build` 在本工作环境跑不起来（工作区 `node_modules` 是指向项目根之外的符号链接，
  Turbopack 拒绝；主检出受批量删除守卫限制），非代码问题。本次改动未改变既有构建产物结构，
  类型检查与全量测试已覆盖。生产构建须在 WorkBuddy 之外的普通终端跑。

## 实测记录（2026-09-29，实施方自测）

- `npm run check:fast`：类型检查通过；**575/575 测试通过，0 失败**
  （M1 基线 564，本轮退役 M1 快照类断言、新增记录解析与派生、生态筛选、确认记录判据等，计 575）。
- **lint 这一关（本轮特意跑的，M1 栽过这里）**：`npm run lint` → **0 error、3 warning**
  （3 条都是既有脚本的历史 warning，非本轮引入）。
  过程中发现并修掉一个会让线上部署失败的 error：`external-sources-ledger-view.tsx` 的加载 effect
  在函数体里同步调 `setIsLoading(true)`，触发 `react-hooks/set-state-in-effect`。这条规则正是
  **M1 那次线上部署失败的同一条**（`vercel.json` 的 `buildCommand = npm run check` 里含代码检查，
  lint 退出码 1 → 部署 failure）。修法沿用 M1 那次的思路：把整段加载从微任务起步，setState 不再
  落在 effect 体的同步路径上；行为不变（首帧仍是加载态，读到的数据与错误处理一致）。
  另删掉一处重写后残留的未使用函数 `isSeparatorRow`（分隔行本来由 `tableLines.slice(2)` 跳过）。
- `npm run import:leads3-records --dry-run`：解析 README 第六节 23 条来源，S7 行匹配到 9 个库内文档，
  不写库。
- `npm run import:leads3-records`：**新增 23**；立即重跑 → **新增 0、跳过 23**（幂等成立）。
- `npm run check:leads3-compliance`：扫描外部来源资产 32 条，**0 违规**，退出码 0。
