## 一、原大纲核心：6 周进阶路径

| 阶段 | 主题 | 核心目标 | 产出 |
| --- | --- | --- | --- |
| 第 1-2 周 | 技术素养打底 | 能看懂代码在干嘛、判断复杂度 | 自己项目的"代码地图" |
| 第 2-3 周 | LLM 与上下文认知 | 理解 Agent 为什么听话/不听话 | 一份《上下文成本账本》 |

## 二、技术素养打底（知识点，对应题库"Web/数据库/终端/代码常识"）

- API 是什么（前端/服务员/后厨类比）
- 前后端怎么交互（请求 → 后端 → 查库 → 返回 → 渲染）
- 数据库基本概念（表/字段/主键/外键/查询/表设计）
- 代码长什么样（函数/类/变量名猜功能）
- 终端基本操作（cd/ls/跑测试/看报错）

> 豆包特别提到"前五课"已讲：API 概念、GET 与 POST 区别、常见状态码、URL 结构拆解、浏览器请求携带信息与安全问题、数据库表设计。

## 三、LLM 与上下文认知（对应题库"AI 编码基础"）

- 大模型怎么工作：**预测下一个词**，不是推理 → 会自信地编（幻觉根源）
- 上下文窗口是什么（token 上限，塞满会忘事）
- Token 是什么（1 汉字 ≈ 1.5–2 token；规则过长费钱又失效）
- 注意力机制（越靠后越关注，重要规则放开头/结尾）
- Prompt 不是咒语（目标 + 上下文 + 验收标准）

## 四、AI Coding 方法论（对应题库"AI Coding 方法论"）

- Spec 驱动开发（先写规格再实现）
- 规则文件（AGENTS.md / CLAUDE.md，具体可验证）
- 验证闭环（写 → 跑 → 看 → 改，循环到通过）
- 上下文工程（恰当且适量，而非越多越好）

## 五、工程化这一半（原路径缺的，对应题库"工程化与质量保障"）

> 豆包明确：原路径只覆盖"让 Agent 听话"那半；生产级项目另一半是"让系统不出事"。

- 测试（单元/集成、回归保护）
- CI / CD（提交即构建测试、通过后自动部署）
- 监控与日志（上线后掌握真实情况、出事能定位）
- 错误处理（优雅降级，不白屏崩溃）
- 安全（密钥不进仓库、防注入）

## 七、第三批：豆包大纲未覆盖的学习点（新增）

豆包 6 周路径面向“会写需求、不懂代码”的产品经理，覆盖了技术素养、LLM 认知、AI Coding 方法论、工程化四块；但作为 2026 年的 aicoding 从业者，还缺一批现代必懂的概念。第三批 53 题补齐：

- **数据与前端底座**：JSON 与数据类型、HTML/CSS/JS 三件套与 DOM、库/框架/SDK 的区别
- **运行与交付**：服务器、域名、DNS、本地 vs 云端部署
- **现代 AI 应用核心**：Embedding 与向量检索、RAG（检索增强生成）、AI Agent 与 Function Calling/MCP
- **用 AI 的性价比与边界**：模型选型与成本（微调 vs 提示、token 计费）、Prompt 进阶（few-shot/CoT/角色/负面约束）、AI 安全与伦理（隐私/数据出境/版权/幻觉治理）
- **工程基本功**：缓存与性能（cache/CDN）、AI 评测与基准、系统化调试、产品与 AI 协作（场景/MVP/原型）

> 配套机制：练习应用已支持「错题重练 / 同类随机再抽 / 重做本题」，配合上述成组题目，可反复验证直到“学会”。
