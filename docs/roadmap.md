## 当前：v4 学习系统（2026-10-27 开工）

主题：把一次性对话产出的学习计划，变成每天能执行、可追踪、能复测的系统。
首个真实主题是**软考中级·系统集成（中项）**，目标 2027-05-22 两科同次 ≥45 分。
范围与成功标准见 [PRD](requirements/v4-learning-system-prd.md)，路线评估与排期见
[v4 全线规划](learning/v4-plan.md)。

| 版本 | 主题 | 状态 |
| --- | --- | --- |
| M0 | 数据地基：schema + 补字段 + 4 表 + 导入器 | **已完成**（2026-10-28，真库已验） |
| M0.5 | 首次离线诊断 + 主题包校准（非产品功能） | **已完成**（2026-10-27 出结果，主题包升 v1.1） |
| M1 | 导入 + 按（内容模块 × 能力层级）出题 + 节点倒计时 | **已完成**（2026-10-28，验收项全过） |
| M2 | 多学习目标：目标与主题分表、阶梯定义随主题走、入口提为子系统级 | **已完成**（2026-10-28，真库与浏览器均已验） |
| M2.5 | 今日计划：按主攻目标、剩余天数、已投入算「今天动哪块、做几道」 | **已完成**（2026-10-28，验收项全过） |
| M3 | 知识点讲义：矩阵页 / 练习页 / 今日计划三个入口都能读到「这块到底在讲什么」 | **已完成**（2026-10-28，浏览器实测三入口） |
| M4 | 诊断闭环 | 设计待出 |
| M5 | 自适应出题 + 一页素材表 | 待 M4 |
| M6 | 手绘知识图谱检查 | 待 M5 |

> **M2 是插进来的**，所以原 M2/M3/M4（诊断闭环 / 自适应 / 知识图谱）顺移为 M4/M5/M6。
> 插在诊断之前是有理由的：诊断要判「你在第几层」，前提是层级名字与判据已经随主题定义好；
> 阶梯还硬编码在组件里的时候做诊断，等于把考试型的五层套到所有目标上。
>
> **M2.5 不是新里程碑，是 M2 的补齐**：M2 验收时「今日计划」被明确记为不做，
> 理由写着「没有今日计划，`weekly_hours` / `target_date` 填了也不产生任何可见效果」。
> M2.5 把这两个字段和「今天做几道」一起上了。
> 它顺带给出了第一个可执行结论：按每周 10 小时，中项到 2027-05-22 差 81 小时，
> 要赶上得每周约 13 小时。
>
> **讲义（M3）也插在诊断之前**，理由与 M2 同类：到 M2.5 为止系统能说清「今天做哪几道题」，
> 却答不了「这个概念到底在讲什么」。380 小时配 118 道题，一天 3 道 40 天刷完，
> 剩下 160 天空着——缺的是内容，不是功能。诊断判完层级之后，需要补的那一端同样是讲义，
> 所以它必须排在诊断之前。
