# 8 周路线图

## 第 1 周：项目基础与静态卡片

- 初始化 Git
- 建立项目规则和产品文档
- 建立 Next.js、TypeScript 和 Tailwind CSS 项目
- 按最终字段结构展示 3 张静态提示词卡片
- 完成桌面端和移动端验收
- 发布版本标签 `v0.1.0`

## 第 2 周：本地提示词管理

- 新增、编辑、删除提示词
- Markdown 编辑和预览
- 变量识别
- 本地浏览器持久化

## 第 3 周：数据安全与迁移层

- 导出全部提示词为带版本号的 JSON 备份
- 检查备份文件格式并阻止无效数据写入
- 导入前预览新增、更新和跳过结果
- 冲突时保留更新时间较新的版本
- 导入时只合并，不删除本机已有提示词
- 记录最近一次备份时间
- 为备份格式、冲突和合并逻辑建立自动化测试

## 第 4 周：本机共享数据库

- 使用本机 SQLite 保存提示词
- 本机 API 提供读取、新增、更新、删除和合并能力
- 不同浏览器共享同一份数据
- 旧 `localStorage` 数据迁移前显示合并预览
- 服务器重启后验证数据持久化
- 数据库文件从 Git 中排除

## 第 5 周：AI 采集能力

- 粘贴原文
- AI 识别正文结构
- 生成分类、标签和适用场景建议
- 用户确认后保存

## 第 6 周：AI 合并与垃圾箱

- 选择 2 至 5 条提示词进行 AI 合并
- 第一条选中项默认为目标，保存前可调整，并支持可选合并要求
- AI 生成可编辑草稿和合并说明，用户确认后原子保存
- 目标旧内容保存为恢复快照，其他来源进入垃圾箱
- 垃圾箱支持恢复、永久删除和清空，默认保留 30 天
- 单条提示词的独立 AI 标签优化继续延后
- 仅提供合并恢复快照，完整版本历史和差异查看延后

## 第 7 周：生产加固

- 自动化测试和错误处理
- 数据备份和恢复
- 安全检查和访问保护
- 云端配置错误时安全关闭
- 固定 Node.js 版本和构建门禁
- 明确数据库迁移、部署和回滚顺序
- 隔离 Preview 与 Production 的环境变量
- 记录架构、请求链路和数据流
- 日志和基础监控

## 第 8 周：发布准备

- 完成第 8 周验收清单
- 以远程 Supabase 迁移和顾问验证作为发布门禁
- 通过发布门禁后完成生产验证
- 验证回滚和恢复流程
- 发布说明和复盘

## 8 周后：工程能力训练

产品功能完成后，使用当前项目进行受控的生产故障演练，学习架构、安全、备份、
发布、回滚、可观察性和成本边界。演练与产品功能开发分开管理，详见
[工程能力学习计划](learning/engineering-readiness.md)。

## 后续迭代

### v0.9.0：提示词 AI 优化（已完成）

- 元数据与正文结构优化，只做整理规范化，不改变原意
- 优化前后差异对比、变量变化清单
- 保存前预览确认，保留优化前快照，30 天内可以回退

### v0.9.1：变量管理（已排定）

来源：v0.9.0 设计讨论中发现的真实场景。AI 采集时可能识别出牵强或多余的变量，
目前只能在正文里逐个手工清理，成本高而且容易漏。

- 采集预览中增加「识别到的变量」清单，可以逐个删除或改名
- 已有提示词提供变量清理入口，删除变量时同步把句子改通顺
- 与 v0.9.0 的「允许调整变量」共用同一套变量校验规则

### 更后面（未排期）

- 分类与标签管理
- 最近使用与使用次数排序
- 统一版本历史：把合并记录和优化记录合并成一个列表
- 真实浏览器端到端测试与 CI 门禁
