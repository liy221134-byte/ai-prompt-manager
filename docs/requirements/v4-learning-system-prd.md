## 一、要解决的问题和给谁用

**问题**：备考需要连续 207 天、约 380 小时的执行，而现在的工具只解决「练得多」。

- 现有 `/practice` 是「固定题库 + 答题记录」：**135 题、27 个分类**、按分类筛、能看错题。
  （135 = 127 条种子题 + 8 道样例题，`docs/operations/database-migrations.md` 2026-09-29 已记；
  需求草案里的「119」是 grep 数法漏算，已作废；「127」是加样例题之前的数。2026-10-27 云端复核确认为 135。）
- 它**不能诊断**——不知道我在哪块知识、哪个能力层级上卡住，所以每次练习都是均匀用力。
- 它**不承载计划**——380 小时怎么分配、这周该学到哪、学到什么程度算过关，全靠人脑记。
- 后果：练了很多题，但「会的还是会、不会的还是不会」，207 天后大概率裸考。

**谁承受这个问题**：我自己。个人使用，单用户，不做团队协作。

**不解决会怎样**：
1. 380 小时没有落点，靠会话 + 手记撑不住 207 天，中途必断。
2. 能力缺口不可见，会把 130 小时砸在已经会的地方，或反过来在最需要练的地方只过一遍。
3. **报名窗口 2027-03 下旬，山东无补报——错过等一年，这是唯一不可挽回的失败点**，现在完全没覆盖。

## 二、这次做什么

按功能列，每条都对标第四节的成功标准：

1. **一个主题 = 一份计划文件**：AI 出 yaml 主题包，产品导入、执行、追踪、回流，产品不生成计划。
2. **内容模块 × 能力层级二维模型**：6 个内容模块（教材 18 章归并）× L1—L5 五层能力，是所有出题和诊断的坐标系。
3. **按层出题**：同一个知识点能取 L1—L5 不同难度的题，层级由数据决定，不由人当场挑。
4. **入学诊断**：一次覆盖全部模块的测试，输出「模块 × 层级」矩阵，指出卡在哪一层，不是给一个总分。
5. **连续拷问**：答对就升层，答错就降层并指出缺哪个知识点，一直考到答不上来。
6. **一页素材表**：每个模块学完，压缩成一页（定义 / 核心概念 / 例子 / 常见错 / 检查清单 / 5 个自测题）。
7. **手绘知识图谱检查**：我自己画，拍照上传，AI 只指出遗漏和层级错位，不替我生成。
8. **全旅程节点**：报名 / 缴费 / 准考证 / 模拟 / 查分，在主题页可见倒计时。

## 三、明确不做什么（非目标）

1. **不做 LMS**：不做课程管理、排课、学分、进度条装饰、证书。
2. **不做多用户**：不做出题人/学生角色、不做分享、不做社区题库、不做导入他人计划。
3. **不让 AI 自动生成整卷**：M3 的自适应出题是「一题一题追着问」，不是「一键出 100 题」。批量生成的题质量必崩。
4. **不做通知系统**：节点提醒靠手机日历兜底，产品只做「打开时看得见倒计时」。
5. **不做移动端适配**：本机与桌面浏览器使用。
6. **不做通用学习平台**：中项是第一个主题，也是 v4 唯一的主题，不抽象多主题并存。
7. **不做 AI 代替我思考**：素材表和知识图谱都必须先出自我，AI 只做检查与补漏。

## 四、成功标准（写成能验证的现象）

1. **模型建立**：主题页能显示 6 模块 × 5 层矩阵，点任一格直接进对应层练习（一次手工验证）。
2. **题库覆盖**：`select module, level, count(*) ... group by 1,2` 结果里**无空格**，即 145 个格子每格 ≥1 题。
3. **诊断有效**：M2 上线后跑一次入学诊断，能产出矩阵并给出「卡在哪一层」的结论；同一套题复测，层级变化可对比。
4. **计划被执行**：从 2026-10-27 到 2027-05-22，**380 小时的计划执行率 ≥80%**（每周记录，这是产品的真成功标准，不是功能上线）。
5. **报名不漏**：2027-03 之前，主题页能看到报名窗口倒计时；窗口开启当周有可见提示。
6. **不回归**：现有 `/practice` 的分类 / 题型 / 状态筛选、错题重练、随机练习全部照常。

## 六、里程碑（口径：v4 是产品线版本号，M0—M4 是线内里程碑）

| 版本 | 一句话 | 界面上能看到什么 |
| --- | --- | --- |
| M0 | 数据地基：schema + 补字段 + 4 表 + 导入器 | 无变化，只有查询结果 |
| M0.5 | 首次诊断 + 校准（离线卷子，非产品功能） | 一份诊断矩阵，不是产品页面 |
| M1 | 导入 + 按（模块 × 层级）出题 + 节点倒计时 | 选主题、看矩阵、分层刷题 |
| M2 | 诊断闭环（举证 → AI 归因 → 人确认 → 复测） | 做入学测、看进步 |
| M3 | 自适应出题 + 一页素材表 | 系统追着问；学完出一页纸 |
| M4 | 手绘知识图谱检查 | 拍照上传，AI 指遗漏 |

**顺序理由**（一句话）：产品功能先「跑」（M1）再「诊」（M2），因为归因要有作答数据；
但**学习动作必须「先测再学」**，所以第一次诊断用 M0.5 的离线卷子提前做掉，不占产品工期。
