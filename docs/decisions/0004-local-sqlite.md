# 本机 SQLite 决策

## 决策

使用 Node.js 内置 SQLite 和本机 Next.js API 保存提示词。数据库默认位于 `.data/prompts.sqlite`，从 Git 中排除。

## 原因

- 当前产品是个人使用，不需要云服务和用户系统。
- 同一台电脑上的不同浏览器需要共享同一份数据。
- SQLite 无需单独安装数据库服务器。
- 数据文件保存在本机，不主动上传到第三方。
- 数据库结构和访问集中在服务端，便于后续迁移到 PostgreSQL。

## 数据流

```text
本地 Chrome ─┐
             ├─> 本机 Next.js API ─> SQLite
Codex 浏览器 ─┘
```

## 迁移规则

1. 页面启动时读取共享数据库。
2. 如果浏览器中存在数据库没有的旧数据，显示迁移确认。
3. 迁移使用提示词标识和更新时间合并。
4. 迁移不会删除数据库和其他浏览器中的现有数据。
5. 数据库写入成功后才更新页面状态。
6. 浏览器缓存写入失败不影响已经成功的数据库操作。

## 当前限制

- 数据库只服务本机，不是云数据库。
- 应用服务未启动时不能读取或修改数据。
- 当前没有访问密码，不应把开发服务器直接暴露到公网。
- Node.js 内置 SQLite 当前会显示实验性功能警告。
- 后续正式部署云端前，应迁移到 PostgreSQL 并增加访问保护。
