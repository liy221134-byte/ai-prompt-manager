# 技术选型

## 决策

采用 Next.js App Router、TypeScript、Tailwind CSS 和 Lucide React。数据库和登录能力延后到对应阶段，暂不创建外部服务。

## 原因

- Next.js 可以在同一个项目中承载页面和后续接口，避免第 2、3 周发生整体重写。
- TypeScript 为提示词数据结构提供稳定约束，降低后续数据库迁移成本。
- Tailwind CSS 适合快速实现响应式卡片页面。
- Lucide React 提供一致且可访问的图标。
- 当前产品是个人工具，暂时不引入用户系统和数据库，可以先验证核心使用流程。

## 暂不采用

- 纯 `index.html`：扩展搜索和动态数据时需要整体改造。
- 同时维护前后端两个仓库：个人项目初期管理成本过高。
- 立即引入完整组件库：第一周没有表单和复杂弹窗，按需增加即可。
- 立即引入用户系统：目前没有多设备或多人协作需求。

## 后续数据库建议

确认需要持久化和多设备访问时，优先评估托管 PostgreSQL。数据模型保持数据库无关，避免过早绑定具体平台。
