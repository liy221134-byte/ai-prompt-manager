# 采集任务怎么回流到采集台账

> 写给产品负责人：采集任务不是「跑完就完了」，产出件要经过一条固定通道回到产品里。
> 这份文档对着**代码现状**写，不是设计稿复述；实测那一段是真跑出来的。

## 一、一句话答案

**产出件必须走「给压缩包」这个入口回来。**

「生成采集任务单」只负责把话术给你——产品不联网、不直连智能体、也读不到智能体的输出。
采完的候选资产想进台账，唯一的通道是：**把产出件交回产品 → 产品用 AI 再提炼一遍 → 确认落库**；
落库时**产品自动生成采集记录**并指向这批新资产，台账随即多一行。

```
① 台账「生成采集任务单」 ──填来源/生态/关注点──▶ 话术
                                                │  复制，扔给智能体
                                                ▼
② 智能体读仓库 ──▶ 产出件（一个 .md，或几个 .md 打成 .zip）
                                                │
                                                ▼
③ 台账「给压缩包（外部采集）」 ──上传──▶ AI 提炼 ──▶ 确认
                                                │
                                                ▼
④ 落库：候选资产（规则=draft+假设级+来源摘录，进公共库）
         + 自动生成 1 条采集记录（处置=已采，落点指向这批资产）
                                                │
                                                ▼
⑤ 台账多一行；「落点」可点进去看这批候选资产
```

## 二、在界面上怎么走（三步）

前提：已登录，能打开「采集台账」页（本地 dev 是 `http://localhost:3000/external-sources`，线上是同一路径）。

1. **要话术**：点「生成采集任务单」→ 填「目标来源」（必填，仓库地址或包名）、生态（可选）、关注点（可选）→ 点「生成话术」→ 点「复制话术」。把话术整段粘给智能体。
2. **拿产出件**：智能体按话术产出候选清单后，**存成一个 `.md`**（内容多就拆几个 `.md`，再打成一个 `.zip`）。
3. **交回来**：点「给压缩包」→ 上传那个 `.md`/`.zip` → 等 AI 识别出候选清单（可勾掉不要的、可改类型）→ 填「这条来源是谁」（+ 生态）→ 点确认。

确认后弹层关闭、台账刷新，顶部提示「已从压缩包采集，采集记录与候选资产都已落在公共库」。

## 三、产出件写成什么样

**推荐：一段候选清单，一条一个小标题，每条写清「是什么规则、来源在哪、什么时候不适用」。**

好的形态（实测能干净提炼成 3 条规则）：

```markdown
## 候选 1：写文件内容一律走文件编辑工具，禁用终端 heredoc 与重定向

- 规则类型：禁止
- 适用项目规模：个人 / 中型 / 大型
- 优先级：p1
- 来源：instructions/no-heredoc.instructions.md
- 不适用场景：装包、构建、跑测试、git 操作仍然走终端。
- 正文要点：……
```

**三条不要做的**（都是实测踩出来的，见第五节）：

- **不要把「去重说明」「未采纳项」「采集过程记录」写进同一个文件**——实测里这段被 AI 单独提炼成了一条 `document` 垃圾资产。这些内容要么删掉，要么单独放另一个文件、不上传。
- **不用写成「资产文件」**——话术第四段现在写「写成资产文件，status: candidate、confidence: hypothesis，填好 source_references」，**目前是白写的**：产品不读产出件的 frontmatter，规则的可信度、来源摘录由产品按自己的规则落。写清楚正文比写对 frontmatter 重要。
- **不要写「已登记采集台账」**——话术现在让智能体在台账里登记这条来源，**它做不到**（智能体没有产品库的写权限）。采集记录由产品在落库时自动生成。这句话留着会让智能体编一堆假登记结果给你。

## 四、产品收到后，落库规则是什么

| 项目 | 落成什么 |
| --- | --- |
| 项目归属 | **固定公共资产库**（`default-project`）。外部采集模式不看客户端传的项目选择。 |
| 规则资产 | `status: draft`（不进活跃列表）、`confidence: hypothesis`（假设级）、`sourceExcerpt` = 正文前 200 字。这三样是强制的，不看 AI 怎么说。 |
| 非规则资产（document / prompt） | `status: active`。 |
| 来源包资产 | 每个上传文件留一条只读记录（原文件名、字节数、存放路径），正文不进资产内容。 |
| **采集记录** | **自动新增 1 条**：标题 = 你填的「这条来源是谁」，生态 = 你选的，处置 = 「已采」，落点 = 指向这一批全部新资产。 |
| 版本记录 | 每个资产留第 1 版，变更是「导入文档包」；采集记录那条写「外部采集」。 |

注意：**一次弹层会话 = 一批**。同一来源采两次、落两批，会生成**两条**采集记录（不做来源级去重）。
想避免重复，第二次就别重复导；已经导错了就去台账里把那条删掉。

## 五、实测记录（2026-09-30）

**跑的什么**：拿 `github/awesome-copilot` 的三份真实 instructions 文件（`no-heredoc`、`self-explanatory-code-commenting`、`update-docs-on-code-change`）当作采集目标，自己扮演那个「被扔了话术的智能体」，产出一份候选清单 `.md`，然后**走第三节那条通道的服务端全链路**（存原始件 → 真实 AI 服务提炼 → 算落库计划 → 写库 → 回读）。

**没跑的什么**：HTTP 与浏览器点击那一段没跑（你本机 3000 端口的 dev 在跑着，Next 16 不允许同一项目起第二个 dev；换独立工作区跑 dev 成本不划算）。好在「上传 → 提炼 → 确认」这段界面链路 M2.1 已经用 8 张截图验过（见 `acceptance/leads-3-m2-1.md`），这次补的是**产出件格式是否吃得下、AI 提炼是否靠谱**。

**结果**：

```
【实验前】测试库 317 条（采集记录 23、规则 71）
【2/4】deepseek-flash，10.3 秒，提炼出 4 条（3 条 rule + 1 条 document）
【3/4】5 条待创建资产，全部 projectId=default-project
        3 条规则：status=draft、confidence=hypothesis、来源摘录 200 字 ✓
        document 那条：status=active
【4/4】写库成功：来源包 1、资产 5
【实验后】323 条（采集记录 24、规则 74）
【回读核对】新增采集记录 collection-batch-…：生态=开源社区、处置=已采、落点指向 4 条新资产 ✓
```

**环境**：隔离测试库 `E:/codeX-collect-test/.data/prompts.sqlite`（E 盘主库的一致性快照），跑完不影响主库与云端。原始上传件落在同一数据目录的 `source-packages/` 下。

## 六、三个发现与建议

### 发现 1（要改）：话术第四段有两句「做不到 / 没用」的指令

- 「在采集台账登记这条来源，处置结论填『已采』」→ **智能体做不到**，采集记录本来就由产品自动生成。
- 「写成资产文件，status: candidate、confidence: hypothesis，填好 source_references」→ **产品不读**，三样都由产品按自己的规则落。

**建议改成**：明确告诉智能体「你的交付物是一份候选清单 markdown，交回给我导入；采集记录由产品自动登记，你不用管元数据」。

### 发现 2（要改）：产出件里的元信息会被当成正文资产

实测中，「去重说明 / 未采纳项」那段被提炼成了一条 `document` 资产。**建议在话术里加一句**：只输出候选条目本身，不要写采集过程、去重说明、未采纳项。

### 发现 3（登记，暂不动）：产出件的来源信息接不进来

智能体产出里写的 `source_references`（具体到哪个 SKILL.md）**没有通道进产品**——落库后资产只有 `sourceExcerpt`（正文前 200 字）和来源包文件名。想追「这条规则出自哪个文件」，目前只能靠来源摘录里带没带。
真要解决，属于改数据模型（给 rule metadata 加 `sourceReferences`），**不建议现在做**——先看你在真实采集里是否真的会去追这个。
