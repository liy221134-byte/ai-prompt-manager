# 规则包格式说明

## 用途

这份文档说清三件事：规则包是什么、文件里必须有什么、校验是怎么卡住的。
它是产品里「导入规则包」面板那份说明的完整版；面板上还有「下载示例规则包」，
下载下来的文件就是按这份格式生成的，可以直接导回去对照。

## 是什么，不是什么

- 规则包 = **一组规则和文档**的可搬运文件，装进项目后按包内编号去重，只新增不覆盖。
- 规则包**不是**数据备份。数据备份是整库快照（项目 + 各类资产 + 关系），
  要用「数据管理 → 导入备份」恢复，不能当规则包导入。

## 文件结构

顶层三个字段加两块内容：

| 字段 | 说明 |
| --- | --- |
| `type` | 固定为 `ai-prompt-manager-rule-pack`，认的就是它 |
| `version` | 当前为 `1`，版本对不上会提示升级产品 |
| `exportedAt` | 导出时间（ISO 时间字符串） |
| `note` | 一句说明，可省略 |
| `pack` | 包信息：`id`、`title`、`summary`、`content`、`status`，以及 `metadata` 里的包版本、可信度、适用规模、来源说明 |
| `members` | 成员清单：每条含 `id`、`assetType`、`title`、`summary`、`content`、`status`、`metadata` |

成员要在装进项目时被正确识别，它的 `metadata.pack` 里必须有包内编号：

```json
{
  "pack": {
    "packId": "rule-pack-sample",
    "packItemId": "RULE-SAMPLE-001",
    "packVersion": "0.1.0",
    "packAssetType": "rule",
    "projectScale": ["personal"]
  }
}
```

少了 `packItemId` 的成员会被跳过——这正是早期种子包里附属文档整批装不上的原因。

## 校验标准

导入时按顺序卡这五关，哪一关不过就停在哪一关并给出对应提示：

1. 文件是合法 JSON。
2. `type` 是规则包类型标记。是数据备份文件会单独提示去「导入备份」。
3. `version` 能识别。
4. 包信息完整：`id`、`title`、`metadata.packConfidence` 都在，且 `status` 取值合法
   （草稿／待确认／活跃／已归档／已废弃）。
5. 成员清单完整：每个成员的标识、类型、标题、摘要、正文、状态和元数据都在。

## 三种生成方式

| 方式 | 什么时候用 | 怎么做 |
| --- | --- | --- |
| 导出已有的包 | 包里内容已经在库里 | 打开规则包详情，点右上角「导出这个包」 |
| 打包选中的资产 | 想把自己攒的规则收成一个包 | 在公共资产视图「更多 → 打包成规则包」，勾选规则／文档 |
| 仓库脚本 | 从 Markdown 源文件重新生成种子包 | `npm run pack:seed`（维护种子资产包时才用） |

## 常见报错对照

| 提示 | 真实原因 | 怎么办 |
| --- | --- | --- |
| 这是数据备份文件，不是规则包 | 选成了备份文件 | 用「数据管理 → 导入备份」 |
| 这个文件不是规则包：缺少类型标记 | 是别的 JSON | 确认文件来自上面三种生成方式之一 |
| 规则包版本无法识别 | 文件版本比产品新 | 升级产品后再导入 |
| 规则包的包信息不完整 | 包信息缺字段或状态取值非法 | 对照本文的字段表补齐 |
| 规则包的成员清单不完整 | 某个成员缺字段 | 对照本文的字段表补齐 |
