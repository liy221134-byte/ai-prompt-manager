# 两侧体系对照表（Codex 侧 ↔ WB 侧）

> 一页，只用来看「哪些是**有意分叉**、哪些**应该一致**」。
> 建立 2026-10-01。依据：`docs/reviews/2026-10-01-两套体系对比调研.md`，
> 以及 WB 侧母仓 `E:/WB项目集/README.md`、`AGENTS.md`。
> **不复制任何一侧的正文** —— 复制必然漂移，那正是这张表要防的事。

---

## 为什么需要这张表

WB 侧 2026-10-01 把我们的 `templates/` 复制过去做了自己的正本，明写「复制即脱钩：自此 WB 侧自持、
独立演进」。方向是对的（一份事实一处正文），但带一个副作用：**分叉之后没有对账机制** ——
两边越走越远，谁对不上没人知道。

这张表就是那个对账机制：只记**哪一类该一致、哪一类该分叉**，不记内容。

---

## 判据（一句话）

> **同一事实出现在两处、且两处都需要改 → 应该一致；只有一侧需要改 → 有意分叉。**

## 三、怎么用（出现分歧时）

1. **改之前先问一句**：这次要改的事实，按上面的判据属于哪一类？
2. 「应该一致」那一栏里的东西要改 → 改正本，另一侧**同步**（技能走 `scripts/sync-market-skills.ts`）。
3. 「有意分叉」那一栏里的东西要改 → **只改自己这边**，不要顺手去改对方；对方要不要跟，是对方的决定。
4. 两侧都要改的同一件事 → 先改「应该一致」的正本，再各自落到自己的载体上。
