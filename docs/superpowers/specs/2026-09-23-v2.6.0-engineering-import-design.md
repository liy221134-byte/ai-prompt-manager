- 目标版本：`v2.6.0`，主题是「把现有工程里已经有的事实导进图谱，而不是靠手抄」。
- 状态：**待产品负责人确认**；按 2026-09-23「签 2.5 并继续推进后面的」的授权，
  下面标「按建议执行」的地方先按推荐做法推进。
- 上游：`v2.5.0` 的图谱节点（五类节点 + 稳定编号 + 父节点 + 关系 + 影响分析）已经可用，
  这一版只负责**把节点批量灌进去**，不新增节点模型。
- 「Agent 连接」原本包含三件事（Schema 导入、代码模块分析、MCP 动态查询）。
  按 [项目规则](../../../AGENTS.md) 的「一个版本只做一个子系统」，

  MCP 动态查询会引入新的对外约定和第三方依赖，单独一版、单独确认。

## 一、做什么 / 不做什么

### 做什么

1. **导入数据库 Schema**：粘贴 SQL 或选 `.sql` 文件，解析出表和字段，
   生成「数据」节点草稿（编号 `TBL-<表名>`，正文是字段清单），
   识别到的外键在同批节点之间建「依赖」关系。
2. **分析代码目录**：本机模式下填一个目录路径，扫描源码文件，生成两类草稿——
   - 「模块」节点：一个目录一个节点，编号 `MOD-<相对路径>`，正文列该目录下的文件和导出符号；
   - 「接口」节点：`app/api/**/route.ts` 这类路由文件，编号 `API-<接口路径>`，
     正文列这个接口支持的 HTTP 方法。
3. **统一的导入预览**：解析/扫描结果先列出来，逐条可勾选；同项目同类型里编号已存在的
   默认不勾并写明「已存在」，确认之后才写资产。
4. 导入的节点来源标成「导入」，备注写明来自哪个文件或哪个目录。

### 不做什么

- 不接 MCP、不做动态查询（单独一版）。
- 不调用 AI：Schema 和代码解析都是确定性解析，不产生 AI 费用，也不存在「AI 猜错」。
- 不改已有节点的正文：同编号的节点默认跳过，要更新就自己去编辑器改。
- 不解析 `ALTER TABLE ... ADD CONSTRAINT`、视图、函数和触发器；只认 `CREATE TABLE`。
- 不分析依赖关系图（import/require 的调用关系），只按目录和路由文件归类。
- 不做增量对比和差异界面：导入是「看不存在的就补上」，不做三方合并。

## 二、数据和产品行为影响

- **不改表结构**：仍然写 `assets` / `asset_versions`，节点类型复用 `graph_node`。
- **编号约定**（按建议执行）：数据节点 `TBL-<表名>`、模块节点 `MOD-<相对路径>`、
  接口节点 `API-<接口路径>`；沿用现有的「同项目同类型忽略大小写唯一」校验。
- **父节点**：只在同一批导入的节点内部串（模块按目录层级、接口按路径层级）；
  已有节点不参与组树，导入后要挂到旧节点下面，去编辑器里改。
- **外键关系**：只在外键指向的表也在同一批时建「依赖」关系，指向批外的表不建。
- **代码扫描只在本机模式可用**：云端（Vercel）读不到你的本机目录，按钮会说明原因并禁用。
- **安全与边界**：扫描只读、只收文本源码；跳过 `node_modules`、`.git`、`.next`、
  `dist`、`build`、`coverage`、`.data` 等目录和所有点开头的目录；
  单个文件超过 400 KB 不读内容（只算进清单）；一次最多 3000 个文件，超过直接报错让你收窄路径。

## 三、验收标准

1. 粘贴一段 SQL（含两个有外键关系的表）后，预览里出现两条「数据」节点草稿，
   编号是 `TBL-*`，正文能看到字段清单，备注写明来源。
2. 确认导入后，图谱视图的「数据」分类里能看到这两张表；被引用的那张表在
   「谁指向它」清单里能看到依赖它的那张表。
3. 再导入同一份 SQL，两条都标成「已存在」且默认不勾；不勾选直接确认不会产生重复节点。
4. 本机模式下扫一个代码目录，能看到「模块」节点树（父子缩进按目录层级）和
   「接口」节点（一个路由文件一条，正文列出 HTTP 方法）。
5. 云端模式下打开导入面板，代码目录那一栏写明不可用并禁用；Schema 导入仍然可用。
6. 扫描遇到不存在的路径、超深路径或文件数超限时给出中文提示，不写入任何资产。
7. `npm run check` 通过（类型检查、自动化测试、lint、生产构建）。

## 五、需要你拍板的三个决定（先按建议执行）

1. **版本拆分**：Schema 导入和代码模块分析合成 `v2.6.0`（同一个子系统「读现有工程建节点」），
   MCP 动态查询留到下一版单独确认。
2. **编号规则**：`TBL-<表名>`／`MOD-<相对路径>`／`API-<接口路径>`，
   保持 `REQ-001` 这种短编号留给手工建的节点。
3. **只补不改**：同编号节点默认跳过，导入永不覆盖你已经改过的正文。

## 六、设计偏差（实施后填）

1. **行内引用也算外键**：`user_id uuid references auth.users(id)` 这种列级写法，
   和表级 `foreign key (...)` 一样被读出来；同一个外键指向同一张表时（复合外键的两列）
   合并成一条依赖关系，说明里把两侧列都写上。
2. **外键关系记到编号层，落库时再判**：设计里写的是「只在外键指向的表也在同一批时建关系」。
   实现改成：批内没有这张表时按 `TBL-<表名>` 记一个编号，物化时如果库里已经有同编号的节点
   就连上，没有就丢掉这条关系。这是实测发现的真实场景——第二份迁移引用第一份迁移的表，
   按原设计关系会断掉。
3. **同名表跨 schema 时编号带 schema**：同一份 SQL 里 `public.users` 和 `auth.users` 同时存在时，
   第二个的编号是 `TBL-auth.users`，否则同批导入会出现两个一样的编号。
4. **中间层目录不建模块节点**：模块节点只覆盖「有源码文件的目录」，父节点是最近的已存在上级目录。
   例如 `src/app/api` 没有直接放文件时，`src/app/api/assets` 会挂到 `src/app` 下面。
5. **接口节点只认有导出方法的 route 文件**：认得出 `GET`／`POST` 这些导出才建节点，
   只有 `export const dynamic` 的路由文件不建，减少噪音。
6. **忽略目录比设计里写的更宽**：除了 `node_modules`／`.git`／`.next`／`dist`／`build`／`coverage`
   /`.data`，所有点开头的目录（`.vscode`、`.turbo` 等）都不进扫描。
7. **修了一个实施中发现的真问题**：导入面板切「Schema／代码目录」页签时，React 会把
   「选择 SQL 文件」那个 input 复用成路径输入框，触发受控/非受控告警；给两个分支各加了 key。
