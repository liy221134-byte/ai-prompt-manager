# 发布门禁与故障演练设计（v2.10.0）

## 文档状态

- 目标版本：`v2.10.0`，主题是「每次上线留下人能验证的证据，出事时知道怎么退回去」。
- 状态：**待产品负责人确认**；按 2026-09-23「签 2.9 并继续推进」的授权，
  下面标「按建议执行」的地方先按推荐做法推进。
- 这是「生产工程治理」的最后一版：质量等级（v2.8.0）、验收证据链（v2.9.0）之后，
  补上发布这一段。

## 一、做什么 / 不做什么

### 做什么

1. **发布记录**（新资产类型 `release_record`）：一次上线留一条，内容包括——
   - **版本号或标签**、**发布日期**、**回滚目标**；
   - **门禁清单**：每项可以勾「做完了」并写一句证据说明（例如「工程检查通过」「备份已生成并确认能打开」「迁移在隔离环境跑通过」「环境变量核对过」「回滚目标已确定」「发布后基础验证已做」）；
   - **结果**：进行中／已发布／已回滚；
   - 正文写这次改了什么、遇到的异常和后续。
2. **门禁清单按项目质量等级预填**：新建发布记录时，自动带出这个等级要求的检查项（来自 v2.8.0 的质量等级要求清单），可以再加自定义项。
3. **工程基线里看最近一次发布**：显示最近一条发布记录的版本、结果和门禁完成情况（x／y 完成，未完成的列出来），带「打开记录」和「新建发布记录」。
4. **故障演练记录模板**（内容，进仓库）：演练目标、隔离环境、开始与结束、步骤与结果、
   发现的问题、后续动作；**红线写在模板第一段**——绝不在当前项目的生产代码和唯一生产数据上演练。

### 不做什么

- 不接 CI：门禁项是人工勾选并写证据，不自动跑检查、不自动读流水线。
- **MCP 不能写发布记录**：门禁是「人工可验证证据」，让 AI 勾选等于自己给自己发证。
  AI 可以查（`get_asset`），不能建、不能改、不能勾。
- 不做演练记录的结构化类型：演练是学习性活动，先给模板 + 红线，不够用再按同一套做法加类型。
- 不做发布审批流、不做多环境发布编排、不做回滚自动化。
- 不自动比对线上版本：发布日期和版本号手填。

## 二、数据和产品行为影响

- 新增资产类型 `release_record`，**不改表结构**（`asset_type` 是文本字段，元数据走 JSON），
  本机和云端都不用迁移。
- 元数据：`{ version, releasedAt, result, rollbackTarget, gates[{ key, label, done, note }] }`；
  缺字段按空值读，老数据不受影响。
- 门禁项的 `key` 用检查项文字本身（同一个概念在各等级里写法一致），
  便于「最近一次发布」和以后的对比；先不做独立目录。
- 类型筛选、搜索、备份、MCP 查询都自动覆盖这种新类型（沿用统一资产）。
- 演练模板加进 `templates/engineering/`，用现有「导入模板」装进项目；内容门禁测试同步更新。

## 三、验收标准

1. 能新建发布记录：填版本号、发布日期、回滚目标，勾门禁项、写证据说明、选结果；
   版本号为空时保存被拦下并给中文提示。
2. 新建时门禁清单按项目质量等级预填（个人工具 2 项、涉及用户数据 6 项），可以增删改。
3. 详情显示版本、结果、发布日期、回滚目标，以及门禁完成情况（x／y）和未完成项。
4. 工程基线显示最近一次发布的版本、结果和门禁完成情况，能一键打开或新建。
5. 类型筛选能筛出发布记录。
6. MCP 能查到发布记录，但**新建和修改都会被拒绝**（写工具的允许列表里没有这一类）。
7. 演练记录模板在仓库里，第一段写明「不得在生产数据和唯一生产代码上演练」。
8. `npm run check` 通过。

## 五、按建议执行的三个决定

1. **发布门禁做成新资产类型**，不是一份模板文档：要能勾、能查「哪些项还没做」，
   模板做不出状态。
2. **演练只给模板和红线**，不做结构化类型：先看真用不用得上。
3. **门禁清单按质量等级取默认项**：等级越高默认项越多，和 v2.8.0 的要求清单是同一份口径。

## 六、设计偏差（实施后填）

1. **发布记录的标题按版本号自动生成**（例如「v2.10.0 发布记录」），编辑器里不再单独填标题。
   一次发布只有一个版本号，两处填同一个信息没意义；实测发现「忘记填标题就存不下」之后改的。
2. **门禁项的 `key` 直接用检查项文字**：等级清单里的同一项文字在各等级写法一致
   （例如「工程检查通过」），够用；将来要做跨发布对比再换成独立编号。
3. **MCP 的拒绝发生在 schema 层**：`create_asset` 的类型枚举里根本没有 `release_record`，
   真机确认调用返回参数校验错误；另外在写入草稿里加了兜底分支，避免以后漏写分支把
   这类只许人工填的资产当文档建出来。
4. **详情抽屉和编辑器补齐了发布记录的类型名与正文字段名**：这和 v2.9.0 遇到的是同一处问题
   （非规则资产缺分支时落到「文档 / 选型说明」），这次一起按类型给全了。
