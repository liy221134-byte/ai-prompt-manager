## 一、做什么 / 不做什么

### 做什么

1. **工程基线能认出已有文档**：缺口那一行如果项目里已经有同类文档，直接给「打开已有的这份」，
   不再只给「新建文档」。
2. **图谱节点能关联文档资产**：节点编辑器增加「关联一份文档」，把项目里的文档挂到节点上
   （走现有的资产关系，不新增字段）；图谱视图里补一句说明，讲清这条链路怎么用。
3. **验收记录能关联录入**：新建验收记录时可以直接挑一条需求节点、挑一份已有的验收清单文档，
   标题和对应需求节点自动带好（现在只能从工程基线的「验收覆盖」进去才有预填）。
4. **技术档案给一个提示词**：技术档案页面提供「复制技术档案提示词」，贴给 AI 拿到内容后
   再贴回编辑器保存——零代码、没有 `package.json` 的项目走这条路。
5. **数据搬运写进手册**：本地与云端之间怎么搬（导出→导入，只新增不覆盖）、
   代跑脚本 `npm run sync:from-cloud` 怎么用，写进 README 和这份文档对应的运维说明。
6. **导入工程补第三种来源「项目文档」**：选一批 Markdown（本机模式下可以直接给一个目录），
   **原样**建文档资产，不走 AI 识别。
   来源：本地自测时发现——项目迭代产生的需求、设计、验收文档现在只能走「导入文档包」，
   而那一条要 AI 逐份识别，导出草稿再确认，比直接入库麻烦得多；
   代码目录扫描又只产出模块和接口节点，不产出文档。于是「项目文档进不来」成了断点。
7. **图谱节点更好用**：
   - 节点详情把「扫描到的文件 / 具名导出 / 支持的方法」按用途说明白（现在有内容，但没人告诉它能干什么）；
   - 项目图谱支持把选中的文档**批量挂到节点**上（多选节点 + 多选文档，一次建好关系）；
   - 节点编辑器里给一句「这个节点该挂哪类文档」的提示（模块挂设计/接口说明，接口挂接口文档，数据挂表结构）。
   来源：本地自测时发现——62 个代码节点没有任何关系，看着像"一堆代码"，用不起来。

### 不做什么

- 不做自动同步（两边都能改，自动合并会把数据弄乱）。
- 不做资产自动归类（「哪条该进公共、哪条该进项目」需要新链路，单独立项）。
- 不做 MCP 批量入库（同上）。
- 不在代码扫描里"猜文档"：扫描只认代码，文档走第 6 条那条原样导入的路。
- 不改数据库结构：以上都在现有资产、元数据和关系字段里做。

## 二、数据和产品行为影响

| 项 | 影响 |
| --- | --- |
| 数据库 | 无表结构变化 |
| 关联关系 | 复用现有四类关系（引用／依赖／替代／实现），节点关联文档默认用「引用」，可改 |
| 工程基线 | 只改展示与入口：已有同类文档时给「打开已有的这份」，缺口判定口径不变 |
| 验收记录 | 新建时多两个可选项（需求节点、已有文档），预填逻辑不变 |
| 技术档案 | 新增一个「复制提示词」按钮，不改技术档案本身的字段和校验 |
| 数据搬运 | 只是写文档和脚本，不改产品行为 |

## 三、验收标准

每条都能用一次手工验证或一次自动化测试判定。

1. 工程基线的缺口行：项目里已有同类文档时显示「打开已有的这份」，点开是那份文档；
   没有同类文档时才显示「新建文档」。
2. 节点编辑器里能挑一份项目内的文档建立关系，保存后图谱视图的「这个节点指向谁」里能看到它。
3. 图谱视图里有说明，写清「节点靠资产关系连文档，影响分析读的就是这批关系」。
4. 验收记录新建面板里可以直接挑需求节点和已有文档；不挑也能正常新建。
5. 技术档案面板能一键复制提示词，提示词里包含项目名、项目说明和当前技术栈。
6. README 里能查到两条数据搬运路径和代跑脚本的用法。
7. 导入工程里能选一批 Markdown 直接建文档资产（原样入库，标题取文件名，正文就是原文），
   导完在项目视图的「文档」标签下能按类型筛出来；同一份文件重复导入不会建重复资产。
8. 在项目图谱里多选节点和文档，一次建好关系；建完节点详情和影响分析里都能看到。
9. 节点编辑器里能看到「这个节点该挂哪类文档」的提示。
