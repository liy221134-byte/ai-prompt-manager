# 提示词写入路径切换到统一资产（设计 + 任务清单）

## 文档状态

- 目标版本：`2.1.0`。
- 前置条件：`2.0.0` 验收清单待签字（白天补）；云端任务需要先应用 Supabase 迁移。
- 状态：设计已确认，按四、里的任务顺序实现。
- 本文只写决定，不写 SQL、完整代码和实现步骤。

## 一、做什么与不做什么

### 做什么

- 统一资产成为提示词的唯一正式写入源，新建、编辑、删除和恢复都写统一资产。
- 旧的 `prompts` 和 `prompt_versions` 表停止写入，保留为迁移前快照。
- 合并、优化、垃圾箱和恢复改为在资产版本上完成，行为与现在保持一致。
- 备份导出和导入改由统一资产承载，备份文件格式不变。
- 本地 SQLite 与云端 Supabase 使用同一条读写路径。
- 切换前提供一次对齐检查，保证统一资产里的提示词与旧表完全一致。

### 不做什么

- 不改备份格式，备份这一步仍然只覆盖提示词。
- 不新增或修改任何界面，用户看到的行为与切换前一致。
- 不新增规则、文档、技术档案相关功能。
- 不删除旧的 `prompts` 和 `prompt_versions` 表，也不清理其中的数据。
- 不做新旧表双写。

## 二、数据和产品行为影响

### 唯一写入源

- 提示词的唯一写入源是统一资产表；旧提示词表在切换后只读。
- 切换前必须先备份；对齐检查失败时不得进入只写统一资产的状态。
- 切换后如果统一资产里缺少某条提示词，以旧表内容补齐一次，不反向覆盖资产。

### 提示词字段映射

- 标题、分类、标签、正文和适用场景继续沿用现有对应关系，规则不变。
- 提示词标识保持不变，书签、合并关系和恢复关系不失效。
- 项目归属沿用默认项目，不因为切换改变已有归属。

### 版本与恢复

- 每次正式保存产生一条不可变资产版本。
- 合并前快照和优化前快照改用资产版本承载，版本原因保持不变。
- 合并恢复和优化恢复产生新版本，历史版本不被覆盖。
- 优化前快照的有效期规则（30 天）和垃圾箱保留规则（30 天）保持不变。
- 恢复到历史版本产生新版本，不修改被恢复的那条记录。

### 垃圾箱

- 垃圾箱状态沿用资产生命周期字段，恢复和永久删除语义与现在一致。
- 永久删除只在用户主动操作时发生。

### 备份

- 备份文件格式和版本号不变，仍然只包含提示词内容字段。
- 导出改为从统一资产读取，导入改为写入统一资产。
- 旧版备份继续可以导入，导入后提示词立即出现在默认项目。

### 回滚

- 回滚依靠切换前备份，不依赖代码回退到旧路径。
- 回滚顺序：先用切换后的版本导出一份提示词备份，再切回旧版本并导入该备份。
- 因为备份格式没有变化，这条回滚路径在切换前后都可用。
- 接受的范围：切换后新增或修改的提示词，只能通过上面的备份导出找回。

## 三、验收标准

每条都能用一次测试或一次手工验证判定。

- 切换后提示词的数量、标题、分类、标签、正文和标识与切换前完全一致。
- 新建、编辑、删除和恢复提示词只在统一资产上写入，旧提示词表不再发生变化。
- 提示词详情、变量填写和一键复制行为与切换前一致。
- 合并后目标提示词更新、来源进入垃圾箱并保留合并关系，恢复行为与切换前一致。
- 优化后可以回到优化前，回退产生新版本，历史版本一条不少。
- 垃圾箱 30 天清理规则不变，过期内容仍然被清理。
- 旧版提示词备份可以导出和导入，导入后立即出现在默认项目。
- 重复执行切换不会产生重复资产和版本。
- 切换失败时旧数据保持可读，不出现半迁移状态。
- 统一资产缺少某条提示词时会被补齐，补齐后内容与旧表一致。
- 本地和云端行为一致，未登录不能读取项目和资产。
- `npm run check` 全部通过。

## 四、任务顺序与预期改动

| 序号 | 任务 | 预期改动 |
| --- | --- | --- |
| 1 | 本地统一资产承载提示词的读写、恢复和垃圾箱 | `src/lib/server/prompt-database.ts`、`src/lib/server/asset-database.ts`、数据库与恢复测试 |
| 2 | 云端使用同一套语义 | `src/lib/prompt-source.ts`、`supabase/migrations/`、云端数据源测试 |
| 3 | 备份导出和导入切到统一资产 | `src/lib/prompt-backup.ts`、备份测试、`docs/operations/` |
| 4 | 切换演练、回滚验证与验收清单 | 迁移测试、`docs/acceptance/` |

每个任务单独提交，完成后运行完整工程检查。云端任务必须在迁移应用之后执行。

任务 1 把内容读写和合并、优化、垃圾箱合并在一起做，原因是：合并和优化既改内容又写快照，
如果只切内容、快照留在旧表，会出现两套版本记录并存的状态，比一次性切完更难验证。

## 五、关键决定

1. 统一资产是提示词的唯一写入源，旧提示词表停写并只读保留。
2. 提示词标识不变，避免书签和恢复关系失效。
3. 备份格式这一步不变，只改变读写去向。
4. 不使用双写；需要回滚时走「先导出、再切换、再导入」。
5. 用户可见行为不变，验收以「与切换前一致」为准。
6. 旧提示词表和旧版本表长期保留，不删除。

## 六、已确认的决定

1. 版本号用 `2.1.0`。原计划里 `2.0.1` 的导入功能顺延。
2. 回滚方式采用「先用新版本导出备份，再切回旧版本并导入」。
3. 旧提示词表和旧版本表长期保留，不在本版本清理。
