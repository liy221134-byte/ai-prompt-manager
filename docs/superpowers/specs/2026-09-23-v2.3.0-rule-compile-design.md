# 规则编译设计（v2.3.0）

## 文档状态

- 目标版本：`v2.3.0`，主题是「把项目里的规则编译成可以直接用的文件」。
- 状态：**待产品负责人确认**，确认后才开始写代码。
- 对应 [2.0 需求草案](../../v2-requirements-draft.md) 里的「编译交付物」和 P0 需求
  「规则冲突检测和人工裁决」「编译 `AGENTS.md` 和 `START_PROMPT.md`」。
- 上游：`v2.2.0` 的规则包和种子资产包已经把「规则 + 可信度 + 编译去向」铺好了。
- 本文只写决定，不写实现步骤、SQL 和成段代码。

## 一、做什么 / 不做什么

### 做什么

1. **编译候选集**：按项目把「该编译的规则」挑出来，依据已有的字段判断——
   资产状态（只算活跃）、作用范围（全局／项目／任务）、作用层级、执行阶段、
   编译去向（`agents`／`readme`／`start_prompt`）、可信度。
   面板按「作用层级 → 规则类型」分组列出，每条可以单独取消。
2. **冲突候选与人工裁决**：把同一项目里**维度重叠**的规则两两摆出来
   （作用范围相同、层级相同、技术上下文有交集），标成「可能打架，请你确认」。
   人工裁决的结果记在规则元数据里（参与编译／排除、备注、时间），
   下次打开还是这个结论，不用重复裁决。
3. **生成草稿**：按固定结构生成两份草稿——
   - `AGENTS.md`：按作用层级分组，组内按规则类型排；每条写陈述、理由、来源（哪个包）、可信度。
   - `START_PROMPT.md`：面向「开工第一句话」，只列必须和禁止，加项目技术档案里的一行摘要。
   草稿顶部写明项目名、生成时间、参与条数、被排除条数和生成器版本。
4. **产出去向**：界面上可以预览、复制、下载，也可以**保存成文档资产**
   （文档类型写文件名，角色标成「编译结果」），这样编译交付物本身也被管理、有版本。

### 不做什么

- 不做规则矛盾的自动判定和自动合并：只做「可能打架」的候选提示，裁决由人来点。
- 不自动写外部文件、不自动提交 Git、不调用任何外部服务。
- 不做模板中心（`template` 资产类型继续预留），这一版的产品结构是内置的固定结构。
- 不做规则的自动裁剪（比如按可信度自动丢掉「假设」），候选集怎么算必须看得见、可改。
- 不做上下文图谱和 MCP。

## 二、数据和产品行为影响

### 新增字段（可选，旧数据缺字段按空值读）

- 规则元数据新增 `compileDecision`：`{ decision: "included" | "excluded", note: string, decidedAt: string }`。
  含义是「这条规则在编译时算不算数」；不写这个字段等同于按默认规则参与编译。

### 行为影响

- 工具栏新增「规则编译」入口，打开编译面板；不改动现有列表和筛选行为。
- 编译产物保存成文档资产时，走的是现有「新建资产」路径，产出的是普通文档资产，
  因此版本、归档、关系这些能力自动具备，不需要新表。
- 本地和云端都不需要改表结构：`compileDecision` 存在资产元数据里，和 `rule_pack`、
  成员上的 `pack` 链接一样是可选元数据。
- 编译本身是只读计算加一次可选写入（保存产物），不修改被编译的规则内容；
  唯一的例外是你在面板里勾选「排除」时，会更新这条规则的 `compileDecision`。

## 三、验收标准

1. 编译面板列出当前项目里参与编译的规则，按作用层级和规则类型分组，
   条数和资产列表里筛出来的条数一致。
2. 取消勾选某条规则后，它的元数据记下「不参与编译」；关掉面板再打开，
   这条仍然是取消状态，而且生成的草稿里没有它。
3. 冲突候选能列出维度重叠的规则对，并显示重叠在哪个维度；
   点「排除其中一条」后它不再出现在草稿里。
4. 生成的 `AGENTS.md` 草稿包含：项目名、生成时间、分组标题、每条规则的陈述、
   理由、来源包名和可信度；被排除的规则不出现。
5. 草稿能在界面上复制和下载，也能保存成文档资产（角色「编译结果」）；
   保存后能在资产列表里看到，并且有正常的版本记录。
6. 全程不修改任何外部文件、不调用外部服务；不参与编译的规则内容不被改写。
7. `npm run check` 通过（类型检查、自动化测试、lint、生产构建）。

## 五、需要你拍板的三个决定

1. **编译产物怎么落**：保存成文档资产（角色「编译结果」，能看到版本和历史），
   同时支持复制和下载；不自动写外部文件。—— 建议这么做，你确认下。
2. **人工裁决怎么留痕**：记在规则元数据里（参与／排除、备注、时间），下次再用；
   还是只在这一次编译里临时生效？—— 建议记下来。
3. **冲突候选的判定口径**：先做**结构化重叠**（同作用范围、同层级、技术上下文有交集，
   或者同层级下一条「必须」一条「禁止」），只提示「可能打架」由你裁决，
   不做自动判定矛盾、不做 AI 语义比对。—— 建议先这样，你确认下。
