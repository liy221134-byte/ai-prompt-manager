## 一、为什么这个功能可做，而「自适应出题」不可做

二者的区别只有一条：**判据在不在手上。**

自适应出题被否，是因为题库里 72 格只有 1 道题，同一格再问必然重复 —— 没有可问的东西。
论文批改相反：**题目自带子问题清单**，而子问题就是判据。

看 2026 年 5 月第一批真题（考生回忆版，多源一致）：

> 论信息系统项目质量管理
> 1. 概要叙述你参与管理过的信息系统项目（背景、规模、发起单位、目的、内容、组织结构、周期、交付成果），并说明你承担的工作
> 2. 围绕以下要点论述你对质量管理的认识：
> （1）如何评价数据质量，写出评价数据质量的常见几个维度
> （2）按质量管理的**子过程及输入与输出**，结合数据独特性与行业，简述你怎么管
> （3）结合相关国家标准，写出 **3 个**评价数据准确性的**指标及其计算方法**

每个子问题都带硬要求：「写出 3 个」「按子过程及输入输出」「给出计算方法」。
**「切合题意 30%」因此不是印象分，而是一张能逐行勾选的表。**

第二批次（AI 时代的安全管理与风险管理）完全同构：1 个大项 + 3 个子问题。
所以这不是某一道题的偶然形状，是这一代题型的固定结构。

**推论：这个产品不问「写得怎么样」，只答「题目问的 4 件事你答了哪几件、答到哪一层」。**
后者是他拿到就能改的东西。

## 二、判据的三层可信度（这一节决定产品边界）

核实过程见本轮对话；`docs/learning/topics/rk-mid-integration.yaml` 的 `exam_facts` 已含考试形式。
下面按「能不能当判据」分档，**产品只允许用第一、二档**。

### 第一档 · 确定，可以直接判

多源一致，且与官方考试规则对得上：

- 2023 年下半年起全面机考，**论文为键盘输入，不是手写**
- 论文 120 分钟，不得提前交卷；满分 75，全国统一 45 及格
- **两道题二选一**，只作答一道
- 三科同次均 ≥45（已知，与目标 `goal` 一致）

> 派生结论：**输入是纯文本，不做 OCR、不做图片上传。** 他在考试系统里打出来的字，
  复制出来就是产品输入。这让整个功能从「识别题」降级成「文本题」。

### 第二档 · 较可信，可以给档位但必须写明来源

同一来源族（含一份评分参考标准的 PDF 原件）三篇文章口径完全一致。论文五维度、百分制加权后 ×0.75：

| 维度 | 权重 | 分几档 |
| --- | --- | --- |
| 切合题意 | 30% | 非常切合 / 较好地切合 / 基本上切合 |
| 应用深度与水平 | 20% | 很强 / 较强 / 一般 / 较差 |
| 实践性 | 20% | 大量实践 / 良好实践 / 一般 / 初步实践 |
| 表达能力 | 15% | 3 档 |
| 综合能力与分析 | 15% | 很强 / 比较强 / 一般 |

总分档：60—75 优良 · 45—59 及格 · 0—44 不及格。

**三条直接不及格的硬线**（不是扣分，是不及格）：
1. 虚构情节，有明显不真实或不可信的内容
2. 未能详细讨论项目实际经验，主要从书本知识与资料摘录进行讨论
3. 所讨论的内容与方法过于陈旧，或项目水准相对很低

已有的扣分项（非否决）：正文基本按条目罗列、过分自我吹嘘、内容有明显错误与漏洞（同类错误扣一次）。

### 第三档 · 存疑，**不做成判据**

- **正文该写多少字**：2000—3000 / 2500—3000 / 「不足 1200 扣分」三种说法，官方无硬性数字
- **摘要还要不要**：评分参考标准里写着「摘要 200—400 字，没写要扣分」，
  但 2026 年 5 月的两道真题结构里**没有摘要这一项**，只有「1. 概要叙述项目 + 2. 论述要点」

这两条的处理方式：**不判达标与否。** 摘要写了就检查是否在 200—400 字区间，没写不扣、不提示要写。
字数只统计并展示，不给「字数不足」结论。

理由与 M6 撤掉 `wrongLinks` 是同一条：**没有依据的判据留着，比空着更糟** ——
空着他知道没查，假判据他会当真。

## 三、主体设计

### 3.1 输入：两样，缺一不可

| 字段 | 必填 | 为什么要 |
| --- | --- | --- |
| 题目全文 | 是 | 不贴题目就无从判切题。**这是硬前提，不给「只批文不批题」的口子** |
| 论文全文 | 是 | 纯文本粘贴（机考打字，直接复制） |
| 稿次说明 | 否 | 如「第 2 稿，改了摘要和第 3 个子问题」。**只影响记录标签，不参与判分** |

字数不让他手填：由正文自动统计（去空白后的字符数）。
**与考试系统计数口径未必一致，界面上只写「本稿约 N 字」，不写「达标」。**

### 3.2 子问题拆解：必须露出来，不能藏起来

模型先读题目、拆出子问题清单（含每个子问题的硬要求，如「写出 3 个」「给出计算方法」），
再逐条对照论文。

**拆解结果放在产出最上面，原样展示。** 这是「读不出来时不许编」的应用：
题目结构特殊、它只拆出 2 条而实际有 4 条时，他一眼能看见，而不是被埋在一段评语里。

不单独做「先确认子问题、再批改」的两步流程：那多一次点击，而拆错的概率并不高；
把清单摆在最上面已经足够发现错误。

### 3.3 产出四块（顺序即重要性）

**① 子问题对照表** —— 核心产物，一行一个子问题：

| 子问题 | 答了没 | 落到项目 | 有具体指标/工具 | 依据 |
| --- | --- | --- | --- | --- |

- 「落到项目」指有没有结合他叙述的那个项目，而不是泛泛讲理论
- 「有具体指标/工具」指有没有落到可验证的细节（工具名、指标名、计算公式、数字）
- 「依据」必须是**从他论文里引的原句**，引不出来就写「未找到对应段落」

形状与他熟悉的覆盖矩阵一致 —— 不新造一种看数据的姿势。

**② 三条硬线的疑点** —— 只报疑点，**不判「你虚构了」**：

每条只写「哪里可疑」+ 原句。判虚构涉及对个人经历真实性的判断，模型越权下结论比不说更糟；
他要的是「这句经不起推敲，你自己看看」，不是判决书。

**③ 五维度档位** —— 每个维度一行：档 + 一句依据（依据必须指向上面表格或原文）。

**④ 如果只改一处** —— 一句话。
三块清单会让人不知道该先动哪儿，所以最后必须收口成一条。

### 3.4 存哪：新表 `learning_essay_reviews`

> **不做「论文」主表 + 批改子表。**
> 论文正文每次都可能大改，不存在稳定的「一篇论文」这个实体；要立主表就得让他给论文起名、
> 管理列表、删除、改名 —— 那是编辑器的活，不是批改的活。
> 这一版只存**批改记录流**，同一篇的多稿靠 `draft_label` + 时间排列串起来。
> 等真的出现「我要管理我的论文库」这个需求，那时候才知道主表该有哪些列。

```sql
create table if not exists public.learning_essay_reviews (
  id           text primary key,
  user_id      uuid not null references auth.users (id) on delete cascade,
  topic_id     text not null references public.learning_topics (id) on delete cascade,
  -- 知识点 id（KP-0701 论文）。不设外键，理由同 learning_probes：
  -- 批改是历史记录，题库重组不该把旧记录带走。
  kp_id        text,
  prompt_text  text not null,          -- 题目原文，必填
  essay_text   text not null,          -- 论文正文，必填
  draft_label  text,                   -- "第 2 稿"，可为空
  word_count   integer not null default 0,  -- 去空白后的字符数
  result       jsonb not null default '{}'::jsonb,  -- 四块产出
  created_at   timestamptz not null default now()
);
```

索引 `(user_id, topic_id, created_at desc)`；RLS 四条策略与表级 `grant` 照抄
`20261028233000_add_learning_probe_and_sheet.sql`。
**迁移里必须显式 `grant`，不依赖 Supabase 的隐式默认授权。**

### 3.5 接口 `POST /api/learning/essay-review`

照 `graph-check/route.ts` 的形状：鉴权 → 校验 → `callChat` → `normalize`。

- `temperature: 0.2` —— 批改要稳定，同一篇跑两次不该一次说漏子问题 (3)、一次说漏 (4)
- `timeoutMs: 55_000`、`maxDuration = 60`
- 落库在**客户端**做完（与素材表一致），API 只负责判、返回结构

**超时是真风险**：2500 字输入 + 结构化输出，接近 60 秒上限。
先按单次调用做，实测若经常超时，再拆成「先判子问题覆盖、再判维度」两次短调用 ——
**拆的判据是实测耗时，不是预判。**

### 3.6 入口与形态

- 第四个抽屉，`variant="fullscreen"`（与讲义一致：铺满、header 吸顶、不挂遮罩关闭）
- 从 `learning-topic.tsx` 里 S7 论文模块进入
- **抽屉必须定义在两个 `return` 之前** —— 练习模式是提前 return 的分支，
  挂在主 return 里会「点了没反应」（M3 踩过的坑）
- 全屏内左侧论文原文（只读、可折叠），右侧四块产出；
  窄屏（< lg）改成上下堆叠，不做横向滚动

## 五、验收标准（写成能看见的现象）

1. 贴 2026 年 5 月第一批**真题目** + 一篇**故意漏答子问题 (2)(3)** 的论文，
   对照表必须指出这两条没答，并且「依据」栏写「未找到对应段落」
2. 同一篇里**只写了「按 ISO 标准」而没给指标与计算方法**的段落，必须被标成
   「有具体指标/工具：否」
3. 贴一篇**正常完整**的论文，子问题对照表 4 行全答，且**不出现任何总分、不出现「能否过线」字样**
4. 拆解结果在产出最上面原样展示；人为用一道结构特殊的题目时，拆得对不对一眼可见
5. 同一篇存两稿（`第 1 稿` / `第 2 稿`），列表能看到两条、按时间倒序、字数各自独立
6. 不贴题目只贴论文 → 提交按钮不可用并说明原因（不接受「只批文不批题」）
7. 摘要**没写**时，产出里不出现任何「缺摘要」提示
8. 窄屏（375px）下左右两栏改为上下堆叠，无横向滚动

## 六、明确不做

- **不代写、不生成论文**，也不给「这句话可以这么改成……」的改写建议。
  一旦给出可粘贴的句子，这篇论文就不再是他写的，而考场上是模型去不了的地方
- **不给总分、不预测能否过 45 分**（第一条已拍定）
- **不判文笔辞藻**。表达能力只判结构与口语化，不评「写得好不好看」
- **不做 OCR / 图片上传**（机考打字，见第二节第一档）
- **不判字数达标、不判摘要缺失**（第三节第三档存疑）
- **不建论文库 CRUD**（3.4 已说明）

## 七、已知风险

| 风险 | 应对 |
| --- | --- |
| 单次调用逼近 60 秒（Vercel Node runtime 上限） | 先按 `timeoutMs: 55_000` 做；实测常超再拆两步。**拆的判据是实测，不是预判** |
| 子问题拆解不准 | 拆解结果原样展示在最上面，错了一眼可见；不藏在评语里 |
| 「实践性」「应用深度」本质是主观判断 | 只给档位 + 指向原文的依据；不给「你这个项目不真实」这种结论 |
| 判据来源是培训站转载，非官方原文 | 文档与界面上都写明来源；三条硬线与五维度只在文档里成立，不伪装成官方标准 |
| 模型倾向讨好，会把漏答说成「稍显不足」 | 提示词里把「依据栏必须引用原句，引不出来写『未找到对应段落』」写成硬要求；验收第 1 条专门测这个 |
