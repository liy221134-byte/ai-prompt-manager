# 2.1.2 技术档案、资产关系与备份升级（设计 + 任务清单）

## 文档状态

- 目标版本：`2.1.2`（排在 `2.1.1` 之后发布）。
- 前置条件：`2.1.1` 已合并并签完验收，规则和文档的完整元数据可以在界面上编辑。
- 状态：**设计待确认**，第六节的四个问题拍板后才开始实现。
- 本文只写决定，不写 SQL、完整代码和实现步骤。

## 一、做什么与不做什么

### 做什么

- 项目级技术档案：记录这个项目选了什么技术、为什么选、什么情况下要重新评估。
- 技术档案与 ADR 关联：偏离默认选型时，要求挂上一条解释原因的 ADR。
- 资产之间的显式关系：引用、依赖、替代、实现四类，可以在详情里查看和编辑。
- 搜索升级：从只搜当前项目，升级到可以按项目、类型、状态、标签、关系组合筛选。
- 备份升级：备份范围从「只有提示词」扩到「项目、提示词、规则、文档、关系和技术档案」，旧版备份继续可导入。

### 不做什么

- 不做规则冲突编译，不生成最终 `AGENTS.md`。
- 不做需要图谱可视化的关系视图，先把关系当数据存好、列表里能筛。
- 不做跨项目的资产移动。
- 不把来源包的二进制原文放进备份文件。
- 不做关系类型的自定义（四类固定）。

## 二、数据和产品行为影响

### 技术档案

- 一个项目最多一份技术档案，作为该项目的技术选型依据；归档项目时一起保留。
- 技术档案的内容分两块：技术栈清单（每项含名称、版本、用途）和选型说明（默认选型与偏离项）。
- 标记为「偏离默认选型」的条目必须关联一条 ADR；没挂 ADR 时保存被拒绝，并提示补一条。
- 技术档案在界面上可编辑，改动产生新版本，历史不覆盖。

### 资产关系

- 关系存在资产上，不新建表；一条关系包含：目标资产、关系类型、一句说明。
- 关系是单向的：A 引用 B，不代表 B 引用 A；反向关系在详情里以「被谁引用」的形式展示。
- 删除或归档资产时，指向它的关系不删除，但在界面上显示为「目标已归档」。
- 关系变化产生新版本，和正文、元数据一样。

### 搜索与筛选

- 搜索范围：标题、说明、正文、标签、技术栈名称。
- 筛选条件可以组合：项目、类型、状态、标签、关系目标。
- 本地模式在前端过滤；云端模式同样在前端过滤，不新增服务端检索接口。

### 备份

- 备份格式升到 v2：包含项目、提示词、规则、文档、技术档案、关系和版本号。
- 旧 v1 备份（只有提示词）继续可以导入，导入时进入默认项目。
- 来源包的二进制原文不进备份，只备份来源包资产的元数据；备份文件里写明这一点。
- 导入依旧是先预览后确认，预览里显示新增、更新、跳过和冲突数量。

## 三、验收标准

- 项目里可以创建一份技术档案，保存后列表里能看到，改动产生新版本。
- 标记为偏离默认选型的条目必须挂 ADR，不挂时保存被拒绝并给出中文提示。
- 资产详情里可以新增、修改、删除四类关系，保存后刷新仍然在。
- 关系目标被归档后，详情里显示「目标已归档」而不是报错。
- 可以按项目、类型、状态、标签和关系目标组合筛选，结果与预期一致。
- 备份文件包含项目、提示词、规则、文档、技术档案和关系；换一个空库导入后逐项对得上。
- 旧版 v1 备份仍然可以导入，导入后提示词进入默认项目。
- 备份文件里不包含来源包二进制，导入后来源包资产仍在但原文需要另行保留。
- `npm run check` 全部通过。

## 五、关键决定

1. 技术档案是项目一级档案，一个项目一份。
2. 偏离默认选型必须有 ADR，靠校验强制，不靠人自觉。
3. 关系是单向的，存在资产里，不新建表；目标归档不回删关系。
4. 备份升级到 v2，旧 v1 继续可导入。
5. 来源包二进制不进备份，只在文件里说明。

## 六、待确认

1. 技术档案的粒度：一个项目一份（建议），还是允许一个项目多份（例如前端一份、后端一份）。
2. 关系类型是否就这四类：引用、依赖、替代、实现；要不要再加「同源」这类弱关系。
3. 备份要不要包含项目设置（名称、目标、阶段、归档状态）：建议包含，这样换库后项目结构一致，
   但导入到已有项目时会出现同名项目，需要决定是跳过还是合并。
4. 要不要在 2.1.2 里顺手清理 `2.0.3` 的加固项（迁移演练和边界测试），还是严格按计划留在 `2.0.3`。
