# 规则引用模型收尾（v2.20.0 设计 + 任务清单）

## 来源

`v2.18.0` 落地时留下的两处已知缺口，记在 `docs/pending-items.md` 第 9 条：

1. 想只改一个项目时，要先在公共库复制一份再改——缺一个**「另存为项目规则」**按钮。
2. 引用粒度是**整包**，不能只挑包里几条。

本文记录这两个缺口的做法。**待确认后才开发。**

## 一、做什么 / 不做什么

### 做什么

1. **逐条挑规则**：项目通过一条引用记录引用一个包时，可以把这个包里不适用的个别规则
   排除掉。被排除的规则不参与项目列表、不参与规则编译。
2. **装包时就能挑**：安装规则包的预览面板里逐条勾选，默认全选；装完后打开那条引用记录
   还能再调整。
3. **「另存为项目规则」**：对一条引用来的规则，可以复制成项目专属副本再改。
   改副本不影响公共库，也不影响别的引用同一个包的项目。
4. **脱钩之后说清楚**：副本在列表里标明「已脱钩」；打开时不再提示「公共库那份改过了」，
   因为已经明确脱钩，两边不再联动。
5. **编排口径跟着走**：规则编译的候选集包含脱钩副本，不包含被排除的规则；沉淀体检
   把脱钩副本算作项目专属规则。

### 不做什么

- **不改数据库表结构**：排除清单和脱钩标记都放进资产的 `metadata` JSON，
  沿用 `v2.18.0` 的做法，云端与本机不用迁移。
- **不做「改回引用公共库」的一键回退**：脱钩后想退回去，手工删掉副本、重新打开引用包
  勾上即可。这条路径要写进界面提示。理由见 D5。
- **不做包内文档和模板的逐条挑选**：包里头的文档、模板本来就不复制进项目（`v2.18.0` 的
  边界），没有可挑的东西。
- **不做规则级的独立引用**：引用单位仍然是包，只是允许在包内做减法。
- **不给公共库加「被哪些项目排除过」的反查**：现在是个人使用，没有人需要看这个统计。

## 二、数据和产品行为影响

### 新增的两个元数据字段（都在 `metadata` JSON 里，不是表结构）

| 字段 | 挂在哪 | 作用 |
| --- | --- | --- |
| `excludedItemIds` | 项目的**引用记录**（`rule_pack` 资产） | 这个项目从这个包里排除掉的包内编号 |
| `detachedFrom` | 项目里的**脱钩副本**（`rule` 资产） | 记它脱钩自哪个包的哪个编号；有这个标记的副本优先于公共正本 |

两个字段都缺省为空：老数据读出来就是「没排除、没脱钩」，行为和现在完全一样。

### 行为影响

| 项 | 影响 |
| --- | --- |
| 项目规则列表 | 项目专属 + 引用包的成员，**减去排除清单**；脱钩副本顶掉同编号的公共正本 |
| 规则包安装 | 装到项目时，预览面板可逐条勾选；勾选结果写成引用记录的排除清单 |
| 引用包详情 | 显示每条成员当前是否生效，可以随时改 |
| 规则编译 | 候选集尊重排除清单；脱钩副本算项目专属，正常参与 |
| 立项推荐 | 口径不变（引用了包就不再推荐包内规则） |
| 沉淀体检 | 脱钩副本进「只在项目里出现」清单——它确实只属于这个项目 |
| 其他项目 | 不受影响。一个项目排除或脱钩，别的项目看到的还是公共库正本 |
| 备份与恢复 | 不变：两个字段跟着资产走，导出导入都是普通资产 |
| 数据库结构 | **无变化**，云端与本机都不用迁移 |

## 三、验收标准

每条都能用一次测试或一次手工验证判定。

1. 项目引用一个包后，取消勾选两条规则，项目规则列表里看不到这两条。
2. 重新打开那条引用记录，被取消的两条仍在列表里且能重新勾上；勾回后项目规则列表里重新出现。
3. 公共库给这个包新增一条规则，项目里没被排除的规则跟着出现，被排除的不会。
4. 对一条引用来的规则点「另存为项目规则」，项目里出现一条可编辑副本，且同一编号只出现一次
   （副本顶掉公共正本）。
5. 改这条副本，公共库那条不变，别的引用同一个包的项目看到的也不变。
6. 副本在列表里带「已脱钩」标记，打开时不出现「公共库那份在这之后改过」的提示。
7. 规则编译的候选集里包含脱钩副本、不包含被排除的规则，编译产物照常生成。
8. 升级前已有的项目，规则条数和升级前一致（老数据行为不变）。
9. `npm run check` 通过。

## 五、需要拍板的五个决定

**2026-09-25 产品负责人确认：D1–D5 全部按推荐做法。**

| 编号 | 决定 | 本版做法（推荐） | 另一种做法 |
| --- | --- | --- | --- |
| D1 | 逐条挑规则怎么存 | 存**排除清单**，界面表现为勾选。好处：老数据不变；公共库以后新增的规则默认会进项目 | 存「选中清单」。好处是范围更死；代价是公共库新增规则时项目不会自动拿到，要手动再挑一次 |
| D2 | 在哪里挑 | 装包时的预览面板逐条勾选（默认全选）+ 装完后打开引用记录再调整 | 只在装完之后调整。省一处界面改动，但装完先涌进一堆再逐条删，用起来更烦 |
| D3 | 怎么区分「主动脱钩的副本」和「老数据遗留的副本」 | 脱钩时在副本元数据写脱钩标记，带标记的副本优先；老副本（无标记）继续被公共正本顶掉 | 不区分，装包时一律不复制副本。差别是老项目的历史数据要另行处理 |
| D4 | 脱钩后还提不提示上游更新 | **不提示**，只标明「已脱钩，不受公共库影响」 | 继续提示。但这等于「脱钩了还联动」，说法会互相打架 |
| D5 | 要不要做「改回引用公共库」的一键回退 | **本版不做**，界面上写清手工路径（删副本 → 打开引用包重新勾上） | 做一键回退。更省心，但要再定一套「副本归档还是删除」的语义，本版不做，等真觉得麻烦再加 |

## 设计偏差

1. **脱钩的纯逻辑放在 `src/lib/rule-reference.ts`**，设计里写的是 `src/lib/asset-draft.ts`。
   理由：脱钩标记的读取优先级和排序逻辑都在 `rule-reference.ts`，放一起不用来回跳；
   `asset-draft.ts` 管的是编辑器草稿，不带这种读取语义。
2. **任务 3（规则编译）没有改代码**：设计里说要在 `src/lib/rule-compile.ts` 上做改动，
   实施时读代码发现候选集按调用方传进来的引用标识计算，排除清单在
   `listProjectRulesForUse` 这一层已经生效，编译这一层不用再改一遍。
3. **脱钩副本不继承资产关系**：原关系指向公共库那份的资产标识，搬进项目是断的，
   所以副本的 `relations` 清空，需要时自己重建。设计里没写这一条。
