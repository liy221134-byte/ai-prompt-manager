# 项目图谱设计（v2.5.0）

## 文档状态

- 目标版本：`v2.5.0`，主题是「给项目建一棵可维护的上下文树，并看清改动会波及谁」。
- 状态：**待产品负责人确认**；按 2026-09-23「其余迭代该做就做」的授权，
  下面标「按建议执行」的地方先按推荐做法推进。
- 对应 [2.0 需求草案](../../v2-requirements-draft.md) 的「项目上下文图谱」第一层
  （需求树、模块树、数据库树、人工映射、基础影响分析）。
- 上游：资产、关系、规则包、编译都已经可用，图谱是它们之上的组织层。

## 一、做什么 / 不做什么

### 做什么

1. **图谱节点资产**（新资产类型 `graph_node`）：
   - 节点类型：需求、模块、数据、接口、测试五类。
   - 稳定编号：例如 `REQ-001`、`MOD-003`、`TBL-002`；同一个项目、同一类型内编号唯一，
     重复时保存被拦下并给中文提示。资产标识和编号分开，改编号不影响引用。
   - 父节点：树结构用父节点串起来（父节点限定同类型，避免需求树里挂一个数据表）。
   - 正文写节点说明（需求的验收条件、模块职责、字段含义等），另有一个备注字段。
2. **项目图谱视图**：工具栏「项目图谱」打开抽屉——
   - 顶部按类型切换（需求／模块／数据／接口／测试），显示每类节点数；
   - 左侧是树（按编号排序，父子缩进）；
   - 选中节点后看详情：编号、完整路径、说明、**直接关系**（这个节点指向谁）、
     **被谁引用**（谁指向它）、**间接影响**（沿依赖链再走一层，写清是通过谁串起来的）。
3. **人工映射**：映射继续用现有的资产关系（引用／依赖／替代／实现），
   图谱视图只读展示，并提供「去编辑」跳到节点编辑器补关系。
4. **影响分析**：直接一层 + 间接一层，每条都能点开对应的资产或节点。

### 不做什么

- 不自动导入数据库 Schema、不自动分析代码模块（那是 Agent 连接那一版）。
- 不自动猜映射关系（不替人判断「这条需求属于哪个模块」）。
- 不做图形化的数据流视图和追踪矩阵，这一版是树 + 影响清单。
- 不做全图遍历和影响等级评分：只到两层，避免给出不可信的结论。
- 不做图谱导出和分享。

## 二、数据和产品行为影响

### 新增内容

- 资产类型 `graph_node`（本地和云端都不用改表结构，`asset_type` 是文本字段）。
- 节点元数据：`nodeType`（五类之一）、`code`（稳定编号，可为空但要唯一）、
  `parentId`（父节点标识，可为空表示根）、`note`（备注），关系沿用通用字段。
- 类型筛选新增「图谱节点」；编辑器按节点类型渲染字段；详情显示编号、类型和路径。

### 行为影响

- 编号唯一是**保存时校验**：同一个项目、同一类型里编号重复就拦下，给「编号已被 X 使用」的提示。
- 图谱视图是只读视图 + 跳转，不改数据；建节点和建关系还是走既有编辑器。
- 影响分析只读现有关系，不新增关系类型。

## 三、验收标准

1. 能新建图谱节点：选类型、填编号、选父节点（只能选同类型的节点），
   同一项目同一类型里编号重复时保存被拦下并给中文提示。
2. 类型筛选能筛出图谱节点；详情显示编号、类型和完整路径（父链）。
3. 项目图谱视图按类型切换，树里父子缩进正确，归档和垃圾箱里的节点不出现。
4. 选中节点后能看到直接关系、被谁引用、间接影响三块清单，间接影响写清是通过谁串起来的。
5. 在编辑器里给节点建一条关系后，图谱视图和影响分析立刻能看到。
6. 清单里每条都能点开对应的资产或节点。
7. `npm run check` 通过（类型检查、自动化测试、lint、生产构建）。

## 五、需要你拍板的三个决定（先按建议执行）

1. **节点怎么建模**：一个资产类型 `graph_node` + 节点类型字段（不拆成需求／模块／数据三个类型）。
2. **树结构用父节点标识**：父节点只能选同类型的节点，避免需求树下挂数据表。
3. **影响分析只做两层**：直接一层 + 间接一层，不做全图遍历，也不给影响等级评分。
