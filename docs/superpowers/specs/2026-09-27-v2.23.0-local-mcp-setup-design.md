# v2.23.0 设计 + 任务清单：本机 MCP 自动接入（只支持 Codex）

背景：待排期第 4 条里，MCP 批量入库（`import_documents`／`import_graph_nodes`）v2.16.0 已经做了，
自动分流的建议也有了（判据就是刚修好的沉淀体检）。剩下没做的是**「本地 MCP 自动接入」**——
现在要让 AI 用上这个库，得自己往 `~/.codex/config.toml` 里手写一段。

产品负责人 2026-09-27 定的范围：**本机模式下、只支持 Codex、改前备份、一键撤销、改完起一次
连接验证**（对应此前方案 C）。

## 一、做什么 / 不做什么

### 做什么

1. **一个「接入本机 MCP」面板**（本机模式的项目视图「更多」里），四件事：
   - 显示目标配置文件路径、当前是否已接入、接入的那段现在长什么样；
   - **接入**：改前先把原文件备份，再写入或更新 `[mcp_servers.ai-prompt-manager]` 这一段；
   - **撤销**：有备份就恢复备份；没有备份就只把这一段删掉，别的原样保留；
   - **验证**：真的起一次 MCP stdio 连接，列出工具，把结果和耗时报出来。
2. **只支持 Codex 一个工具**，路径按 Codex 自己的规则取：优先环境变量 `CODEX_HOME`，
   没有就用 `~/.codex/`，文件名固定 `config.toml`。
3. **幂等**：那一段已经存在且内容一致就什么都不做，直接告诉人「已经接好了」；
   存在但内容不同时，先把两边的差异摆出来，由人决定是覆盖还是不动——不静默覆盖。
4. **只碰这一段**：`config.toml` 里别的表、别的 MCP、模型和密钥一律不动。
5. **云端模式没有这个入口**：接口用项目已有的 `rejectLocalApiInCloudMode` 拦住，
   和 `/api/code-scan` 一个口径。

### 不做什么

1. 不支持 Claude Code、Cursor 等别的工具的配置——等真有人用再加，现在只做 Codex。
2. 不做「自动发现你装了哪些 AI 工具」。
3. 不自动改模型、密钥、别的 MCP 服务器，也不动 `.env` 一类的文件。
4. 不引 TOML 解析依赖：这个操作只涉及「定位一个表头到下一个表头之间的范围」，
   用最小文本处理，测试覆盖边界（文件为空、表在开头、表在末尾、表后面还有别的表）。
5. 不改本产品的数据表结构。
6. 不在云端模式下暴露任何相关接口。

## 二、数据和产品行为影响

**本产品的数据**：不改表、不加字段。

**你的电脑**：会在你本机创建和修改两个文件——

| 文件 | 什么时候有 | 内容 |
| --- | --- | --- |
| `~/.codex/config.toml` | 点「接入」或「撤销」时 | 只增删 `[mcp_servers.ai-prompt-manager]` 这一段 |
| 同目录下的 `config.toml.bak` | 每次点「接入」时 | 改之前的原文件副本，用来撤销。**名字固定**，下次接入直接覆盖它，只保留最近一次改前的状态 |

**行为边界**：

- 云端模式（Vercel + Supabase）下这个面板不出现；接口也拒绝，返回「只能在本机模式下使用」。
- 写入的是**订阅命令**（`npm --prefix <仓库根> run mcp`），不是内联密钥，所以文件里不会多出密钥。
- 「验证」会起一个子进程跑 MCP 服务，走只读模式（`MCP_READ_ONLY=1`），有超时上限，不会卡住界面。

## 三、验收标准

每条都能用一次自动化测试或一次手工操作判定。

1. 文件里没有这一段时，计划是「新增」，生成的内容能被 TOML 解析，且指向本仓库。— 测试
2. 文件里已有这一段、内容一致时，计划是「不动」。— 测试
3. 文件里已有这一段、内容不同时，计划是「覆盖」，并且把差异列出来。— 测试
4. 撤销时有备份就恢复备份、无备份就只删这一段；
   备份文件名固定是 `config.toml.bak`，反复接入不会堆出多份备份。— 测试
5. 表在文件开头、在中间、在末尾三种位置都能正确定位并替换。— 测试
6. 处理前后，这一段之外的每一行都逐字节不变。— 测试
7. 本机模式下点「接入」：`config.toml` 多出那一段、旁边生成备份、别的段没变。— 手工
8. 点「验证」：能看到 MCP 的工具清单（当前 11 个），并显示耗时；服务连不上时给出可读的失败原因。— 手工
9. 点「撤销」：文件回到改前的内容。— 手工
10. 云端模式下这个入口不出现；直接调接口返回「只能在本机模式下使用」。— 手工
11. 完整检查通过：`npm run check`（类型检查、全部测试、代码检查、生产构建）。— 自动化
