# v2.15.0 立项起步包：设计 + 任务清单

## 来源

链路断点评估里的 G7／G8／G12／G10（见 [从沉淀到立项：链路断点评估](../../project-lifecycle-gaps.md)）：
新项目立项时不知道该装哪些公共资产、没有立项提示词、交不出一个整包、
反复编译会攒出一堆同名产物。产品负责人 2026-09-24 指示「直接全都做完」，
本文记录**已按建议执行的取舍**，如与预期不符可直接改实现。

## 一、做什么 / 不做什么

### 做什么

1. **按等级推荐该装哪些公共资产**（G7）：工程基线里新增「建议从公共库装这些」——
   按项目质量等级挑出**还没装过**的规则（必须／禁止优先）、产物模板和方法级参考文档，
   每条写明推荐理由，一个按钮全部装进项目。已经装过的（同类型同标题）不再列出。
2. **立项提示词包**（G8）：新面板「立项与交付」，四条提示词分别对应
   需求（PRD）、实现规格（Spec）、技术档案、验收清单；每条都带上项目名、项目说明、
   质量等级和已定技术栈，一键复制给任意 AI 用（**产品不调用 AI**）。
3. **导出开发体系包**（G12）：把项目当前生效的内容按「规则 → 文档 → 模板」拼成
   一份 Markdown，可以下载，也可以一键存成项目里的一份文档（便于版本留痕）。
   不做 ZIP：单文件最容易核对和转发。
4. **编译产物改成"更新这一份"**（G10）：同一个项目里已有同名编译产物时，
   再次保存走**更新**（产生新版本、旧内容留在历史里），不再新建一条文档资产。

### 不做什么

- 不自动装资产：推荐只是清单，装不装由人点。
- 不做 ZIP 打包、不做导出格式版本号（单文件 Markdown，够用就行）。
- 不调用 AI：提示词只负责复制给人。
- 不改表结构。

## 二、数据和产品行为影响

| 项 | 影响 |
| --- | --- |
| 数据库结构 | 无变化 |
| 推荐 | 只读计算，不写数据 |
| 一键装 | 走「从公共资产库挑资产」同一条复制路径（按来源去重、只新增不覆盖） |
| 立项提示词 | 只复制文本，不写数据 |
| 开发体系包 | 下载不写库；「存成文档」在项目里新增或（同名时）更新一条文档资产 |
| 编译产物 | 同名产物由「新建」改为「更新」，历史版本仍可恢复 |

## 三、验收标准

1. 工程基线里能看到建议清单，每条有理由；点「把这 N 条装进项目」后清单里减少对应条目。
2. 已经装过的资产不再出现在建议里。
3. 立项与交付面板里有四条提示词，每条能复制，内容包含项目名与项目说明。
4. 能下载开发体系包，文件按规则／文档／模板分节，别的项目的资产不在里面。
5. 「存成项目里的一份文档」后，项目文档里出现这份包。
6. 同一个项目里第二次编译同一产物，走更新（不新增同名文档），旧内容能在版本记录里找到。
