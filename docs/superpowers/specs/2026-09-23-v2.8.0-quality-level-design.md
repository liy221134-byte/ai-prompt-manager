## 一、做什么 / 不做什么

### 做什么

1. **项目质量等级**：项目上加一个一级属性，四档——个人工具、低风险生产、涉及用户数据、高敏感项目。
   新建项目时选，已有项目按「个人工具」读，不用回头改老数据。
2. **等级对应的要求清单**（只读展示，不自动创建）：
   - 这个等级**必须有**哪些工程文档（对应第四节那八份）；
   - 这个等级**建议关注**哪些规则方向（例如涉及用户数据要有 RLS、备份和回滚）；
   - 这个等级**发布前必须完成**哪些检查（工程检查、迁移演练、备份、回滚目标、发布后验证）。
3. **项目工作区里能看到缺口**：按等级对照现有资产，列出「已有／缺失」，
   缺失项给一个「新建文档」入口，预填文档类型和标题，正文默认带出对应模板（模板已导入时）或留空。
4. **八份工程文档模板进仓库**（已完成）：
   架构与请求链路、数据流、环境变量清单、发布与回滚、备份与恢复、安全检查、故障处理手册、
   成本与性能基线。用现有的「导入模板」装进项目，内容门禁由测试守住。

### 不做什么

- 不做验收证据链（v2.9.0）。
- 不做发布门禁的执行记录和故障演练记录（v2.10.0）：这一版只给「要求清单」，不做「完成证据」。
- 不自动创建文档：缺口只给入口和预填，保存仍然由你点。
- 不做第三方安全扫描、合规检查、成本采集：这些要连外部服务，不在这一版。
- 不按等级自动装规则包：只提示「建议关注」，装不装你定。

## 二、数据和产品行为影响

- **项目表加一列**：`risk_level`（文本，取值 `personal`／`low_risk`／`user_data`／`high_sensitive`），
  默认 `personal`。本机 SQLite 自动迁移；线上 Supabase 需要跑一次迁移文件。
- **线上影响（必须先说清）**：Vercel 跟着 `main` 自动部署，代码上线后如果线上库还没这一列，
  **线上「项目设置」保存会报错**。两种做法请选一个：
  - **做法 A（推荐）**：这一版连迁移一起做。我提供迁移文件，你在 Supabase 上执行一次
    （或者给我 Supabase MCP／数据库密码，我来跑）；跑完再让代码上线。
  - **做法 B（更稳）**：先只在本机启用。线上读不到这一列就按「个人工具」，写入端在线上
    暂时不写这一列，等哪次你方便跑迁移了再打开线上写入。代价是线上线下行为短暂不一致。
- **备份兼容**：老备份没有这个字段，导入时按「个人工具」处理，不报错。
- **模板是内容不是数据**：八份模板放在仓库里，用「导入模板」装进项目，将来改文案不需要迁移。

## 三、验收标准

1. 新建项目时能选质量等级；已有项目默认是「个人工具」，可以改。
2. 项目工作区能看到这个等级的要求清单，包含「必须有哪几份文档」「建议关注哪些规则方向」
   「发布前必须完成哪些检查」。
3. 要求清单按现有资产算出「已有／缺失」，缺失项点「新建文档」能带着文档类型和标题进编辑器。
4. 八份工程文档模板能用「导入模板」一次性装进项目，装完在模板列表里能看到。
5. 老备份、老项目数据读进来不报错，等级按默认值处理。
6. 等级改动写进版本记录，能看出什么时候改的。
7. `npm run check` 通过。

## 六、设计偏差（实施后填）

1. **要求清单做成了抽屉，不是工作区面板**：工具栏「工程基线」打开抽屉，
   和项目图谱、导入工程的交互保持一致；项目设置里只放等级选择。
2. **「新建文档」只预填标题和文档类型，不带正文**：模板正文要用户自己从
   `templates/engineering` 复制。原因是模板还没进项目库时读不到内容，
   强行塞一段空正文反而容易误以为写过了。
3. **「已有」的判定口径收紧了**：只认「活跃、没进垃圾箱」的文档资产，
   草稿和归档不算已有。理由是草稿还不算成文，归档表示不再维护；
   这条口径写在面板底部，避免用户猜。
4. **项目没有版本历史**：设计里写的「等级改动写进版本记录」没有实现，
   项目本身没有版本表，改成「更新项目更新时间，界面即时生效」。
   要真正的版本记录得给项目加版本表，那是另一个改动。
5. **文档类型新增七个**：架构说明、数据流说明、环境变量清单、备份说明、
   安全检查、故障手册、成本与性能（发布与回滚复用已有的「发布手册」）。
6. **顺带修了一个真 bug**：导入文档包时创建项目没带质量等级字段，
   本机写库会失败（测试跑出来的）；已补上默认值。
