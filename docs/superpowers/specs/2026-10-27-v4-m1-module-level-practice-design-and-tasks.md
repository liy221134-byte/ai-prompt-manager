## 一、先解决三个设计问题

### 问题 1：M1 的矩阵不是「诊断矩阵」，别混

诊断矩阵 = 「你在这一层能不能站住」，需要每个格子有足够题量 + 严格的层级判定规则，那是 **M2** 的事。

M1 能显示的是**练习覆盖矩阵**，每格三件事：

| 显示 | 来源 |
| --- | --- |
| 该格有几道题 | `count(practice_questions) where module_id=? and level=?` |
| 你做过几道 | `practice_attempts` 按 question_id 去重 |
| 正确率 | `practice_attempts.is_correct` |

**为什么必须分开**：M1 阶段 S5 只有 3 道题、S6 只有 2 道，拿这个算「诊断层级」就是重新犯一次
首次诊断卷犯过的错（单题定生死）。**M1 只说「覆盖了多少、做得怎么样」，不说「你在第几层」。**

### 问题 2：题量不够时，界面必须敢说「这层没题」

首次诊断的教训：S4 只有 1 道 L1 题，错一题就判「未过 L1」。M1 的规矩：

- 某格 `题数 = 0` → 显示「未出题」，不可点击，不参与任何比率计算。
- 某格 `题数 < 3` → 显示题数并用浅色标注「题量不足，练习结果仅供参考」。

**每模块每层 ≥3 题是 M1 的验收条件之一**，但在题库补完之前，界面不能假装数据是够的。

### 问题 3：145 道题还要不要一次性拉？

现有 `/practice` 的做法是**客户端一次拉全量 135 题**。M1 沿用这个做法，理由是：

- 145 题 × 平均 ~2KB ≈ 300KB，一次拉完，与现状同一量级；
- 改成按需分页要动现有取数链路，属于「可做但没必要」，会碰回归风险。

**上限与升级路径（写进代码注释）**：题量超过 ~600 道时，改成按 `module_id` 分次拉取。
这个数不是拍的——单次请求 >1MB 时首屏会明显变慢。

## 二、做什么 / 不做什么

### 做什么

1. **新增 `/learning` 一页**：中项主题页，上下两块——顶部关键节点、下方 6×5 矩阵。
2. **点格子进练习**：点某个「模块 × 层级」，直接在该页进入两栏练习（复用 `PracticeQuiz`），
   题池只含该格子的题。
3. **练习入口加一条**：`/practice` 顶部加入口链到 `/learning`，**不改现有任何筛选逻辑**。
4. **关键节点倒计时**：距考试天数 + 报名窗口提示。
5. **题库补到每格 ≥3 题**：29 KP × 5 层 = 145 题。**代码与内容并行，不阻塞开发**。

### 不做什么

- **不做诊断**（M2）：不出层级判定、不写 `learning_diagnostics`、不做 AI 归因
- **不做自适应**（M3）：不按答题结果动态调难度
- **不做出题界面**：题库靠主题包导入，不提供网页录入
- **不改 `/practice` 的任何筛选、错题重练、两栏布局、随机练习**
- **不做多主题**：`/learning` 直接是单主题页，不做主题列表
- **不动表结构**：本版零迁移

### 关键节点放在哪：`exam_facts`，不新建列

倒计时需要结构化日期，但 `registration_expected: "2027-03下旬"` 是字符串，算不出天数。
**不新增列**，把节点塞进已有的 `exam_facts`（jsonb）：

```yaml
exam_facts:
  subjects: [...]
  milestones:
    - { name: 报名开放,   date: "2027-03-20", note: "山东窗口约 10-20 天，无补报" }
    - { name: 准考证打印, date: "2027-05-10" }
    - { name: 考试,       date: "2027-05-22" }
```

理由：`exam_facts` 本来就是 jsonb、本来就存考试相关事实，加一个键**零成本**；
新建列要写迁移，而迁移在这个环境里得你手动去 SQL Editor 执行（今天已经卡过一次），不值得。

**这条要写进 `topic-pack-schema.md`**，否则下一个人不知道 `milestones` 是约定出来的。

## 四、验收标准（每条都能一次判定）

1. 登录后从 `/practice` 顶部能进 `/learning`，页面显示中项主题名与目标。
2. 矩阵 6 行 × 5 列，每格显示「已做 / 总题数」，空格显示「未出题」且不可点击。
3. 点任一有题的格子，进入练习模式，**题池只含该模块该层的题**（界面上能核对第一题的层级标签）。
4. 答题后返回矩阵，该格的「已做」数 +1（刷新后仍在）。
5. 顶部显示「距考试 N 天」，N 与 `deadline` 差值一致；报名节点按 `milestones` 显示。
6. 题库覆盖：`select module_id, level, count(*) ... group by 1,2` 结果里 **145 个格子无空缺**。
7. **现有 `/practice` 不回归**：分类分组、题型筛选、状态筛选、错题重练、随机练习全部照常。
8. `npm run check:fast` 通过。
9. **界面改动真在浏览器里看过**：矩阵渲染、点格子进练习、答一题回矩阵，三步各截图一次。
