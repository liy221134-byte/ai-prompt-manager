# 2.0.1 文档包导入与元数据编辑（设计 + 任务清单）

## 文档状态

- 目标版本：`2.0.1`（排在 `2.1.0` 之后发布）。
- 前置条件：`2.1.0` 合并并签完验收；规则和文档已能新增、编辑、归档。
- 状态：设计已确认（2026-09-22），第六节的三个问题已拍板，可以开始实现。
- 本文只写决定，不写 SQL、完整代码和实现步骤。

## 一、做什么与不做什么

### 做什么

- 上传 Markdown、纯文本或 ZIP 文档包，保留原始文件。
- AI 识别文档包，生成「项目创建草稿」和「资产清单草稿」，由用户确认后才创建。
- 草稿预览里可以改资产类型、合并、拆分、跳过，也可以改项目名称和目标。
- 规则补齐完整元数据：规则类型、用途、适用范围、作用层级、技术上下文、执行阶段、
  优先级、生命周期、覆盖权限、来源证据、验证方式。
- 文档补齐完整元数据：文档类型、文档角色、是否权威来源、所属模块、生效版本、
  来源位置、更新触发条件、新鲜度和最后验证时间。
- 技术档案之外的元数据编辑在界面上可写可改，界面只强制填核心字段。

### 不做什么

- 不做规则冲突编译，不生成最终 `AGENTS.md`。
- 不做文档与规则的完整协作路径。
- 不做需求、模块、代码、数据和 Bug 图谱。
- 不接 MCP 动态查询。
- 不由 AI 在后台自动创建项目或自动激活资产。
- 不用 AI 摘要覆盖原文。

## 二、数据和产品行为影响

### 上传与原文保留

- 用户主动点击后才开始分析，不分析就直接保存原文。
- 原始文件作为「来源包」资产保存，保留文件名、上传时间、大小和内容。
- 原文不进日志，只有用户主动点击时才把内容发给 AI 服务。
- 来源包只保留模型能力，不开放编辑。

### 存储位置

- 本地模式：原始文件存在项目数据目录下的来源目录里，资产里记录相对路径。
- 云端模式：原始文件存在 Supabase Storage 的私有空间，按用户隔离。
- 两边的资产语义一致：来源包资产记录来源文件信息，不把二进制塞进资产正文。

### 草稿与确认

- AI 输出只是草稿，不写正式资产、不建正式项目、不激活 AI 提取的规则。
- 草稿预览必须展示：建议的项目名称和目标、识别到的资产数量和类型、每个文件的
  分类建议、识别到的技术栈和约束、候选规则、以及无法识别或冲突的文件。
- 用户可以逐条改类型、合并、拆分、跳过，确认后才一次性创建项目与资产。
- 确认创建后，每个资产都产生第 1 版，来源指向对应的来源包。

### 元数据

- 规则和文档的元数据都存在资产元数据字段里，不新增表。
- 核心字段必填，扩展字段可以留空，界面不因为扩展字段为空而拦截保存。
- 元数据变更和正文变更一样产生新版本，历史不覆盖。
- 现有规则和文档的旧元数据要能读出来，缺字段按空值处理，不做强制补齐。

### 生命周期

- AI 提取的规则默认是「草稿」状态，需要用户手动改成「活跃」。
- 导入产生的来源包资产在项目归档后仍然保留。

## 三、验收标准

- 上传 Markdown、纯文本和 ZIP 都能成功，原始文件被完整保留且可下载查看。
- 上传后先看到草稿预览，**确认前不创建项目、不写入资产**。
- 预览里可以改类型、合并、拆分和跳过，确认后结果与预览一致。
- AI 提取的规则创建后是草稿状态，不会自动进入活跃列表。
- AI 摘要不覆盖原文，来源包里的内容与上传文件逐字节一致。
- 规则可以保存用途、范围、层级、优先级和生命周期等完整元数据。
- 文档可以区分来源、工作稿、权威版和编译结果。
- 元数据修改会产生新版本，旧版本内容不被覆盖。
- 未登录不能上传文件，也不能读取别人的来源包。
- `npm run check` 全部通过。

## 四、任务顺序与预期改动

| 序号 | 任务 | 预期改动 |
| --- | --- | --- |
| 1 | 原始文件上传与来源包资产 | 上传接口、来源包存储、`src/lib/server/`、上传测试 |
| 2 | AI 识别与项目创建草稿 | 识别接口、草稿模型、`src/components/`、草稿测试 |
| 3 | 草稿预览与确认创建 | 预览组件、确认接口、端到端测试 |
| 4 | 规则完整元数据 | 规则元数据模型、编辑器、元数据测试 |
| 5 | 文档完整元数据 | 文档元数据模型、编辑器、元数据测试 |
| 6 | 导入演练与验收清单 | 导入测试、`docs/acceptance/` |

每个任务单独提交，完成后运行完整工程检查。云端存储相关的任务必须在迁移应用后验证。

## 五、关键决定

1. AI 只生成草稿，正式项目和资产由用户确认后才创建。
2. 原始文件完整保留，AI 摘要不覆盖原文。
3. 来源包只保留模型能力，不开放编辑。
4. 元数据存在资产元数据字段里，不新增表；核心字段必填，扩展字段可空。
5. AI 提取的规则默认草稿状态。

## 六、已确认的三个决定（2026-09-22）

1. 云端原文存放：用 Supabase Storage 私有空间，按用户隔离，保留二进制原件。
2. ZIP 文档包大小上限：单个包 20 MB，超出直接拒绝并提示。
3. 一次导入最多创建 200 个资产，超出要求分批。

这三条都涉及外部依赖或成本，已由产品负责人确认，实现时不再重复确认。
