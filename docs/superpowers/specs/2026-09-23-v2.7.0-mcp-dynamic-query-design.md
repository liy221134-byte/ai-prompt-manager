# MCP 动态查询设计（v2.7.0，待确认）

## 文档状态

- 目标版本：`v2.7.0`，主题是「让 AI 在干活时能直接查我的库，而不是只吃一份编译好的 AGENTS.md」。
- 状态：**待产品负责人确认**。这一版会引入新的对外接口和第三方依赖，按
  [项目规则](../../../AGENTS.md) 先写设计，等确认后再动代码。
- 上游：提示词、规则、文档、图谱节点、影响分析和规则编译都已经可用，
  这一版只补「查询入口」，不改数据模型、不做写入。
- 后面还剩「生产工程治理」（质量等级、验收证据链、发布门禁与演练模板），排在 MCP 之后。

## 一、为什么做、做什么、不做什么

### 为什么

现在把上下文交给 AI，只有一条路：在界面上点「规则编译」，复制或下载产物，再贴给别人。
每次改一条规则都要重来一遍。MCP 让 AI 在开发过程中自己查——
「这个项目有哪些必须遵守的规则」「这个需求节点改动了会波及谁」。

### 做什么

1. **本机 MCP 服务器**（一条命令启动，`npm run mcp`）：标准输入输出方式的 MCP 服务，
   只读当前本机库（和界面用的是同一个 SQLite 文件和同一套读逻辑）。
2. **六个只读工具**（先只做这些，够用就行）：
   - `list_projects`：有哪些项目。
   - `search_prompts`：按项目 + 关键词／标签搜提示词，返回标题、适用场景和正文。
   - `get_asset`：按资产标识取正文、元数据和关系（指向谁、被谁指向）。
   - `list_rules`：按项目取规则，可按作用层级／规则类型筛选，带理由和来源片段。
   - `list_graph_nodes`：按项目 + 节点类型取图谱节点（编号、标题、路径、备注）。
   - `analyze_impact`：按节点编号给出「指向谁 / 谁指向它 / 间接影响」。
3. **只读、只在本机**：不监听网络端口，不写数据，不需要账号和密钥。

### 不做什么

- 不做远程 MCP（不部署到 Vercel、不开对外端口）：个人工具，先不开鉴权面。
- 不做写操作：改资产仍然只在界面上做，AI 不能通过 MCP 新增或修改任何东西。
- 不读云端 Supabase 库：这一版只读本机库；云端留到以后真有需要再说。
- 不做提示词全文以外的日志：不记录查询内容。
- 不做鉴权和多用户：只有本机进程能跟它通信。

## 二、数据和产品行为影响

- **不改表结构、不改写入路径**：MCP 进程只调用现有的本地读逻辑（`src/lib/server/prompt-database.ts`）。
- **新依赖**：需要引入 `@modelcontextprotocol/sdk`（只用在本地脚本里，不进浏览器打包产物）。
  备选是自己写 stdio JSON-RPC，不引依赖，但要跟着协议版本自己维护，风险更大。
- **打开方式**：在 Codex／Claude Code 这类客户端的 MCP 配置里加一条本机命令，
  路径指向本仓库，不带任何密钥。
- **数据边界**：查到的内容会进对话上下文，和「复制编译产物贴给 AI」是同一件事，
  但查询由 AI 主动发起——这一点要在界面或文档里写清楚，避免误以为「什么都没发出去」。

## 三、验收标准

1. `npm run mcp` 能启动，客户端能连上并列出六个工具。
2. `list_projects` 返回本机库里真实存在的项目。
3. `search_prompts` 按关键词能搜到提示词，返回正文；搜不到时返回空列表并说明。
4. `list_rules` 能按作用层级筛选，返回的规则带理由和来源片段。
5. `analyze_impact` 对已导入的图谱节点返回「指向谁 / 谁指向它 / 间接影响」，
   和界面上看到的一致。
6. 任何工具都不会修改库：跑完一轮查询后，资产数量、更新时间和版本记录都不变。
7. 云端模式或没有本地库文件时，启动给出中文提示，不静默返回空数据。
8. `npm run check` 通过。

## 五、需要你拍板的三个决定

1. **只读够不够**：这一版只让 AI 查，不让 AI 写。写入仍然只在界面上做。
2. **本机 stdio，不做远程**：不开端口、不放 Vercel、不需要鉴权。
   代价是只有跑在这台机器上的 AI 客户端能用。
3. **引 `@modelcontextprotocol/sdk`**：本地脚本用官方 SDK；不加这个依赖就得自己维护
   协议实现（我不推荐，协议还在演进）。
