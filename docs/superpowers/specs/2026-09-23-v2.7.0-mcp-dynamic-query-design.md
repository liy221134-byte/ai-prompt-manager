# MCP 动态查询设计（v2.7.0，待确认）

## 文档状态

- 目标版本：`v2.7.0`，主题是「让 AI 在干活时能直接查我的库，而不是只吃一份编译好的 AGENTS.md」。
- 状态：**已确认**。2026-09-23 产品负责人拍板：**AI 也能写**、本机方式做、引官方 SDK。
  写入边界按下面第一节执行（只做可恢复的操作）。
- 上游：提示词、规则、文档、图谱节点、影响分析和规则编译都已经可用，
  这一版只补「查询入口」，不改数据模型、不做写入。
- 后面还剩「生产工程治理」（质量等级、验收证据链、发布门禁与演练模板），排在 MCP 之后。

## 一、为什么做、做什么、不做什么

### 为什么

现在把上下文交给 AI，只有一条路：在界面上点「规则编译」，复制或下载产物，再贴给别人。
每次改一条规则都要重来一遍。MCP 让 AI 在开发过程中自己查——
「这个项目有哪些必须遵守的规则」「这个需求节点改动了会波及谁」。

### 做什么

1. **本机 MCP 服务器**（一条命令启动，`npm run mcp`）：标准输入输出方式的 MCP 服务，
   读写当前本机库（和界面用的是同一个 SQLite 文件和同一套读写逻辑）。
2. **六个查询工具**：
   - `list_projects`：有哪些项目。
   - `search_prompts`：按项目 + 关键词／标签搜提示词，返回标题、适用场景和正文。
   - `get_asset`：按资产标识取正文、元数据和关系（指向谁、被谁指向）。
   - `list_rules`：按项目取规则，可按作用层级／规则类型筛选，带理由和来源片段。
   - `list_graph_nodes`：按项目 + 节点类型取图谱节点（编号、标题、路径、备注）。
   - `analyze_impact`：按节点编号给出「指向谁 / 谁指向它 / 间接影响」。
3. **三个写入工具**（只做界面上已经有的、可恢复的操作）：
   - `create_asset`：新建提示词／规则／文档／图谱节点／模板，只新增、不覆盖。
   - `update_asset`：改标题、正文、说明和各类元数据；没传的字段保持原样，每次都写一条新版本。
   - `set_asset_status`：改状态（草稿／待确认／活跃／已废弃／已归档）。
   - 写入的资产来源统一标成「AI」，你在界面上一眼能看出哪些是它写的。
4. **只在本机**：不监听网络端口，不需要账号和密钥；`MCP_READ_ONLY=1` 时只注册查询工具。

### 不做什么

- 不做远程 MCP（不部署到 Vercel、不开对外端口）：个人工具，先不开鉴权面。
- **不做删除**：没有删除、没有进垃圾箱、没有清空垃圾箱。界面本身也没给非提示词资产回收路径，
  AI 能做的永远只是你在界面上能做的，且不多一项。
- 不改技术档案：一个项目一份、结构特殊，先不开。
- 不改项目、不做规则编译、不做备份导出：这些继续在界面上做。
- 不读云端 Supabase 库：这一版只读本机库；云端留到以后真有需要再说。
- 不写日志：不记录查询和写入内容。
- 不做鉴权和多用户：只有本机进程能跟它通信。

## 二、数据和产品行为影响

- **不改表结构**：MCP 进程调用现有的本地读写逻辑（`src/lib/server/prompt-database.ts`），
  写入走和界面同一条路径（`createAsset`／`updateAsset`），版本、编号查重、状态语义完全一致。
- **新依赖**（已确认）：`@modelcontextprotocol/sdk` 和 `zod`，都放在开发依赖里，
  只被本地脚本使用，不进浏览器打包产物。
- **写入是安全的**：每次修改都产生不可变的新版本，旧版本留在历史里可以从界面恢复；
  没有删除入口，所以不存在「AI 把东西弄没了」这条路。
- **打开方式**：在 Codex／Claude Code 这类客户端的 MCP 配置里加一条本机命令，
  路径指向本仓库，不带任何密钥。
- **数据边界**：查到的内容会进对话上下文，和「复制编译产物贴给 AI」是同一件事，
  但查询由 AI 主动发起——这一点要在界面或文档里写清楚，避免误以为「什么都没发出去」。

## 三、验收标准

1. `npm run mcp` 能启动，客户端能连上并列出九个工具。
2. `list_projects` 返回本机库里真实存在的项目。
3. `search_prompts` 按关键词能搜到提示词，返回正文；搜不到时返回空列表并说明。
4. `list_rules` 能按作用层级筛选，返回的规则带理由和来源片段。
5. `analyze_impact` 对已导入的图谱节点返回「指向谁 / 谁指向它 / 间接影响」，
   和界面上看到的一致。
6. `create_asset` 新建的资产能在界面上看到，来源标成「AI」。
7. `update_asset` 改完正文后，界面历史版本里多一条，旧版本还在。
8. `set_asset_status` 归档后，这条资产不再出现在默认列表和查询结果里，但内容和历史版本都保留。
9. 工具清单里没有删除类工具；`MCP_READ_ONLY=1` 启动时只剩查询工具。
10. 找不到项目或资产时返回中文提示，不抛异常、不写坏数据。
11. `npm run check` 通过。

## 五、三个决定（2026-09-23 已拍板）

1. **AI 也能写** → 开放新建、编辑、改状态三类写工具；
   边界定为「只做界面上已有的可恢复操作」：没有删除、没有垃圾箱，每次修改都留版本。
2. **本机做** → 标准输入输出方式，不开端口、不放 Vercel、不需要鉴权；
   代价是只有跑在这台机器上的 AI 客户端能用。
3. **引官方 SDK** → `@modelcontextprotocol/sdk`（配 `zod`），不自己维护协议实现。

## 六、设计偏差（实施后填）

1. **工具从六个变成九个**：按「AI 也能写」的决定加了 `create_asset`、`update_asset`、
   `set_asset_status`；查询工具保持六个不变。
2. **多了一个只读开关**：`MCP_READ_ONLY=1` 时不注册写工具，客户端连看都看不到。
   这是给「今天只想让它查」留的开关，不是权限系统。
3. **写入来源标成「AI」**：新建的资产来源是 `ai`，界面上能一眼分辨。
4. **技术档案没开放写入**：一个项目一份、结构特殊，先不开放，改了会给出中文提示。
5. **关系仍然只能在界面上建**：MCP 没有建关系、改关系的工具；AI 要靠 `get_asset`
   和 `analyze_impact` 读关系，要改就去界面。这一版刻意不做，避免 AI 批量改映射。
6. **写入不做「先预览再确认」**：产品规则里那条「AI 结果先预览、我确认后再保存」是给
   界面上 AI 生成流程定的；MCP 是 AI 自己发起的写入，没法拦一道确认，
   改成靠版本历史和「没有删除入口」兜底。这一点如果和你预期不一致，说一声我改成
   「写工具先落草稿、你在界面上确认再激活」。
