# AI 提示词合并与垃圾箱设计

## 文档状态

- 版本目标：`v0.8.0`
- 状态：设计已确认，等待实现计划。
- 本文只定义产品行为、数据边界和技术原则，不替代实现计划。

## 目标

把 2 至 5 条相似提示词合并成一条更通用、更可复用的提示词，同时保证
原始内容可以被安全恢复。

核心流程：

```text
选择提示词
-> 填写可选合并要求
-> AI 生成合并草稿
-> 用户预览和编辑
-> 确认更新目标提示词
-> 来源提示词进入垃圾箱
```

## 本期范围

### 包含

- 选择 2 至 5 条提示词。
- 第一条选中项默认为目标提示词。
- 用户可以在保存前调整目标提示词。
- 可选“合并要求”输入。
- AI 提炼共性、互补内容、变量和冲突。
- AI 返回标题、分类、标签、适用场景、正文和合并说明。
- 合并结果必须由用户预览和确认。
- 目标提示词原内容保存为恢复快照。
- 其他来源提示词进入垃圾箱。
- 垃圾箱支持恢复、彻底删除和清空。
- 垃圾箱和恢复快照默认保留 30 天。
- 云端每天自动清理过期数据。
- 本地模式在启动时自动清理过期数据。

### 不包含

- 单条提示词详情中的独立 AI 标签优化。
- 完整版本历史界面。
- 版本差异比较。
- 提示词分支和合并树。
- 永久撤销。
- 通用规则生命周期引擎。
- 自动更新外部项目文档或代码。

## 用户交互设计

### 进入合并

提示词库工具栏增加“AI 合并”入口。

点击后进入选择模式：

- 卡片显示复选框。
- 最多选择 5 条，至少选择 2 条。
- 第一条选中项显示“目标”标记。
- 用户可以点击其他已选卡片上的“设为目标”。
- 选择数量不满足要求时不能进入下一步。

### 合并面板

合并面板显示：

- 已选提示词的标题、分类、标签和适用场景摘要。
- 目标提示词标记。
- 可选“合并要求”文本框。
- “生成合并草稿”按钮。
- 生成失败后的错误信息和重试入口。

“合并要求”示例：

```text
合并成通用版本
保留严格的输出格式
不要包含某个模型平台的限制
尽量保留可替换变量
```

### 合并结果

AI 生成后显示可编辑草稿：

- 标题。
- 分类。
- 标签。
- 适用场景。
- Markdown 正文。
- AI 合并说明。

合并说明展示：

- 提炼出的共性。
- 保留的互补内容。
- 处理过的冲突。
- 变量重命名或统一情况。

用户可以修改所有字段，但合并说明只读。

### 保存

保存按钮必须明确显示影响，例如：

```text
更新《目标标题》并归档 2 条来源
```

点击保存前不修改任何数据。

保存成功后：

- 目标提示词更新为合并结果。
- 来源提示词进入垃圾箱。
- 目标提示词的合并前内容保存为恢复快照。
- 页面显示“已合并，来源可在垃圾箱恢复”的提示。

## 垃圾箱设计

### 普通删除

现有删除操作改为软删除：

- 提示词从普通列表移除。
- 提示词进入垃圾箱。
- 记录删除时间和删除原因。
- 用户可以恢复或彻底删除。

### 合并归档

AI 合并时：

- 来源提示词写入垃圾箱。
- 来源记录 `merged_into_prompt_id`，用于说明它被合并到了哪里。
- 目标提示词合并前内容生成恢复快照。

### 垃圾箱界面

垃圾箱以抽屉或对话框展示：

- 提示词标题、分类、标签。
- 删除时间。
- 删除来源：手动删除或 AI 合并。
- 剩余保留天数。
- 恢复按钮。
- 彻底删除按钮。
- 清空垃圾箱按钮。

垃圾箱还展示“合并恢复记录”：

- 目标提示词标题。
- 合并时间。
- 来源提示词数量。
- 恢复合并前版本按钮。
- 彻底删除恢复记录按钮。

### 恢复语义

恢复被删除的来源提示词时：

- `deleted_at` 清空。
- `deleted_reason` 清空。
- `merged_into_prompt_id` 清空。
- 提示词重新出现在普通列表。

恢复合并前版本时：

- 目标提示词恢复为快照内容。
- 该次合并的来源提示词恢复为普通提示词。
- 当前合并结果被替换。
- 恢复操作需要用户明确确认。
- 恢复目标、恢复来源和更新快照状态必须在一次事务中完成。

### 永久删除

- 彻底删除不可恢复。
- 清空垃圾箱需要明确确认。
- 超过 30 天由清理任务删除。
- 云端实际清理时间允许晚于 30 天，最长不超过下一次每日任务。
- 本地模式只在应用启动时检查过期数据。

## 数据模型

### `prompts` 扩展字段

| 字段 | PostgreSQL 类型 | 说明 |
| --- | --- | --- |
| `deleted_at` | `timestamptz` | 为空表示正常，非空表示在垃圾箱 |
| `deleted_reason` | `text` | `manual` 或 `merge` |
| `merged_into_prompt_id` | `text` | AI 合并目标的稳定标识 |
| `merge_version_id` | `text` | 本次 AI 合并的恢复快照标识 |

新增索引：

```text
prompts_user_deleted_idx (user_id, deleted_at)
```

普通列表查询必须包含：

```text
deleted_at is null
```

垃圾箱查询必须包含：

```text
deleted_at is not null
```

### `prompt_versions` 表

这张表保存合并前恢复快照。本期不把它完整暴露为版本历史界面。

| 字段 | PostgreSQL 类型 | 说明 |
| --- | --- | --- |
| `user_id` | `uuid` | 所属用户，关联 `auth.users.id` |
| `version_id` | `text` | 快照稳定标识 |
| `prompt_id` | `text` | 被恢复的目标提示词标识 |
| `title` | `text` | 合并前标题 |
| `category` | `text` | 合并前分类 |
| `tags` | `text[]` | 合并前标签 |
| `content` | `text` | 合并前 Markdown 正文 |
| `use_case` | `text` | 合并前适用场景 |
| `created_at` | `timestamptz` | 快照创建时间 |
| `version_reason` | `text` | 本期固定为 `merge_before` |
| `source_prompt_ids` | `text[]` | 本次合并的来源提示词 |
| `restored_at` | `timestamptz` | 恢复时间，未恢复时为空 |
| `expires_at` | `timestamptz` | 快照过期时间 |

主键：

```text
(user_id, version_id)
```

索引：

```text
prompt_versions_user_prompt_idx (user_id, prompt_id, created_at desc)
prompt_versions_user_expires_idx (user_id, expires_at)
```

`prompt_versions` 必须启用 RLS，并只允许用户访问自己的记录。

### 本地 SQLite

本地模式实现等价结构：

- `prompts` 增加三个字段。
- 新增 `prompt_versions` 表。
- 建立相同用途的索引。
- 数据库升级必须保持现有数据不丢失。

## 合并提交语义

保存合并结果必须作为一次原子操作执行。

云端模式使用一个 PostgreSQL 函数完成：

1. 校验当前用户。
2. 校验目标提示词属于当前用户。
3. 校验所有来源提示词属于当前用户。
4. 显式拒绝 `NULL` 或空来源数组，并校验来源数量为 2 至 5，且包含目标。
5. 在事务中读取锁定后的目标提示词，由服务端创建合并前快照。
6. 更新目标提示词。
7. 将其他来源提示词写入垃圾箱。
8. 写入 `merged_into_prompt_id`。

本地模式使用 SQLite 事务完成同样步骤。

客户端只提交稳定 `versionId`。快照中的标题、分类、标签、正文和适用场景必须从
事务内读取到的目标行生成，客户端提供的恢复内容不得进入快照。

任何一步失败时，整次操作回滚。

PostgreSQL 函数使用 `SECURITY INVOKER`，不得通过
`SECURITY DEFINER` 绕过 RLS。

云端清空垃圾箱使用单个 `empty_prompt_trash()` RPC，在同一事务中删除当前用户的
恢复快照和垃圾箱提示词；本地清空使用同一 SQLite 事务完成等价操作。

## AI 合并接口

接口：

```text
POST /api/ai/merge-prompts
```

输入：

```json
{
  "prompts": [
    {
      "id": "prompt-1",
      "title": "标题",
      "category": "分类",
      "tags": ["标签"],
      "content": "正文",
      "useCase": "适用场景"
    }
  ],
  "mergeInstruction": "可选合并要求"
}
```

输出：

```json
{
  "draft": {
    "title": "合并后的标题",
    "category": "产品设计",
    "tags": ["标签"],
    "content": "合并后的正文",
    "useCase": "适用场景",
    "mergeSummary": [
      "提炼的共性",
      "处理的冲突"
    ]
  }
}
```

接口规则：

- 必须登录。
- 只接受 2 至 5 条提示词。
- 每条正文最多 20000 个字符。
- 全部正文合计最多 40000 个字符。
- 超限时返回明确错误，不静默截断。
- 用户提示词作为数据传入，不作为系统指令执行。
- AI 输出必须经过结构化校验。
- 标签使用现有标签清理规则。
- 变量保持 `{{变量名}}` 格式。
- AI 不得直接写数据库。

## 数据源接口

`PromptDataSource` 增加：

```text
fetchTrash
restorePrompt
permanentlyDeletePrompt
emptyTrash
commitAiMerge
fetchMergeRecoveryRecords
restoreMergeRecord
```

现有 `fetchLibrary` 只返回未删除提示词。

`commitAiMerge` 输入只包含合并结果、来源标识和客户端生成的 `versionId`，不包含
客户端生成的快照内容。备份导入预览与实际导入必须使用相同的垃圾箱过滤结果：
已经在垃圾箱中的标识显示为“跳过”，不会被显示为新增。

## 错误处理

- AI 生成失败：保留选择、合并要求和现有数据。
- AI 输出格式错误：允许重试，不写入数据库。
- 用户取消：不修改数据。
- 合并提交失败：事务回滚，不出现部分更新。
- 云端网络失败：提示重试，不自动重放写操作。
- 清理任务失败：记录错误，下一次任务继续尝试。
- 恢复失败：原垃圾箱状态保持不变。

## 安全要求

- 所有表和函数都必须遵守当前用户隔离。
- 垃圾箱和恢复记录不能跨账号读取。
- 只有登录用户可以调用 AI 合并接口。
- 不向浏览器暴露 Service Role Key。
- 不把提示词全文写入普通日志。
- 合并说明只在预览中展示，不写入提示词正文。
- 日志不得记录 AI 密钥、请求头或完整提示词。
- 永久删除和清空垃圾箱必须有明确确认。

## 风险与处理

### AI 合并质量不稳定

使用结构化输出、合并说明、可编辑预览和用户确认控制风险。

### 自动归档造成误删

使用软删除、恢复快照、明确保存影响和 30 天保留期控制风险。

### 本地与云端事务行为不一致

两端分别实现事务语义，并使用相同的数据库测试场景验证。

### 数据迁移失败

先执行并验证迁移，再部署依赖新字段的代码。

### 免费层定时任务不稳定

云端每天清理一次；失败时下一次继续，垃圾箱显示理论剩余天数。
