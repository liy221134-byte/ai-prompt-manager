# 挑资产引用模型（v2.20.0 的一部分，设计 + 任务清单）

## 来源

2026-09-25 线上写库自测发现：从公共资产库挑资产、工程基线「把这 N 条装进项目」，
**规则一条都进不来**。查出来的第一层根因（引用记录抄了包的 `pending` 状态）已经修掉，
修的时候带出第二层：挑资产时现攒的包用的是**固定标识** `rule-pack-public-library`。

第一次挑的两条成了这个包的成员；第二次挑、以及装推荐时那些规则既没进公共库正本、
也不在引用范围内，照样看不见。产品负责人 2026-09-25 拍板走**方案 2**。

## 一、做什么 / 不做什么

### 做什么

1. **挑规则进项目＝记引用，不复制**：选中的规则标识写进这个项目那条「公共资产库挑入」
   引用记录的元数据 `referencedAssetIds`，正文留在公共库那份。
2. **读项目规则时把点名的那些算进来**：项目当前生效的规则 = 项目专属 + 引用包的成员
   （减排除清单）+ 引用记录里点名的公共资产；同一条只出现一次。
3. **不再现攒包**：挑资产不再往公共库写重复副本，也不再写 `packId`。
   公共库从此不会因为「挑过」长出同名副本。
4. **文档和模板照旧复制**：它们要出现在项目的文档和模板列表里，体量也小（`v2.18.0` 的边界）。
5. **脱钩跟着放宽**：以前要求「这条规则必须属于某个包」才能另存为项目规则；
   现在只要是**从公共库引用来的**（包成员或点名引用）都能脱钩，
   脱钩标记补记来源资产标识 `sourceAssetId`。

### 不做什么

- **不改数据库表结构**：新字段仍然放进资产的元数据 JSON。
- **不动「装规则包」那条路**：包引用照旧按包整体引用、按包排除。
- **不做「一条规则一条引用记录」的细粒度界面**：每个项目仍然是那一条「公共资产库挑入」记录。
- **不回溯改写历史数据**：以前那条带 `packId` 的引用记录继续按包成员读，兼容；
   这次自测留下的残留按产品负责人决定**归档**，不删。

## 二、数据和产品行为影响

| 项 | 影响 |
| --- | --- |
| 新增字段 | 项目引用记录的 `metadata.referencedAssetIds: string[]`（公共库资产标识） |
| 脱钩标记 | `detachedFrom` 增加 `sourceAssetId`；老的「只有包内编号」的记录继续认 |
| 项目规则列表 | 多出「点名引用来的公共规则」，角标显示「公共库」（没有包名） |
| 公共资产库 | 挑资产不再产生副本，`沉淀体检` 的重复项会随之减少 |
| 规则编译 / 覆盖口径 | 点名引用来的规则和包成员一样参与，去重按资产标识 |
| 备份与恢复 | 不变：新字段跟着普通资产走 |
| 数据库结构 | **无变化**，本机与云端都不用迁移 |

## 三、验收标准

1. 在新项目里挑两条规则，项目规则列表里出现这两条，各带「公共库」角标。
2. 挑的时候**公共资产库不再新增同名副本**（挑前后条数不变）。
3. 再挑另外两条，四条都在；重复挑同一条不重复出现。
4. 改公共库里被点名的那条，项目里看到的正文跟着变。
5. 对一条点名引用来的规则点「另存为项目规则」，能脱钩，且列表里只显示副本。
6. 文档和模板照旧复制进项目（不受本改动影响）。
7. 老数据不变：带 `packId` 的历史引用记录读出来和以前一样。
8. `npm run check` 通过。

## 设计偏差

1. **老记录上的 `packId` 不清掉**：设计里写「不再写 `packId`」指的是新建时不写；
   实际更新一条历史记录时只把点名的补上去，不动它原有的 `packId`。
   理由是别人用老办法挑过的规则，一旦把 `packId` 抹掉就会突然看不见，属于静默丢东西；
   那条历史记录连同它指向的现攒包已经归档，不影响新行为。
2. **文档和模板仍走「现攒一个包」的老路径**：它们的标记只用来记住来源，
   不影响规则那条引用语义；这次只把规则的引用改对了，没有顺手重做它们的复制方式。
