# 种子包状态口径与规则包重装设计（v2.29.0，暂定名）

起因两件：① 导入规则包后包版本号永远停在首次导入的值；② 采集合规检查里那 29 条
「规则处于 active 但没有确认记录」，根因是打包器把成员状态强制写成 `active`，
源文件里的 `candidate` 从来没生效过。

## 1. 做什么 / 不做什么

### 做

1. **打包器按源文件的 `status` 出包，不再强制 `active`。** 每个成员的包内状态取自它
   源文件 front matter 的 `status`，按下面的词表映射；包文件本身的 `status` 保持现在的口径。
   （`candidate` 的规则不带确认记录就是不该参与编译的，被强制成 `active` 等于绕过
   SOP 第 4 条。）
   - 种子包 schema 与资产库是**两套词表**：库里的状态只有
     `draft`／`pending`／`active`／`archived`／`deprecated`，没有 `candidate`。
   - 映射：`candidate` → `pending`（待确认）；`draft`／`active`／`deprecated`／`archived`
     原样；**没写 `status` 的文件**（项目画像、编译验证记录）维持原来的 `active`，
     它们是说明性文档，改成待确认会被默认列表藏掉。
2. **重装同一个包时，更新包条目本身。** 库里已有这个包时不再整条跳过：
   `packVersion`、`summary`、`metadata`（可信度、适用规模、来源说明）跟着包文件走，
   `updatedAt` 刷新。
3. **导入结果如实报到三档。** 完成提示从一句「已装 N 条」改成三个数字：
   新增 K 条 / 跳过 M 条（库里已有同包同编号）/ 其中 N 条的记录版本旧于包版本。
4. **导入对话框说清「装到哪个项目」的实际差别。** 下拉保留（它是真实参数），
   但下面加一行说明：选**默认项目（公共资产库）**＝把正文复制进公共库当正本；
   选**普通项目**＝只装引用记录，正文留在公共库。
5. **从公共资产入口进来时默认选中默认项目。** 现在默认取「当前项目」，在公共资产视图下
   恰好也是默认项目——要写死，不靠巧合。
6. **把「默认项目 = 公共资产库」写进 `AGENTS.md`。** 这是产品里一条真实存在的对应关系，
   此前只存在于代码注释里。

### 不做

1. **不覆盖已有成员的正文和状态。** 哪怕包里那条变了，也不自动改库里那份——用户可能
   确认过它、也可能改过它
   （产品规则第 5 条：AI 不得静默覆盖用户内容）。这一版只把「你的成员是旧版本」说出来，
   怎么处理由人决定。
2. 不改规则包的 JSON 格式（`pack.json` 结构不动，旧包仍能导入）。
3. 不改「成员只新增」的去重键（`项目:包:包内编号`）。
4. 不做「一键把库里成员升级到包版本」。留到有人真的需要时再评估。
5. **不动库里已经存在的 29 条 active 规则**（那是存量数据，处理方式见文末「待拍板」）。

## 2. 数据和产品行为影响

- **数据表、字段、迁移：不变。** 只改写入时机。
  - 包资产（`asset_type = rule_pack`）在重装时走一次更新，产生一条新的资产版本记录
    （现有 `updateAsset` 版本机制原本就支持）。
  - 回滚语义：包条目的历史版本留在 `asset_versions` 里，可恢复；成员资产完全不动。
  - 没有新增字段，不需要迁移，不涉及云端表结构。
- **产品行为变化：**
  - 新导入的种子包成员状态跟着源文件走：`candidate` 的进库还是 `candidate`，
    不再自动进编译候选。
  - 重装后包条目的版本号会变成包文件当前的版本。你库里那份会从 `0.2.1` 变成 `0.13.0`，
    训练包会从 `0.1.0` 变成 `0.3.0`。
  - 导入完成提示多两个数字。
  - 导入对话框多一行说明文字。
- **影响面：** 只影响「导入规则包」和「重装规则包」这一条路径。挑资产、引用规则、
  编译到 `AGENTS.md` 的口径都不变。

## 3. 验收标准

每条都能用一次测试或一次手工验证判定。

1. 重跑 `npm run pack:seed` 后，包内成员的 `status` 与源文件 front matter 对得上：
   工程包 0.13.0 是 **58 条 `pending` + 11 条 `active`**（原来 54 条 `active` + 15 条
   `document/active`）；那 11 条 active 里，1 条是源文件本来就写 `active` 的
   `PLAYBOOK-DEBUG-001`，另 10 条是没有 `status` 字段的画像与验证记录。
2. 导入后，新成员的库内状态是 `pending`；跑 `npm run check:leads3-compliance`，
   违规数**不因为新导入而增加**。
3. 库里已有 0.12.0 的包时导入 0.13.0 的包文件 → 包条目版本号变成 `0.13.0`。
4. 同一次导入，已有成员一条不改：抽查任一老成员，导入前后 `updatedAt`、正文和状态完全一致。
5. 新增成员数正确：工程包 0.12.0 → 0.13.0 那次新增 **8** 条（含补登的
   `MTH-REQ-FORMAT-001`）；训练包新增 **6** 条。
6. 导入完成提示里能同时看到三个数字：新增、跳过、其中旧版本条数。
7. 包条目更新后 `asset_versions` 里多一条记录，且能把包条目恢复到旧版本。
8. 从公共资产入口打开对话框，默认选中的是「默认项目」；切到普通项目时，
   说明文字明确写出「只装引用，正文留在公共资产库」。
9. `AGENTS.md` 里能搜到「默认项目 = 公共资产库」这条对应关系。
10. 回归：`npm run check` 全过。
