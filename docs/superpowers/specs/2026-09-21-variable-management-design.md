# 变量管理设计（v0.9.1）

## 文档状态

- 版本目标：`v0.9.1`。
- 状态：需求草案，等 v0.9.0 人工验收完成后再开工。
- 前置条件：v0.9.0 已经发布，并且人工验收清单签完。

## 为什么做这个

变量目前只是正文里的文本，没有独立的确认环节。

真实场景：我用 AI 采集一段提示词入系统，识别出来的变量不是我要的——有些变量很牵强，
或者本来就是固定内容却被识别成了变量。现在我只能回到正文里逐个找、逐个删，删完还要
把句子改通顺。成本高，而且容易漏。

v0.9.0 的「允许调整变量」能缓解这个问题，但那是让 AI 再猜一次；我需要的是**我自己
直接管**。

## 目标

把变量的确认、改名和删除变成一等公民，发生在两个位置：

1. **入库前**：AI 采集识别完成后，在保存之前就能逐个确认。
2. **入库后**：已有提示词可以随时清理变量。

## 本期范围

### 包含

- 采集预览增加「识别到的变量」清单，每项可以改名或删除。
- 编辑抽屉增加同样的变量清单。
- 详情抽屉增加「整理变量」入口，点击后打开编辑抽屉。
- 改名：正文里所有该变量的出现位置同步替换。
- 删除：用一个输入框决定"用什么文字替换"，默认填入变量名本身。
- 改名和删除的即时校验：空名、非法字符、重名都要在保存前拦下。
- 两个位置的变量清单行为完全一致。

### 不包含

- 变量的默认值或预设值（属于独立功能）。
- 变量排序调整。
- 跨提示词统一变量名。
- 批量清理多条提示词。
- 把变量单独存成数据库字段。

## 关键设计决定

### 1. 变量继续从正文派生，不新增字段

数据库不新增 `variables` 字段。变量永远是「正文里 `{{...}}` 的解析结果」。

理由：一旦变量单独存一份，就会出现"正文改了但变量表没改"的不同步问题，而这类
问题排查起来很贵。派生虽然每次要重新解析，但永远不会不一致。

### 2. 删除变量时必须决定"替换成什么"

直接删掉 `{{行业}}` 会让句子变成"请分析 的市场规模"，语意断裂。所以删除时弹一个
输入框：

```text
用什么文字替换 {{行业}}？
[ 行业            ]（默认填入变量名）
留空表示直接删除占位符
```

默认值是变量名，用户改成"目标行业"这类通顺说法即可。留空则直接删除占位符，适合
变量出现在句末或列表里的情况。

理由：只有让用户决定替换文字，才能既保证句子通顺，又不替用户决定内容。

### 3. 变量规则与 v0.9.0 保持一致

- 变量名两侧空格自动去掉。
- 变量名不能为空、不能包含 `{` 或 `}`、长度不超过 30 个字符。
- 改名后不能和同一提示词里已有的变量重名。
- 同一个提示词的变量数量上限 20 个。

## 数据与产品行为影响

- **不改数据库结构**，不需要迁移；本地 SQLite 和云端都不变。
- 改的是提示词正文，走现有的保存路径（采集预览保存、编辑抽屉保存）。
- 详情抽屉只展示变量清单和「整理变量」入口，不做就地修改，避免和"填写变量"混淆。
- 取消编辑时，已存的提示词不受影响。
- 不做任何自动保存：必须点保存才写入。

## 用户交互设计

### 采集预览

- AI 识别完成后，正文编辑区上方显示「识别到的变量（N 个）」。
- 每个变量一行：变量名 + 「改名」+ 「删除」。
- 改名：就地变成输入框，回车确认，正文同步替换。
- 删除：弹出替换文字输入框，确认后正文和清单同步。
- 清单为空时整块隐藏，不占空间。

### 编辑抽屉

- 与采集预览完全一致的清单和交互。
- 编辑已有提示词时，清单从当前正文实时解析。

### 详情抽屉

- 变量填写区保持现状（只填值）。
- 右上角增加「整理变量」按钮，点击后打开编辑抽屉。

## 验收标准

- [ ] AI 采集识别完成后，变量清单数量与正文里的变量一致。
- [ ] 改名后正文里所有出现位置同步更新，清单同步。
- [ ] 改名冲突（与已有变量重名）时给出明确提示，不写入。
- [ ] 删除变量时可以填替换文字；留空时直接删除占位符。
- [ ] 删除后正文里不再出现该占位符，句子读起来通顺。
- [ ] 变量名为空或含非法字符时无法保存，并指出是哪一个。
- [ ] 采集预览和编辑抽屉两处行为一致。
- [ ] 详情抽屉的「整理变量」能打开编辑抽屉。
- [ ] 取消编辑不会修改已保存的数据。
- [ ] 数据库结构没有变化，变量仍然从正文派生。
- [ ] 本地 SQLite 与云端 Supabase 行为一致。
- [ ] `npm run check` 全部通过。

## 任务顺序

一个任务一次提交。

| 序号 | 任务 | 预期改动 |
| --- | --- | --- |
| 1 | 变量编辑纯函数：改名、删除并替换、重名与非法字符校验 | `src/lib/prompt-variables.ts` 新增，配单元测试 |
| 2 | 采集预览接入变量清单 | AI 采集抽屉与编辑器预填逻辑 |
| 3 | 编辑抽屉接入变量清单 | 提示词编辑抽屉 |
| 4 | 详情抽屉「整理变量」入口 | 提示词详情抽屉与库组件接线 |
| 5 | 自动化测试与人工验收记录 | `tests/`、`docs/acceptance/` |

## 风险与处理

- **改名后用户已填的变量值失效**：变量值本来就不持久化，只影响当前会话，接受。
- **替换文字造成句子别扭**：默认填变量名，并且必须由用户确认，不做自动改写。
- **两个入口行为不一致**：任务 1 的纯函数是唯一实现，两个入口都调它。
- **清单和正文不同步**：清单始终从正文实时解析，不单独维护状态。

## 后续可能的方向

- 变量默认值和预设值。
- 变量在多个提示词之间统一命名。
- 采集时把变量识别结果作为独立的确认步骤（当前是识别后直接在编辑器里确认）。
