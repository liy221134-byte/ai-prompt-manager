# 规则引用模型（v2.18.0 设计 + 任务清单）

## 来源

2026-09-24 产品负责人复盘时提的一条现场问题：

> 我们项目中实践过的规则就只有这四条么，我觉得公共资产中的大部分规则都在本项目的开发中实践过了。

事实核对（2026-09-24 实测）：公共资产库 28 条规则里，**24 条的证据／来源直接指向本项目文档**；
而项目里只挂着 4 条——那还是当天 06:51 一次「从公共资产库挑资产」自测留下的复制品。
原因是这个包当初是**手写提炼**出来的，没走「提升为公共资产」，两边既没有同源关系、
项目里也没有那份记录。

本次按产品负责人指示与 v2.17.0 一起做掉，本文记录**已执行的取舍**。

## 一、做什么 / 不做什么

### 做什么

1. **项目用「引用」表达在用什么规则**：项目里放一条**引用记录**（`rule_pack` 资产，
   标识 `包标识-ref-项目标识`，元数据里记 `packId`），规则正文只保留在公共资产库那份。
2. **读项目的规则时把引用合并进来**：项目当前生效的规则 = 项目专属规则 + 引用包在公共库里的成员。
   公共库改一处，所有引用它的项目立刻跟着变。
3. **界面上分得清来源**：引用来的规则在项目列表里挂「公共库 · 包名」角标；
   打开时顶部提示「这条来自公共资产库的 X，改它会影响所有引用这个包的项目」。
4. **安装规则包分两种去向**：装进公共资产库＝复制包和成员（正本落在这里）；
   装进项目＝只记引用。往项目装一个公共库还没有的包时，先把它建成公共库正本，再记引用。
5. **规则编译、立项推荐都认引用**：编译候选集把引用来的规则算进去；
   已经引用的包不再出现在推荐清单里。
6. **老数据不删**：项目里已经复制过的那份副本，如果公共库还有同一个包内编号的正本，
   就不在列表里重复显示（正本优先）；副本本身归档保留，状态改回活跃即可恢复。

### 不做什么

- **不改数据库表结构**：引用记录复用 `rule_pack` 类型，`packId` 放元数据 JSON。
- **不做双向同步**：公共库是规则正文的唯一来源；项目想自己改，就把那条**另存为项目规则**
  （脱钩成项目专属），这属于下一步的细化，本版先不做那个按钮。
- **不碰文档和模板成员**：包里头的画像、案例、模板仍然复制进项目——它们要出现在文档和模板列表里，
  体量也小。
- **不做规则级引用**（只到包这一级）：规则本来就是成包进来的，包是天然的引用单位。
- **不做云端与本机分工**（公共上云、项目本地）：那是下一版，单独设计。

## 二、数据和产品行为影响

| 项 | 影响 |
| --- | --- |
| 数据库结构 | 无变化（引用记录是 `rule_pack` 资产，多一个 `metadata.packId`） |
| 项目规则列表 | 项目专属 + 引用包在公共库里的成员；同一包内编号只出现一次 |
| 规则包安装 | 目标项目不是公共资产库时走引用；公共库缺这份包时先建正本再引用 |
| 规则编译 | 候选集包含引用来的规则（正文取自公共库） |
| 立项推荐 | 引用了包就不再推荐包内规则 |
| 沉淀体检 | 口径不变：项目专属规则（没有包来源）才会进「只在项目里出现」的清单 |
| 备份 | 不变（引用记录就是一条普通资产，跟着备份走） |

## 三、验收标准

1. 项目引用一个包后，项目规则列表里能看到这个包在公共库里的全部成员，每条带「公共库 · 包名」角标。
2. 改公共库那条规则，项目列表里看到的正文跟着变（读的是同一份）。
3. 项目里那份老副本与公共库正本重复时，列表里只出现一次（公共库那份）。
4. 往项目装一个公共库还没有的包时，公共库先出现正本，项目里出现引用记录，规则成员不进项目。
5. 规则编译的候选集包含引用来的规则；规则编译能正常出产物。
6. 项目专属规则（自己写的、没有包来源）仍然留在项目里，能编辑、能提升为公共资产。
7. `npm run check` 通过。

## 五、需要拍板的三个决定

| 编号 | 决定 | 本版做法 |
| --- | --- | --- |
| R1 | 引用的粒度 | **按包引用**（规则本来成包进来；逐条引用要另做一套界面） |
| R2 | 项目想改公共规则怎么办 | 改公共库那份（影响所有引用它的项目）；「另存为项目规则」留到下一版 |
| R3 | 老副本怎么处理 | 公共库有正本时列表只显示正本；副本归档保留，不删 |

## 设计偏差

1. **引用记录用一条 `rule_pack` 资产**（标识 `包标识-ref-项目标识`），而不是新增资产类型：
   不改表结构，也不影响云端；`listProjectPacks` 同时认包成员和引用记录。
2. **往项目装包时先保证公共库有正本**：否则引用没有正文可读——这条是原设计里没写、
   实施时补上的必要动作。
