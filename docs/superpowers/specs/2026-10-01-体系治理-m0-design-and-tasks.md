## 四、任务顺序与每个任务改哪些文件

### T1 · 规则命中台账

**改**：新增 `docs/rule-hits.md`；改 `docs/pending-items.md`（那一节改成指针）。

**形状**（借 WB 侧已跑通 868 行的形状，按本机情况裁剪）：

1. 页首三节：
   + **判定口径**：守住 / 不适用 / 违背（违背含自曝自己造出来的问题）
   + **退役阈值**：连续 5 次「不适用」→ 退役候选；20 个会话未命中 → 退役候选；同一条 3 次「违背」→ 强制复盘，等人介入。候选只提出，不自动删。
   + **豁免清单**：A 类低频高危（删数据、改写 Git 历史、推远端、写生产库、动个人目录、拿账号登录）只免「未命中」不免「违背」；B 类「命中即退场」（引入第三方库／外部服务／部署环境）——它的未命中是生效证据，不是失效信号。
2. **逐条累计表**：规则名 | 豁免 | 连续不适用 | 累计违背 | 未命中会话数 | 状态。按 `AGENTS.md` 现有章节逐条起，**不改规则内容，只建索引**。
3. 分会话场景记录（append-only）。

**不做**：不新造规则编号体系。`RULE-*` 已被资产库占用（如 `RULE-SCHEMA-CHECK-001`），另起一套会撞号；沿用章节名做 key。

### T2 · 技能体检清单

**改**：新增 `docs/reference/skill-inventory.md`。

**内容**（数字均为本次实测，直接落）：

- 三个来源：用户级 `.codex/skills` **24** 个、交叉 `.agents/skills` **13** 个、插件缓存 **104** 个 = **141 个**
- description 总量 **38,322 字符**（≈11k tokens／轮）；外部一手事实：技能列表预算 = 上下文窗口的 1%，溢出时按「最少调用」丢 description —— 越不用越触发不了
- 重名 1 处：`ui-ux-pro-max` ×2
- **非规范字段**（Agent Skills 规范只允许 `allowed-tools` / `compatibility` / `description` / `license` / `metadata` / `name` 六个）：
  - `.agents/skills` 侧用了 `version`、`agent_created`
  - 插件缓存里 11 个 figma 技能用了 `disable-model-invocation`
- 建议清单分三档：可降级 / 可停用 / 需回正本仓确认，**只列建议**

### T3 · 一次性改 `AGENTS.md`（本轮最大的一步）

**改**：`AGENTS.md`（根）；新增 `docs/method.md`（方法正本）。

拆法（按字节算过；方案甲＝移出 5 块）：

| 段落 | 行 | 字节 | 处置 |
| --- | ---: | ---: | --- |
| 头部 + 关于我 | 1–8 | 293 | 留根 |
| 每次开始工作前 | 9–22 | 1,114 | 留根（精简为 5 条） |
| 开发流程引言 | 23–24 | 59 | 改成「三层 + 按动作读哪节」索引表 |

结果：根 `AGENTS.md` 从 **15,918 → 约 8,000 字节（约 -50%）**；`docs/method.md` 约 8,800 字节。

**同时在根补两条新规则**（是新增，不是移动）：

1. **交付门 · 收口**：一版交付时回看设计文档；规格已不成立或已被实现推翻的，按「设计偏差」列出，
   裁定后**回写规格**（改设计文档或改验收标准），并注明哪一份是当前有效版本。

   > **现状核对（重要，防止把已有的当成缺的）**：`AGENTS.md` 设计门里**已经有**「实现和设计不一致时，
   > 单独列出设计偏差，由我决定改设计还是改实现」。本轮补的是**裁定之后回写规格**这个动作，
   > **不是**新增「设计偏差」概念。调研报告第 5 节 O4 写得比实际宽，此处更正。

2. **交付门 · 成本申报**：交付说明固定报一行「本轮新增依赖／新增工具位」，没有就写「无」。

**拆分的取舍**：

- 留根的判据：**漏读代价不可逆**（硬边界、检查命令、工具分工、产品事实）
- 移出的判据：**漏读代价可控**（判据类文本，正本随时可查）
- 对应风险：判据移出后 AI 可能不再主动读 `docs/method.md`。缓解：根里保留一张**读取触发表**
  （「接下来要做什么 → 先读哪节」），与 WB 侧已验证的形状一致。

### T4 · 两侧体系对照表

**改**：新增 `docs/reference/two-sides-alignment.md`。

**内容**（一页）：两栏——**有意分叉**（各自自持、不该互抄）／**应该一致**（同一事实只能有一处）。
已知条目：技能正本只在 `E:/AI资产市场`（应该一致）；文档体系两份副本、分叉点 `18e6bf8`（有意分叉）；
方法层我们叫 `docs/method.md`、WB 叫 `DEV-SYSTEM.md`（有意分叉，内容同源）。
一句判据：**同一事实出现在两处、且两处都需要改 → 应该一致；只有一侧需要改 → 有意分叉。**
