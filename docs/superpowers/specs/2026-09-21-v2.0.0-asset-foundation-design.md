# 2.0.0 项目与统一资产底座设计

## 文档状态

- 目标版本：`2.0.0`。
- 前置计划：[2.0 资产管理底座计划](../../v2-plan.md)。
- 状态：设计待确认，确认后才开始实现。
- 本文只写产品决定和数据边界，不写 SQL、完整代码和实现步骤。

## 一、做什么与不做什么

### 做什么

- 新增项目工作区。
- 建立统一资产模型，提示词成为资产的一种类型。
- 将现有提示词迁移到默认项目。
- 为未来规则、文档、模板、技术档案和来源包保留统一资产类型。
- 建立不可变资产版本模型。
- 建立项目下的资产列表和类型筛选。
- 保持现有提示词采集、编辑、变量、合并、优化、垃圾箱和备份行为可用。
- 本地 SQLite 与 Supabase 使用同一套资产语义。
- 为后续项目导入、复杂元数据和规则编译提供稳定基础。

### 不做什么

- 不做 ZIP 和文档包导入。
- 不做 AI 识别项目或规则。
- 不做规则和文档的完整元数据编辑界面。
- 不做技术档案编辑界面。
- 不做资产关系和影响分析。
- 不做规则编译和协作路径。
- 不做上下文图谱和 MCP。
- 不允许删除项目，只能归档项目。
- 不清理旧 `prompts` 和 `prompt_versions` 表。

## 二、数据与产品行为影响

### 项目

项目是当前版本的资产归属单位。

项目需要包含：

- 稳定项目标识。
- 名称和描述。
- 状态：活跃、已归档。
- 阶段：原型、开发、发布、维护等。
- 创建和更新时间。
- 归档时间。

用户只能主动创建、重命名和归档项目。`2.0.0` 不支持删除项目。
归档项目可以重新激活，资产不会因归档而删除。

### 默认项目

- 首次迁移时自动创建一个“默认项目”。
- 所有现有提示词归入默认项目。
- 现有提示词标识保持不变。
- 默认项目可以重命名和归档，但不能删除。
- 用户没有选择项目时，默认进入最近使用的项目。

### 统一资产

`2.0.0` 建立统一资产主模型，但界面先只管理提示词。

资产类型预留：

```text
prompt
rule
document
template
tech_profile
source_package
```

资产公共字段包括：

- 资产标识。
- 资产类型。
- 所属项目和用户。
- 标题和摘要。
- 当前内容。
- 生命周期状态。
- 来源类型。
- 当前版本标识。
- 创建、更新和归档时间。

提示词继续使用现有标题、分类、标签、正文和适用场景字段。其他资产类型在这一版只保留模型能力，不提供正式创建入口。

### 资产版本

- 每次正式内容变更都产生一个不可变版本。
- 版本保存内容、元数据、变更原因和创建时间。
- 当前资产指向当前版本。
- 历史版本不能覆盖，只能通过恢复操作产生一个新版本。
- 现有合并恢复和优化恢复必须迁移为资产版本，并保持恢复行为不变。

### 现有数据迁移

- 迁移前必须备份。
- `prompts` 中的记录复制到统一资产模型。
- 原提示词标识直接作为资产标识，避免书签和恢复关系失效。
- `prompt_versions` 的不可变快照迁移到资产版本。
- 垃圾箱、合并来源标记和优化恢复关系必须保持。
- 旧表在一个版本周期内保留为只读回退副本，不再作为正式写入源。
- 迁移必须可重复执行，重复执行不能产生重复资产。

### 产品行为

- 首屏从单一提示词库升级为项目资产库。
- 用户可以切换项目。
- 默认项目下的现有提示词行为保持不变。
- 新建项目初始为空，不自动复制默认项目资产。
- 资产列表默认只显示当前项目、当前类型的活跃资产。
- `2.0.0` 的资产类型筛选只支持提示词和“全部”，其他类型显示为空状态。
- 现有 `/api/prompts` 行为需要兼容，避免前端和备份逻辑同时重写。
- 旧版提示词备份导入时进入默认项目。

### 本地与云端

- 本地 SQLite 和 Supabase 使用相同的项目、资产和版本语义。
- 云端资产和项目必须使用 RLS 按用户隔离。
- 未登录用户不能读取项目、资产或版本。
- 迁移失败时不得进入部分可写状态。

## 三、验收标准

- 旧数据库首次启动后自动创建默认项目。
- 所有现有提示词出现在默认项目中，数量和内容完全一致。
- 提示词标识不变，合并、优化和垃圾箱恢复关系继续有效。
- 用户可以创建、重命名和归档项目。
- 归档项目不会删除其资产，重新激活后资产仍然可见。
- 用户可以切换项目，资产列表只显示当前项目的数据。
- 新建项目保持空状态，不自动复制默认项目资产。
- 现有提示词采集、编辑、删除、变量、复制、合并和优化流程不回归。
- 旧版提示词备份可以导入默认项目。
- 本地和云端数据行为一致。
- 不同账号之间无法读取项目和资产。
- 重复执行迁移不会产生重复数据。
- 迁移失败时旧数据保持可读，不出现半迁移状态。
- `npm run check` 全部通过。

## 五、关键决定

1. `2.0.0` 只建立项目与统一资产底座，不提前开发导入和规则编译。
2. 统一资产是正式写入源，旧提示词表只保留为短期回退副本。
3. 提示词标识迁移后保持不变。
4. 项目只能归档，不能删除。
5. 资产版本不可变，恢复操作产生新版本。
6. 现有提示词功能全部保持兼容，不能要求用户重新建立数据。

## 六、后续版本边界

- `2.0.1`：文档包导入、AI 识别草稿、规则和文档元数据编辑。
- `2.0.2`：技术档案、资产关系、搜索筛选和完整备份升级。
- 规则编译、协作路径、上下文图谱和 MCP 在资产底座稳定后重新设计。
