# 复盘：从已发生的事里学

## 核心结论

每个周期结束用固定仪式看「哪些好 / 哪些差 / 下周期改什么」，只反思流程不追责人。

## 使用条件

- 版本发布后、重大项目节点后。

## 不适用场景

- 事故刚发生、情绪未平——先走故障演练 / incident 流程。
- 纯日常小改。

## 执行方法

1. 固定时间盒（如 1 小时），全员参与。
2. 三栏：做得好 / 待改进 / 行动项。
3. 每条行动项带负责人与截止日，进下一周期跟踪。
4. 聚焦可改的流程问题，不指向个人。
5. 上轮行动项先回看：做了没、有效没。

## 失败模式

- 变成吐槽会或表彰会，没产出。
- 行动项无主人，不了了之。
- 只复盘不落地。

## 验证证据

- 行动项有负责人 / 截止日且下轮回看。
- 同类问题不再复发。
