# 备份与恢复

## 备份对象

- 提示词数据。
- Supabase 用户和权限配置。
- 必要环境变量名称。
- 代码和 Git 标签。

## JSON 备份

入口：

```text
数据管理 -> 导出备份文件
```

备份内容：

- 备份格式版本。
- 导出时间。
- 全部提示词。

## 建议频率

- 每次发布前导出一次。
- 每月至少导出一次。
- 大批量导入或 AI 合并前导出一次。
- 修改数据库结构前强制导出。

## 保存位置

至少保留两份：

- 本机文件目录。
- 私人云盘或其他离线存储。

不要把包含提示词内容的备份提交到 GitHub。

## Supabase 数据备份

自动每日备份只对 Pro 及以上计划开放。免费计划虽然也在做备份，但我们**访问不到、也
恢复不了**，官方文档的建议就是免费计划自己导出并异地保存。

所以本项目不把 Supabase 当作可用的备份来源，恢复点完全取决于上面的导出频率。这一条
和可用性目标的关系见 `operations/availability-targets.md`。

## 恢复流程

1. 先导出当前数据，避免恢复过程覆盖新内容。
2. 打开数据管理。
3. 选择备份文件。
4. 检查新增、更新和跳过数量。
5. 确认导入。
6. 刷新页面并核对提示词数量。

预览和实际导入使用同一套垃圾箱过滤规则。备份中存在、但当前仍在垃圾箱中的
提示词会显示为“跳过”，导入后不会复活。

## 恢复演练

至少每三个月进行一次：

- 导出当前数据。
- 修改或删除一条测试提示词。
- 使用备份恢复。
- 核对原文、标签和变量没有被破坏。
