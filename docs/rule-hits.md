## 一、判定口径

**什么叫一次命中**：`AGENTS.md` 里已经写过的规则，AI 没照做、被指出来。
产品负责人临时改主意、需求变了、规则里根本没写过的，都不算。口径写在 `AGENTS.md` 交付门。

三个结果，别的词不用：

| 结果 | 含义 | 记不记 |
| --- | --- | --- |
| **守住** | 规则本来会踩、这次没踩；或规则真实拦下了一次风险 | 记 |
| **不适用** | 这一轮没有触发这条规则的场景 | 记（用于退役判定） |
| **违背** | 没做到，或被人指出 —— **价值最高的一类，照实记，包括 AI 自己造出来的问题** | 记 |

**谁在什么时候记**：每轮交付说明写完「本次规则命中」那一行之后，顺手往第五节追加，不等提醒。

## 二、退役与复盘阈值

规则也会腐坏：写下来没人用、或者用了没人真踩。判定按**会话数**，不按时间 ——
会话切换频繁，按时间算的话，等数据攒够，坏规则早坑完好几轮了。

| 条件 | 动作 |
| --- | --- |
| 连续 **5** 个会话被记「不适用」 | 退役候选 |
| 累计 **20** 个会话一次都没被记过 | 退役候选 |
| 同一条累计 **3** 次「违背」 | **强制复盘**：停下来问产品负责人 —— 是规则定得不对，还是 AI 没长记性。这条不是退役，是要人介入 |
| 同一条累计 **2** 次「违背」 | 允许改 `AGENTS.md`（沿用原「规则命中记录」的旧口径，见 `docs/pending-items.md` 历史版本）。改的时候必须说明删掉或合并了哪条 |

退役候选一律在交付说明里提出来问，**不自动删**。升级/降级也只认这份台账，不认「我觉得好用」。

## 三、豁免清单

有一类规则**命中频率天然很低，但违背一次就是不可逆损失** —— 用「没人碰过」判它该不该退，
逻辑本身就错了。这类标记为**豁免**，**只免「不适用／未命中」两种判定，不免「违背」**：
违背照样累计、照样触发强制复盘。

| 豁免规则 | 类别 | 为什么 |
| --- | --- | --- |
| 数据与安全 1 · 删除 / 覆盖 / 改生产库 / 破坏性 Git | **A 类 · 低频高危** | 不可逆 |
| 版本与提交 · 未经确认不 `reset --hard` / 强制推送 / 删历史 | **A 类 · 低频高危** | 不可逆 |
| 数据与安全 3 · 密钥不进浏览器代码和 Git | **A 类 · 低频高危** | 泄露不可逆 |
| 界面验证 · 需要登录态且无保存会话时不许拿账号登录 | **A 类 · 低频高危** | 低频，违背即越权 |
| 数据与安全 2 · 引入第三方库 / 外部服务 / 远程仓库 / 部署环境 | **B 类 · 命中即退场** | 骨架期触发，此后因方案已落地、难度降低而不再命中。**它的「未命中」不是失效信号，而是生效证据** |

加豁免或取消豁免，同样在交付说明里提出来问，不自动改。

## 六、工具与依赖期限表（成本与额度纪律，2026-10-01 建）

新增 MCP / 技能 / 外部依赖时，在这里登记一行。**「观察期至」与「验收口径」两栏必填** ——
缺一栏不许登记。验收口径要写成**能数出来的事**（「两周内实际触发 ≥3 次」），
不写「好用就留」。

为什么挂在台账里而不是单开一份文件：**它和规则一样，是「该不该留」的判断依据**，
而且扫描动作要挂在「写交付说明」上才不会忘 —— 参考 WB 侧已验证的形状。

| 登记日 | 项 | 类型 | 观察期至 | 验收口径 | 状态 |
| --- | --- | --- | --- | --- | --- |
| （暂无登记项） | | | | | |

**到期怎么办**：到点**不是必须撤，而是必须复核一次** —— 过「目标 / 期限 / 归因」三道闸门就续，
不过就走（走 = 停用或隔离，保留回退路径）。

**谁扫**：挂在**每轮交付说明**上 —— 写完「本轮新增依赖／新增工具位」那一行，顺手扫一次这张表，
到期的在交付说明里提出来问，**不自动撤**。不新增定时任务：那会在已有的自动化里再加一条要维护的链路。

**存量（无期限）**：本机 141 个技能 / 13 个插件 / 若干 MCP，目前都没有期限。
清点与「可降级 / 可停用」建议见 `docs/reference/skill-inventory.md`；
在那份建议落地之前，这批按「无期限存量」对待，**等产品负责人定**，不由 AI 自行清理。
