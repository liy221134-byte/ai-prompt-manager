## 二、⚠️ 先决阻断：本机没有 Docker，也没有可用的 WSL

这是实测结论，不是推测：

| 查的 | 结果 |
| --- | --- |
| `docker --version` | `command not found` |
| `docker compose version` | `command not found` |
| `C:\Program Files\Docker` | 不存在（没装 Docker Desktop） |
| `wsl.exe` | 文件存在，**但我这边的执行被安全策略拦截**（沙箱黑名单），我无法验证能否启用 |
| VirtualBox | 无 |

**为什么这是阻断**：一页纸 M0 的核心交付物是 `docker-compose.yml`，验收标准第 1 条是"一条命令起全栈"。
没有 Docker，**这份产出物在本机无法验证**——按 `RULE-AGENT-VERIFY-001`，没验证过的东西不能写成"已验收"。
这正是科创平台二期那次的教训：不能把跑不起来的东西说成跑通了。

### 三个方案

| 方案 | 怎么做 | 能验收到什么程度 | 代价 |
| --- | --- | --- | --- |
| **A. 装 Docker Desktop** | 你装（需管理员），后端 WSL2 或 Hyper-V，装完重启 | **全部 5 条验收都能真跑** | 要你操作 + 重启；WSL2 启不来就白装（我这边测不了 wsl，得你确认） |
| **B. 本机原生四件套** | Nginx Windows 版（zip）、Postgres Windows 安装器、MinIO Windows 二进制、Python 写 SMTP 服务；`docker-compose.yml` 照样写，但**标注未经本机验证** | 证书/反代、文件存储、邮件、备份恢复 4 条能真跑；**"一条命令起全栈"这条只能静态检查** | 四处手工安装，卸载麻烦；compose 模板的可信度是"写出来"不是"跑过" |
| **C. 先只做不依赖容器的部分** | 证书 + 反代 + 邮件 + 备份（用本机 Postgres 或已有实例），MinIO 与 compose 推迟 | 部分验收 | 缩小了目标，一页纸的 M0 不完整 |

**我的建议：先试 A，A 不通就 B。**
理由：这个练习的目的就是要能交付给内网客户一套 compose 模板。用 B 练出来，模板本身没跑过，交付时还是心里没底——等于练了个半成品。
但 A 要你出面（安装 + 确认 WSL2 能不能起），我装不了。

**如果选 B，我会把"compose 模板未在本机验证"明确写进验收记录和手册**，不把它算作已验证项。

## 三、做什么 / 不做什么

### 做（M0：本机跑通一遍）

1. **四块能力各练一次**（实现方式见第四节）：数据库、证书与 HTTPS、文件存储、邮件。
2. **一份手册**：怎么起、怎么验、怎么停、怎么备份与恢复、密钥放哪、证书怎么分发。
3. **练习记录**：每一步"我以为会怎样 / 实际怎样"，重点记证书分发和邮件这两块。
4. **`docker-compose.yml` + 各组件的最小可用配置**（按方案 A/B 决定能否本机验证）。
5. **备份与恢复各做一次**：备份 → 删一条数据 → 恢复 → 查回来。

### 不做

- 不练信创数据库（达梦、人大金仓）迁移。
- 不做 K8s、集群、多机编排。
- **不把密钥写进仓库**：自签证书私钥、`.env`、数据卷全部 `.gitignore`；仓库里只放生成脚本。
- 不在公司网络或客户环境做实验，**只在本机**。
- **不用真实邮箱账号和授权码**发信（授权码是密钥，且一页纸指出邮件最容易卡）——用本机 SMTP 收信服务。
- M1（抽成起步包、导出进公共资产库）**不在这版**；M2（真项目验收）更不做。

## 四、四块能力怎么练（实现方式）

| 能力 | 首选实现 | 为什么 | 不用 Docker 时的替代 |
| --- | --- | --- | --- |
| 数据库 | `postgres:16-alpine` | 生产级默认档，与 `project-map` 技术选型一致 | Windows 原生 Postgres |
| 证书与 HTTPS | `nginx:1.27-alpine` + openssl 自签 CA 与服务器证书 | **证书分发是这次的重点练习**，openssl 本机已有 3.5.7，可直接生成 | Nginx Windows 版 zip |
| 文件存储 | MinIO（官方镜像） | 自建对象存储是内网场景的标准答案；自带 Web 控制台，可直接验上传 | MinIO Windows 二进制（单文件） |
| 邮件 | MailHog（SMTP 1025 + Web 8025） | 只收不发真实邮件，**零密钥**，能直接看到信 | Python 标准库写的 SMTP 接收服务 |
| 应用（上传页） | Python 标准库 `http.server` 写的上传处理器，**不引第三方依赖** | 目的是把反代 → 应用 → 存储这条链路走通，不是练框架 | 同 |

反代把 `/app`（上传页）、`/minio`（对象存储控制台）、`/mail`（邮件）挂在同一个 HTTPS 域名下——
这样"证书分发"这一课才是真的：只装一个根证书，三个路径都通。

## 六、验收标准（每条一次命令或一次手工操作可判定）

| # | 标准 | 怎么判 |
| --- | --- | --- |
| 1 | 一条命令起全栈 | `docker compose up -d` 后，浏览器打开 `https://<本机>/app/` 能看到上传页，传一个文件后能在存储里查到该文件 |
| 2 | HTTPS 用自签证书正常访问 | 导入根证书后浏览器无证书告警；手册里写清根证书怎么分发（含 Windows 导入的具体步骤） |
| 3 | 邮件能收到一封测试信 | 上传动作触发一封信，在 MailHog Web 界面能看到；**写明为什么不用真实邮箱** |
| 4 | 备份与恢复各一次 | `pg_dump` 备份 → 删掉一条数据 → 恢复 → 能查回来 |
| 5 | 手册可复现 | 另起一个 AI 会话（或 `compose down -v` 从零）照手册独立跑通 |
| 6 | 密钥零进仓 | 仓库里 grep 不到私钥与口令；`.gitignore` 覆盖证书、`.env`、`data/` |
| 7 | 追加题目按同一格式 | 后续加的题（如编程常识题）同样具备"能跑起来 + 有手册 + 有可判定的验收项" |

第 1、5 条在方案 B 下会降级为"compose 模板静态检查通过，未经本机运行验证"，并在验收记录里如实标注。
