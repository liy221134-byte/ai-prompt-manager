# 产品范围

## 产品定位

面向个人用户的 AI 提示词资产管理工具，核心闭环为：

```text
采集 -> 结构化 -> 分类 -> 检索 -> 使用 -> 优化/合并 -> 版本沉淀
```

## 目标用户

产品经理、开发者或内容创作者等需要长期积累和重复使用 AI 提示词的个人用户。

## 第一版范围

### 必做能力

- 浏览提示词卡片
- 新增、查看、编辑和删除提示词
- 使用 Markdown 保存和展示正文
- 主分类和多个标签
- 关键词搜索和基础筛选
- 识别并填写变量
- 变量可以逐条改名、降级为正文，也可以从正文选区或光标处新增
- 一键复制最终提示词
- 导入和导出提示词
- 本地数据持久化和备份
- AI 自动识别结构、摘要和标签建议
- 云端邮箱密码登录和账号数据隔离
- 云端跨设备同步
- AI 合并 2 至 5 条提示词，用户确认后保存
- 合并前目标内容保存为恢复快照
- 垃圾箱、恢复、永久删除和 30 天清理

### 延后能力

- 团队空间、评论和审核
- 浏览器插件
- 提示词市场
- 直接调用模型执行提示词
- 超过 5 条的提示词合并
- 单条提示词详情中的独立 AI 标签优化
- 完整版本历史界面
- 版本差异比较
- 提示词分支和合并树

团队协作仍不进入第一版；个人账号只做数据隔离，不做多租户权限。

## 提示词数据结构

第一周静态卡片直接采用最终字段结构，避免后续重做数据模型。

### 必须字段

| 字段 | 用途 |
| --- | --- |
| `id` | 唯一标识 |
| `title` | 卡片标题 |
| `category` | 主分类 |
| `tags` | 多个检索标签 |
| `content` | Markdown 格式的提示词正文 |
| `useCase` | 适用场景 |
| `createdAt` | 创建时间 |
| `updatedAt` | 更新时间 |

### 生命周期与合并字段

| 字段 | 用途 |
| --- | --- |
| `deletedAt` | 进入垃圾箱的时间，为空表示正常 |
| `deletedReason` | `manual` 手动删除或 `merge` 合并归档 |
| `mergedIntoPromptId` | 合并目标的稳定标识，仅合并归档来源填写 |
| `mergeVersionId` | 本次合并的恢复快照标识 |

合并前目标内容保存在 `prompt_versions` 恢复快照中。本期只提供恢复快照，
不提供完整版本历史界面。

### 后续字段

- `summary`：AI 生成的简短摘要
- `variables`：从正文识别的变量
- `isFavorite`：收藏状态
- `collectionId`：所属集合
- `source`：来源类型和原始内容

## 当前数据存储

- 默认数据保存在本机 `.data/prompts.sqlite`。
- SQLite 文件不提交到 Git。
- 同一台电脑上的不同浏览器通过本机 API 共享数据。
- 浏览器 `localStorage` 只用于旧数据迁移和页面缓存。
- 云端模式使用 Supabase 保存提示词，并通过 RLS 隔离账号数据。
- 本地与云端不自动同步。
- 本地模式在启动时清理过期垃圾箱和恢复快照；云端模式已包含每日清理代码路径，远程执行待验证。
- JSON 备份只导出提示词内容字段，导入时不会恢复已在垃圾箱中的提示词。
- 合并提交只接收客户端生成的版本标识；恢复快照内容由服务端从目标提示词生成。
- 云端清空垃圾箱使用单个原子 RPC，本地使用同一个 SQLite 事务完成等价操作。

## 核心流程

### 使用提示词

1. 通过分类、标签或搜索找到提示词。
2. 打开卡片并识别变量。
3. 填写变量并实时预览最终内容。
4. 一键复制。
5. 用户将内容粘贴到目标 AI 工具中使用。

### 采集提示词

1. 用户粘贴原始文本。
2. AI 识别标题、正文、分类、标签和适用场景。
3. 用户检查并修改识别结果。
4. 用户可以逐个确认、改名或降级识别出的变量。
5. 用户确认保存。

### 变量与复制

变量识别和复制是核心流程的一部分，长期规则放在这里，逐条验收见
[第 2 周验收](acceptance/week-02.md)。

1. 正文中的 `{{变量名}}` 打开详情时自动识别为输入框。
2. 变量按照第一次出现的顺序排列，同一个变量只显示一个输入框。
3. 变量名两侧的空格不参与识别。
4. 填写变量后预览区立即显示替换后的完整内容。
5. 原始模板保持不变，替换只作用于当前预览和最终复制结果。
6. 存在变量时，所有变量填写完成前不允许复制，按钮必须显示还缺多少个变量。
7. 没有变量时不显示变量输入区，复制按钮直接可用。
8. 复制结果必须与最终预览完全一致。

### 整理变量

1. 变量清单始终从正文中的 `{{变量名}}` 实时解析，不单独保存变量字段。
2. 改名会同步更新正文中的全部出现位置。
3. 降级为正文会去掉占位符语法，但保留里面的文字。
4. 可以把正文选区设为变量，也可以在光标处手动插入变量。
5. 空名、重名、花括号、超过 30 个字符或超过 20 个变量时不能保存。

### 合并提示词

1. 用户在提示词库选择 2 至 5 条提示词。
2. 第一条选中项默认为目标，用户可以调整。
3. 用户填写可选合并要求。
4. AI 生成可编辑草稿和合并说明。
5. 用户预览、编辑并确认保存。
6. 目标提示词更新为合并结果，来源提示词进入垃圾箱，目标旧内容保存为恢复快照。

### 管理垃圾箱

1. 用户打开垃圾箱查看被删除或合并归档的提示词。
2. 用户可以恢复提示词、恢复合并前版本、永久删除单条或清空垃圾箱。
3. 过期数据默认保留 30 天，之后由本地启动或云端每日任务清理。
