# 产品范围

## 产品定位

面向个人用户的 AI 提示词与工程资产管理工具。核心是把"提示词"扩成统一的"资产"模型，
让个人长期积累的提示词、规则、方法模板、技术档案和来源文档都能被检索、复用、沉淀和回流。

> 本文随产品从 v1（纯提示词库）演进到 2.0（统一资产底座）。v1 形态见
> [8 周路线图](roadmap.md) 的「历史：v1 阶段」一节；2.0 之后的能力见下文。

## 目标用户

- 产品经理、开发者、内容创作者等需要长期积累和重复使用 AI 提示词与工程方法的个人用户。
- 用本产品练习工程能力（部署、回滚、故障演练）的个人或小团队，见
  [工程能力学习计划](learning/engineering-readiness.md)。

## 产品范围

### 统一资产模型（2.0 底座）

所有内容都归到一个资产模型下，按类型区分，不另起一套：

- **提示词**：用于执行的 AI 指令，沿用变量与一键复制规则。
- **规则**：约束开发行为的原子规则（如"动手前先事前验尸""界面文案也是设计"）。规则元数据完整
  （类型、用途、层级、优先级、生命周期、来源），可编译进 `AGENTS.md`。
- **文档**：PRD、ADR、验收、数据库说明、发布手册等成篇内容；区分来源、权威版、工作稿、编译结果。
- **模板**：定义未来文档或编译结果的结构（如设计计划、事前验尸记录、用户故事），不直接代表项目事实。
- **技术档案**：项目一级档案，记录规模、运行环境、技术选型与偏离理由。
- **来源包**：上传的原始文件或 ZIP，保留导入前完整内容。

每条资产都有稳定标识、归属项目、来源证据、版本与生命周期（草稿／待确认／活跃／已归档／已废弃），
以及资产间的关系（引用、依赖、来源、替代、实现、验证）。

### 三条使用链路（各自独立）

1. **提示词链路**：找到 → 填变量 → 一键复制；采集、优化、合并都先预览再保存。
2. **项目文档链路**：需求 → 规格与计划 → 交付 → 验收 → 发布，六段分组，缺哪环看得见。
3. **代码链路**：从建表语句或代码目录导入模块／数据／接口／测试节点，做两层影响分析（代码视图）。

### 支撑能力（2.0 中后期）

- 规则编译：公共库规则编译进项目 `AGENTS.md`，项目引用公共库那份、不各存副本（引用模型）。
- 项目图谱：需求／模块／代码节点与影响分析。
- 工程导入：Schema 与代码目录扫描成节点。
- 本机 MCP：AI 直连读写本地库，能力不超过界面。
- 质量等级与工程基线：按质量等级查缺、给出推荐清单。
- 验收证据链：每条验收记录关联覆盖的需求与证据。
- 发布门禁与回滚目标：上线前门禁 + 回滚演练。
- 沉淀回流：把项目里的好资产提升为公共资产、提醒上游、沉淀体检。
- 立项起步包：新项目推荐 + 四条立项提示词 + 开发体系包。
- 本地与云端定期同步：本机 SQLite 与云端 Supabase 行为一致，定期对齐
  （只增不删／谁新谁赢／判不出就留着）。
- 资产库本身也被管理：方法规则、方法模板、产品方法提示词、技能定义分四层各司其职——
  **定义只在规则／方法资产里，模板留骨架，提示词留执行指令，技能留触发与编排**（本仓库 `v2.25.0` 收口）。

### 不做（明确冻结，不是漏做）

- 团队协作、评论、审批、多租户权限：产品定位是个人使用。
- 规则冲突自动解决、完整协作路径生成、代码与数据库完整图谱：延后评估。
- 自动修改外部 GitHub 仓库、自动部署执行。
- 真实浏览器端到端测试与 CI 门禁（工程能力练习里手动做）。

## 核心流程

### 使用提示词

1. 通过分类、标签或搜索找到提示词。2. 打开卡片识别变量。3. 填写变量并实时预览。
4. 一键复制。5. 粘贴到目标 AI 工具使用。

### 采集提示词

1. 粘贴原文。2. AI 识别结构、分类、标签、适用场景。3. 用户检查修改。4. 逐个确认变量。
5. 确认保存（AI 不静默覆盖原文）。

### 变量与复制

沿用 v1 规则：`{{变量}}` 自动识别为输入框；填写完成前不允许复制；复制结果与预览一致。

### 项目文档六段

需求 → 规格与计划 → 交付 → 验收 → 发布，每段可单独创建与验收，缺环可见。

### 资产沉淀回流

项目里验证过的规则／模板可以提升为公共资产；上游引用它的项目会收到提醒；
沉淀体检定期扫出"只在项目里出现、值得升公共"的资产。

## 数据与安全

- 默认数据在本机 `.data/prompts.sqlite`，不提交 Git；同机不同浏览器共享。
- 云端模式用 Supabase 保存资产，RLS 隔离账号数据；本地与云端用 `npm run sync` 定期对齐。
- 个人使用、不做多租户；密钥不进前端与 Git；AI 生成结果先预览再保存。
