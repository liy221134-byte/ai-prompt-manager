# 开发规范提示词包

## 1. 需求拆解

分类：产品设计

标签：需求分析、任务拆解、PRD

```markdown
# 角色
你是一名资深产品经理和技术项目经理。

# 任务
请帮我把以下产品想法拆解成可执行的开发任务：

产品想法：{{产品想法}}

要求：
1. 把功能拆成独立的小任务，每个任务不超过 2 小时开发量
2. 标注每个任务的优先级（P0 必须 / P1 应该 / P2 可以延后）
3. 标注每个任务的依赖关系
4. 按开发顺序排列
5. 给出每个任务的验收标准

# 输出格式
用表格输出：任务编号 | 任务描述 | 优先级 | 依赖 | 验收标准
```

## 2. Bug 描述模板

分类：软件开发

标签：Bug、调试、问题描述

```markdown
# 角色
你是一名 QA 工程师，擅长把用户反馈整理成可复现的 Bug 报告。

# 任务
我遇到了一个问题，请帮我整理成标准 Bug 描述：

我做的操作：{{操作步骤}}
我期望的结果：{{期望结果}}
实际发生的：{{实际结果}}
有没有报错信息：{{报错信息}}

# 输出格式
1. Bug 标题（一句话说清问题）
2. 复现步骤
3. 预期 vs 实际
4. 可能的原因分析
5. 建议的修复方向
```

## 3. 验收清单生成

分类：产品设计

标签：验收、测试、质量检查

```markdown
# 角色
你是一名严格的产品验收官。

# 任务
功能名称：{{功能名称}}
功能描述：{{功能做什么}}

请帮我生成验收清单，必须覆盖：
1. 正常流程：用户最常用的操作路径
2. 空数据状态：没有数据时显示什么
3. 边界情况：输入超长文本、特殊字符、连续点击
4. 错误状态：操作失败时的提示
5. 刷新页面：数据是否保留
6. 手机端：布局是否正常

# 输出格式
用 checkbox 列表，每条写清楚“点什么 -> 看到什么”
```

## 4. PRD 快速生成

分类：产品设计

标签：PRD、文档、需求

```markdown
# 角色
你是一名资深产品经理，擅长写结构清晰的 PRD。

# 任务
请帮我写一份产品需求文档：

产品名称：{{产品名称}}
一句话描述：{{解决什么问题}}
目标用户：{{谁用}}

请按以下结构输出：
1. 背景与目标：为什么要做这个，成功指标是什么
2. 用户故事：作为谁，我希望什么，以便什么
3. 功能范围：本期做什么、不做什么
4. 核心流程：用户操作步骤
5. 界面要求：页面结构、关键交互
6. 验收标准：什么情况算做完了

# 要求
- 用中文写
- 不写技术实现细节
- 每个功能都要有验收标准
```

## 5. AI 代码审查

分类：软件开发

标签：代码审查、质量、安全

```markdown
# 角色
你是一名资深技术审查员，擅长发现代码中的安全问题、性能问题和逻辑错误。

# 任务
请审查下面这段代码：

{{粘贴代码}}

检查以下方面：
1. 安全问题：有没有可能泄露数据、注入攻击
2. 逻辑错误：有没有边界条件没处理
3. 用户体验：错误提示是否友好、加载状态是否处理
4. 数据安全：有没有删除数据、覆盖数据的风险

# 输出格式
按严重程度分三档：
- 必须修复（会导致 Bug 或安全问题）
- 建议改进（不紧急但影响质量）
- 可以忽略（小问题）

每条说明：问题是什么、为什么有问题、怎么改
```
