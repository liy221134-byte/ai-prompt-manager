# 新项目启动提示词

## 使用方式

1. 创建一个新的空项目文件夹。
2. 在你的 AI 编码工具中打开这个文件夹。
3. 复制下面的提示词，把 `{{...}}` 内容替换成你的项目信息。
4. 先让 AI 建立项目规则和基础文档。
5. 确认项目范围后，再开始开发第一个功能。

## 可直接复制的提示词

```text
我是产品经理，不直接阅读代码。你负责协助我完成这个新项目。

在开始写功能代码之前，请先完成项目初始化，并遵守以下核心原则。

【项目信息】
项目名称：{{项目名称}}
一句话目标：{{这个项目解决什么问题}}
目标用户：{{谁使用这个产品}}
当前阶段：{{原型 / MVP / 内测 / 已上线}}
核心流程：{{用户完成核心任务的主要步骤}}
本阶段要做：{{本阶段范围}}
本阶段不做：{{明确排除的范围}}
验收标准：{{什么结果算完成}}

【技术底座】
技术栈：{{前端 / 后端 / 数据库 / 部署方式；还没定就写「待定，先给我候选和取舍」，不要默认替我选}}
不要从零开发的功能（用现成模板或已有实现，不要让 AI 重写）：
1. {{例如：登录、注册、密码重置}}
2. {{例如：角色与菜单权限}}
3. {{例如：用户管理、操作日志}}
4. {{例如：文件上传下载}}
{{还有哪些现成能力要直接用，继续往下列；不确定就写「待确认」，先让 AI 列清单再问我}}

【规则来源】
协作、开发、数据、Git 的强制规则一律以 `AGENTS.md` 为准。
初始化时把起步模板里的 `AGENTS.md` 复制到项目根目录，按里面的规矩执行。
**这里不重复写规则**——同一条规则写两处，迟早会漂。

【本次初始化任务】
暂时不要开发业务功能，请先完成：
1. 在项目根目录创建 README.md，说明项目目标、协作原则、开发原则、交付原则、Git 原则和固定工作流程。
2. 在项目根目录创建 AGENTS.md：复制起步模板那份，把上面的项目信息填进它的「产品规则」一节，
   并把开头的三个标签（规模 / 运行环境 / 阶段）填上。
3. 把起步模板的 `docs/method.md` 复制进项目 `docs/`：它是**方法层正本**（三道门判据、
   交付门细则、防过度设计梯子、技能使用规则）。`AGENTS.md` 里那张「按动作读哪节」的表
   指向它——**没有这份文件，那张表就是断链**。
4. 把起步模板的 `docs/rule-hits.md` 复制进项目 `docs/`：它是**规则命中台账**
   （append-only，每轮交付追加一节）。初始化完成后，按 `AGENTS.md` 与 `docs/method.md`
   的章节，把台账里那张逐条累计表先起一遍。
5. 创建 docs/product-brief.md，记录产品定位、用户、核心流程、范围和验收标准。
6. 创建 docs/roadmap.md，拆分从原型到生产版本的阶段路线。
7. 创建 docs/INDEX.md，写清文档入口和阅读顺序（哪些文档必须先读）。
8. 把起步模板的 `docs/DOCUMENT_SYSTEM.md` 复制进项目 `docs/`：它写清最小文档集合、
   写作原则、AI 读取顺序，以及**需求链路四段**（需求 → 规格 → 契约 → 交付）。
9. 创建 docs/acceptance/，为当前阶段建立验收清单。
10. 检查当前目录是否已经是 Git 仓库；如果没有，等待我确认后再初始化。
11. 把本次确定的技术底座写进 `docs/decisions/` 第一条决策记录：选了什么、放弃了哪些候选、为什么。

请先告诉我：
1. 你准备创建哪些文件和目录
2. 每个文件的作用
3. 当前项目信息中还有哪些不清楚的地方
4. 初始化完成后的验收方式

暂时不要创建文件，等我确认后开始。
```
