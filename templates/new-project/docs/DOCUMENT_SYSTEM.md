# 新项目文档体系

## 目的

零代码 AI 开发需要稳定的项目上下文。文档不是装饰，而是让不同 AI 和不同阶段的开发保持一致。

## 最小文档集合

| 文档 | 作用 | 何时更新 |
| --- | --- | --- |
| `AGENTS.md` | AI 强制规则 | 协作方式或产品边界变化时 |
| `README.md` | 项目说明、启动方式和回滚入口 | 技术栈、命令和项目状态变化时 |
| `docs/INDEX.md` | 文档索引和阅读顺序 | 新增或删除核心文档时 |
| `docs/product-brief.md` | 产品定位、范围和成功标准 | 产品范围变化时 |
| `docs/roadmap.md` | 阶段目标 | 阶段调整时 |
| `docs/decisions/` | 技术和产品决策 | 做重要选择时立即记录 |
| `docs/acceptance/` | 每阶段验收标准 | 阶段开始前创建，完成后更新 |
| `docs/database-schema.md` | 数据表和字段 | 数据结构变化时 |
| `docs/operations/release-rollback.md` | 发布和回滚 | 部署方式变化时 |
| `docs/operations/backup.md` | 备份与恢复 | 存储方式变化时 |
| `docs/faq.md` | 常见问题 | 同类问题重复出现时 |
| `CHANGELOG.md` | 版本变更 | 每次发布时 |

## 写作原则

1. 一份文件只解决一个主要问题。
2. 记录当前真实状态，不保留失效说明。
3. 决策记录必须说明备选方案和放弃原因。
4. 验收标准必须可观察、可测试。
5. 文档更新与代码修改放在同一个提交中。
6. 不把密码、API Key 或数据库连接串写入文档。

## AI 开发前读取顺序

```text
AGENTS.md
-> README.md
-> docs/INDEX.md
-> product-brief.md
-> roadmap.md
-> 当前阶段 acceptance
-> 相关 ADR、数据库和运维文档
```

## 文档维护检查

- 功能变更是否影响产品范围。
- 数据结构是否发生改变。
- 环境变量是否增加。
- 验收标准是否需要更新。
- 是否需要新增 ADR。
- 是否影响发布、回滚或备份。
