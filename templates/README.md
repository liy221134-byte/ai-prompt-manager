# 模板层说明

> 一页，讲清「模板从哪来、谁是正本、改了之后新项目和已经在跑的项目分别怎么办」。
> 立这份的理由：模板的母本地位原先散在 `README.md` / `AGENTS.md` / 同步脚本注释三处，
> 没有一处能一眼看完。WB 侧为同样的问题建了一个母仓（`E:/WB项目集`）——
> **我们不需要那个仓，需要的是这一页。**

---

## 三个目录各自是什么

| 目录 | 装什么 | 正本关系 |
| --- | --- | --- |
| `engineering/` | 12 份工程文档骨架（PRD / Spec / 契约 / 架构 / 数据流 / 环境变量 / 安全检查 / 备份恢复 / 发布回滚 / 故障手册 / 演练记录 / 成本基线） | 本仓是正本 |
| `methods/` | 6 份产品方法模板（设计计划 / 事前验尸 / 红队 / 用户故事 / Job Story / WWA） | 本仓是正本 |
| `new-project/` | 新项目起步母本（`AGENTS.md`、`README.md`、`START_PROMPT.md`、`docs/method.md`、`docs/rule-hits.md`、`docs/DOCUMENT_SYSTEM.md`） | 本仓是正本 |

## 母本 vs 副本：一句话判据

**本仓 `templates/` 是母本；被复制进某个项目之后的那一份是副本，复制即脱钩。**

- 母本改了，**已经在跑的项目不会被自动更新** —— 这是有意的：改一个跑着的项目要单独决定。
- 所以「项目里的模板落后于母本」**不是 bug，是设计**。想知道差在哪，把项目的模板文件与
  `templates/` 里对应那份对一遍即可。

## 改了模板之后要做两件事

1. **跑测试**：`npm run check:fast`。`tests/template-chain.test.mjs` 会锁住链路四段、
   编号唯一、模板之间互相引用真实存在、起步模板带方法层与命中台账。
2. **推进资产库**（改了正文就该做）：
   - `engineering/` 与 `methods/` → `npx tsx scripts/import-local-content.ts --dry-run` 先看
   - `new-project/` 六份 → `npx tsx scripts/sync-new-project-templates.ts --dry-run` 先看

   区别：前者**只新增不覆盖**；后者**按 id 精确更新，库里没有的直接建**。
   两个脚本都**只写本机库**。要推云端得另跑 `npm run sync -- --push` ——
   那是一次生产库写入，按「数据与安全」第 1 条要单独点头。

## 为什么不建母仓

WB 侧建了母仓，因为它当时**没有自己的仓库**、在借本仓的模板干活。
我们已经有一个仓库、体系资产在 git 里、有版本历史和测试锁 —— 母仓的核心价值已经具备。

再建一个仓等于多一套要同步的链路。这不是假设，WB 侧已经出现了一个实例：
它 `开发体系/README.md` 写「当前 `0.3.5`」，而正本 `DEV-SYSTEM.md` 自己写 `0.5.1`。

判据：**同一事实出现在两处、且两处都要改 → 该合并；只有一侧要改 → 才分叉。**
两侧分工的完整清单见 `docs/reference/two-sides-alignment.md`。
