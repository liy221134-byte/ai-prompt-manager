# 只打承重假设：先钢人，再攻击

## 核心结论

红队不是事前验尸。事前验尸是**想象已经失败、叙述原因**；红队是**现在就攻击承重假设**，趁还来得及测最便宜的那个。

五步：

1. **只攻击承重假设**——那种「假了方案就死」的假设；装饰性假设不管。
2. **先钢人，再攻击**——先把这个说法最强的版本说出来，然后攻击那个版本。打稻草人的攻击没有价值。
3. **失败模式写成「Fails if ___」**——要具体、可证伪。「失败如果激活根本不是瓶颈」胜过「有执行风险」。
4. **按（错了的影响 × 错的可能性 × 测试的便宜度）排序**——排在最前面的就是这周该测的，要显式排出来，不要埋在正文里。
5. **每条给四样**：Fails if（什么条件下方案就崩）/ 这周该拿什么证据 / Kill criterion（什么阈值就停或改道）/ 最便宜的测试（最小实验）。

两条硬纪律：

- **不许编造弱点**。想得通的就明说想得通——制造怀疑的红队和盖章通过的红队一样没用。
- **五条真假设配测试，胜过二十条泛泛的风险**。目标是把判断变锐，不是把风险清单变长。

## 使用条件

- 计划、方案、需求或路线图已经成形、还没投入实现之前。
- 拿一份文档去过会、去要资源之前。

## 不适用场景

- 已经开跑、没有可选项的应急处理——那时要做的是止损，不是红队。
- 局部实现细节。
- 当「挑刺仪式」用：真的挑不出承重的洞时，就应该明说「这份方案我想不出致命假设」。

## 判断步骤

1. 把方案里的断言全列出来（关于用户、市场、约束、机制、时间）。
2. 分出承重假设和装饰性假设，只留承重的。
3. 对每条承重假设先写「它最强的样子」，再攻击这个版本。
4. 把失败模式写成「Fails if ___」。
5. 按三个乘数排序，取前 3～5 条。
6. 每条补上：这周该拿的证据、Kill criterion、最便宜的测试。
7. 单独写两段：「哪些地方是想得通的」和「哪些地方我没法判断」。

## 失败模式

- 攻击方案的弱版本（稻草人），看着热闹，其实没碰到要害。
- 为了显得有用，硬编一条弱点出来。
- 列二十条泛泛的风险，没有一条带测试和阈值。
- 把排序埋掉：最该测的那条淹没在长清单里。
- 只输出恐惧，不输出「这周做什么」。

## 验证证据

- 承重假设 3～5 条，每条都有 Fails if、本周证据、Kill criterion、最便宜的测试。
- 「想得通的」那一段确实写了内容（哪怕只有一条）。
- 排在最前面的那条测试，是一周内真做得完的。
