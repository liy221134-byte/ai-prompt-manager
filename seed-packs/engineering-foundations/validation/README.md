# 编译验证说明

## 目的

验证相同的工程资产经过项目画像筛选后，能够编译出不同深度和不同重点的项目
开发体系，而不是输出同一套模板。

## 输入

- 12 条核心资产。
- 3 个项目画像。
- 每个画像对应的当前状态、约束和风险。

## 输出要求

每个场景至少生成：

1. 项目分级和路线选择。
2. 适用范围和不适用范围。
3. 必选规则、模板和阶段门禁。
4. 未选择资产及原因。
5. 冲突、假设和待确认项。
6. 项目验收和证据要求。

## 通过标准

- 不同画像的资产选择明显不同。
- 每条结果可以追溯到资产来源。
- 冲突不会被静默合并。
- 输出没有超出项目规模的无用文档。
- 人工确认后可以形成项目开发体系。
