# 大型平台

## 典型特征

- 多个核心分系统和服务域。
- 多团队、多供应商或驻场协作。
- 大量外部接口、历史系统和数据源。
- 强性能、可靠性、安全、合规和信创要求。
- 交付周期长，返工和集成失败成本高。

## 推荐路线

```text
需求与指标澄清
-> 架构、数据和接口基线
-> 公共平台能力
-> 两条端到端最小链路
-> 服务域并行纵向交付
-> 集成、性能、安全、信创和试运行
```

## 必选资产

- 项目规模与复杂度分级。
- 需求边界与外部依赖澄清。
- 定量指标与冲突检查。
- 架构与工程基线。
- 端到端最小链路。
- 按业务能力拆分模块。
- 接口契约与数据所有权规则。
- 项目质量画像与必选门禁。
- 验收证据链。
- 发布、回滚与恢复。
- 生产故障演练。

## 关键控制点

- 模块、接口和数据所有权。
- 公共身份、权限、审计和监控。
- 外部依赖的测试环境和责任方。
- 性能、容量、可用性和恢复目标。
- 多团队接口冻结和并行开发。
- 分阶段验收和上线，而不是一次性大集成。

## 验收重点

- 端到端主链路。
- 非功能指标和容量模型。
- 安全、合规和信创兼容。
- 故障恢复和业务连续性。
- 需求、代码、数据、测试和发布的追踪。
